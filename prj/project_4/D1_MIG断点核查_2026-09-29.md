## 2. ui_clk 与 DDR4 裸容量独立复核

### 2.1 ui_clk = **300.12 MHz**（标称 300 MHz）【已核实】

三条互相独立的证据链，结论一致：

1. **配置链**：`ddr4_0.xci` `C0.DDR4_TimePeriod=833`(ps) → DDR 时钟 1/833ps = **1200.48 MHz** → DDR4-**2400.96** MT/s；`C0.DDR4_PhyClockRatio="4:1"` → ui_clk = 1200.48/4 = **300.12 MHz**
2. **IP 生成链**：xci `C0.DDR4_UI_CLOCK = 300000000`（Xilinx 自己算出来的生成值，不是我推的）
3. **实现链（最强）**：`impl_1\mig_verify_top_timing_summary_routed.rpt:157-169` Clock Summary
   - `sys_clk_p {0.000 4.998} 9.996 ns 100.040 MHz`（= `C0.DDR4_InputClockPeriod=9996`）
   - `mmcm_clkout0 {0.000 1.666} 3.332 ns 300.120 MHz`  ← **ui_clk**
   - `pll_clk[0..2] {0.000 0.208} 0.417 ns 2400.960 MHz`（VCO_2X）+ `pll_clk[i]_DIV 300.120 MHz`

→ 帧周期 12.30 µs = **3690 个 ui_clk 拍**；prj10 设计说明里的 300 MHz 口径**正确**。

### 2.2 容量 = **4 GiB = 4,294,967,296 字节**，"DDR4 4GB" 文档口径**是对的**；`Capacity=512` **不是容量**【已核实】

**(a) 器件几何独立算**（不引用任何文档说法）：
`C0.DDR4_ROW_WIDTH=16`、`COLUMN_WIDTH=10`、`BANK_WIDTH=2`、`BANK_GROUP_WIDTH=1`、`DQ_WIDTH=64`、BL8（4:1 模式只支持 BL8，见 `rtl\axi\ddr4_v2_2_axi.sv:292-297`）

> 2^16(R) × 2^10(C) × 2^2(BA) × 2^1(BG) = 2^29 个 BL8 单元 × 64 bit = 2^35 bit = **2^32 字节 = 4 GiB**

**(b) 器件法**：MT40A**512M**16 = 512M 深度 × 16 bit = 8 Gib/片；4 片拼成 64-bit → 4 × 8 Gib = 32 Gib = **4 GiB**
（xci 生成值：`MEM_DENSITY=8Gb`、`MEM_DEVICE_WIDTH=16`、`DQ_WIDTH=64`、`RANK_WIDTH=1`、`nCS_PER_RANK=1`）

**(c) IP 自证**：xci `C0.DDR4_MEM_SIZE = 4294967296`（单位=字节）；AXI 地址宽 32 位正好覆盖 2^32，**无别名、无重映射**。

**(d) `Capacity=512` 的真相** —— 这是 Lead 点名的答辩问题，已查到底：
- `D:\Xilinx\Vivado\2023.1\data\ip\xilinx\ddr4_v2_2\component.xml:7274-7277`：`C0.DDR4_Capacity` 挂 `choiceRef="choice_list_b5a1a778"`
- 该 choice 列表定义在 `component.xml:6315-6318`，**只有两个合法值：512 / 1024**
- → 它是**器件深度代号（512M 个地址位置）**，正对应型号里的 "512M"；选 1024 就是 1G×16 的 16 Gb 器件
- **绝不能念成 512 GB 或 512 MB**。它既不是总容量也不是单片容量。

> **答辩口径（可直接背）**："4 片 MT40A512M16（单片 8Gb×16）拼成 64-bit，总容量 32 Gib = 4 GiB = 4,294,967,296 字节；MIG 界面里的 Capacity=512 指的是器件 512M 深度代号，不是容量数值。"

**与文档比对**：实操单 §2「总容量 32Gbit = 4GB」**正确**（32 Gib 恰好 = 4 GiB）；§0 表 #2「19.2 GB/s」**正确**
（2400.96 MT/s × 8 B = 19.21 GB/s；AXI 侧 512 bit × 300.12 MHz = 19.21 GB/s，两条路同一个数）。

### 3.3 高风险项：尾拍部分 WSTRB（#1 上板必踩候选）

- 事实：MIG `C0.DDR4_AxiNarrowBurst = false` → `P_USE_UPSIZER = (512<512)?1:0 = 0`（`ddr4_v2_2_axi.sv:261-262`）→ **upsizer 被旁路**，AXI 与 MC 1:1 直连
- 旁路分支里 WSTRB 是**直通**的：`ddr4_v2_2_axi.sv:708 assign wstrb_d2 = wstrb_d1;` → `:822 wstrb_d3` → `:927 .wstrb(wstrb_d3)` 进 `axi_w_channel` → `:936 .mc_app_wdf_mask(...)`
- 字节掩码通路本身存在（`DM_NO_DBI` + `C0.DDR4_USE_DM_PORT=1`），**理论上支持部分写**
- 但桥的尾拍只对帧内有效字节拉 strobe（`axi4_master_bridge.v:199 w_strb_r[w_bi] <= (w_bidx < w_len);`）
- **判定【待验证】**：`AxiNarrowBurst=false` 的官方语义是"主机不得发窄传输"，尾拍部分 strobe 落在灰色地带，**没有任何离线手段能证明 MIG 会正确落盘**
- W3 必做实验：写一个非 64 字节整数倍长度的帧（如 3 B / 100 B），读回逐字节比对。退路：尾拍也补成全 64 B 写（槽内 4 KB 有余量，帧长由描述符给出，补零不影响语义）

## 4. 桥的 3.1 µs/帧 量化与 DDR 侧带宽需求

### 4.1 桥的真实瓶颈（RTL 逐行可读，不依赖仿真）【已核实】
- 写侧：`W_FILL` 每 ui_clk 从字节 FIFO 吃 **1 字节**（`bridge:197-205`，一拍一个 `wf_data`）→ 上限 **300 MB/s**
- 读侧：`R_UNPACK` 每 ui_clk 往字节 FIFO 吐 **1 字节**（`bridge:400-410`）→ 上限 **300 MB/s**
- → **服务时间由 8b↔512b 转换决定，与 DDR 带宽无关**。（设计说明 §5 的"修正说明"方向正确，我用 RTL 行号坐实。）

### 4.2 按 3.1 µs/帧算 DDR 侧需求
- 帧长上限 `MAX_LEN=1538 B`；AXI 拍数 = ⌈1538/64⌉ = **25 拍 = 1600 B**
- 实测（`project_10\docs\prj10_W2_mem_bridge_design_note_2026-09-29.md:95`）：写 933 拍 = 3.11 µs、读 920 拍 = 3.07 µs @300 MHz
- **写侧**：1600 B / 3.11 µs = **0.515 GB/s**
- **读侧**：1600 B / 3.07 µs = **0.521 GB/s**
- 合计（读写两 FSM 并行可叠加）：**≈1.04 GB/s**
- 按帧周期 12.30 µs 摊平：读写各 `1600/12.30 = 0.130 GB/s`，合计 **0.26 GB/s**

### 4.3 MIG 侧持续带宽上界（算术）
- 理论峰值：2400.96 MT/s × 8 B = **19.21 GB/s**（= 512 bit × 300.12 MHz，两条路同数）
- 效率折损【推测，工程取值】：连续顺序大突发、单主 → 70–85%；混合读写频繁换向 + REFRESH（`tREFI` 生成值 9363 nCK）→ 55–70%
  → **持续上界 ≈ 19.21 × 0.55~0.85 = 10.6–16.3 GB/s**
- 结论：桥需要 1.04 GB/s，只占 **6%–10%**；余量 4–6 倍
- **更关键**：桥**根本发不出** 2.44 GB/s，上限就是每方向 300 MB/s（合计 0.6 GB/s）
- ⚠️ 注：我在 `C:\Users\15266\Desktop\毕设` 全目录 grep `2.44` **0 命中**、`project_9` 也 0 命中 —— **该数字的出处需 Lead 补**（本报告结论不依赖它）
- ⚠️ 真正受 MIG 影响的量是**单笔突发延迟**与 `RD_PRI_REG` 下的**读写换向惩罚**，本地无实测数据【待验证】，是 W3 第一个观测点
