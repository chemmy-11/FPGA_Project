## 一、需求与我的理解

**导师原话（09-24）**：以太网发送的数据先写到内存 → 内存里选定某个地址（**每次可选不一样**）读出来 → 经光回环再存到内存 → 最后从内存读出经以太网发回；**核心是把内存读写、特别是随机读写放进整个环路**。

**我的转写**：在现有「以太网 ↔ 光回环」通路的光口**两侧**各插一级 DDR4（**写 + 按地址读**），使数据面从"流式直通"变为"**按地址存储转发**"。

**为什么必须强调"按地址读"**：

| 维度 | 现在（帧泵 = FIFO 语义） | 导师要求（内存语义） |
|---|---|---|
| 地址 | 硬件自行递增，对外不可见 | **地址是显式、可指定的一等参数** |
| 读出顺序 | 必然等于写入顺序 | **可不同于写入顺序** |
| 数据归属 | "第 N 个出来的那份" | "**存在地址 X 的那份**" |

> 「多读几个数据、地址不一样」= **随机读写**：读出顺序 ≠ 写入顺序，且每帧内容与其槽位严格对应。这是"内存 ≠ 更深的 FIFO"的决定性证据，也是后续**多队列 / 优先级 / 拥塞迁移 / 描述符环**的地基。
> ⚠️ **请确认读法**：是"写侧分槽、读侧仍按序"（只证明用上了地址空间），还是"**读侧每次指定不同地址**"（真正的随机读）？我的理解是后者——见 §五 Q2。

**数据流（四步落到通路上）**：

```text
PC ═千兆═► [以太网栈] ► [泵A] ► ①内存桥·写(槽号=帧计数) ► ②读(槽号=选择器) ► [pack 8→64]
   ► [Aurora A] ══光纤══ [笼A↔笼B 回显] ══光纤══ [Aurora A RX] ► [unpack 64→8]
   ► ③内存桥·写 ► ④读 ► [泵B] ═千兆═► PC
   粉色四级 = 本期新增；以太网栈 / 泵 / pack / unpack / Aurora 全部零改动（只增不改）
```

## 二、现状盘点：技术核心已被验证过，只缺"对接"

| 导师四步 | 网络那一半（prj9 ✅） | 内存那一半（学长工程 ✅） | 覆盖判定 |
|---|---|---|---|
| ① 以太网数据写入内存 | ✅ 以太网入口 | ✅ 写内存（**入口是 UART**） | 各有一半 |
| ② 选地址读出 | — | ✅ 完整实现（16 槽 × 64KB，按编号寻址） | **已达标** |
| ③ 光回环再存内存 | ✅ 光回环（单板双笼，渡光两次） | ❌ 无光口 | 各有一半 |
| ④ 读出经网口发回 | ✅ 以太网出口 | ❌ **出口是 UART** | 各有一半 |

**三条支撑条件**：

1. **只缺对接**——「网络那一半」与「内存那一半」都是已验证的存量，本期是**集成**而非从零开始；
2. **引脚风险已下降**——DDR4 引脚约束**双来源交叉验证 107/107 一致**（学长 `ddr.txt` vs `project_4/mig_verify_pins.xdc`）；
3. **位流在库**——MIG/DDR4 已配置完成并产出位流（`project_4`），**唯缺上板**：`init_calib_complete` 与零比对误码这条最基本的判据至今未取得（这是 D1 要补的第一件事）。

> ⚠️ **需与导师对齐的口径**：DDR4 理论带宽比当前链路高约三个数量级，**把内存放进环路不会提升吞吐**。本步目的是**功能验证**（内存语义进数据面），不是性能优化——避免答辩被问"加了 DDR 快了多少"（见 §五 Q5）。

## 三、核心建议：走**路线 A**（自研 RTL 内存桥）

### 3.1 分岔口只有一处

| 路线 | 数据怎么进出 DDR | 数据面执行者 |
|---|---|---|
| **A（建议）** | AXIS → **自研 RTL AXI4 主机** → 直连 MIG `S_AXI`（512bit） | 纯硬件；MicroBlaze **可选**（只下参数、读计数器） |
| B | AXIS → **AXI DMA** → SmartConnect → MIG | AXI DMA IP，由 MicroBlaze 软件配置（**必需**） |

> 分岔口**不在**"要不要内存"，也**不在**"要不要软核"——**只在"数据怎么进出 DDR"这一层**。因此 D0（复现基线）、D1（MIG 上板）、地址/槽规划、判据与主机侧脚本，**两条路共用，绝不浪费**。

### 3.2 结论与一句话理由

**建议：路线 A，但把「选地址」做成软件可写寄存器（读槽号 + 模式：递增 / 伪随机 / 外部指定）。**

一句话理由：**「随机读写」考的是「地址是不是一等参数」，不是「谁来搬数据」**——地址参数化在 A 里同样成立；而 B 会让 MicroBlaze 进入每一帧的数据通路，把一个功能里程碑变成「BD 集成 + DMA + 中断 + 位宽迁移」四变量联调。

### 3.3 选 A 的四条理由（按权重）

| # | 理由 | 说明 |
|---|---|---|
| 1 | **与开题报告定案一致** | 开题报告 v2 §4.1 已定「**板内双平面：数据面纯硬件 + MicroBlaze 控制面**」。A 是这句话的直接实现；B 把软核放进数据通路，反而要回头改开题表述 |
| 2 | **风险面小一个数量级** | B 要同时解决四件事：① BD 与纯 RTL 顶层共存；② 参考实现 **32bit** ↔ 我们 **64bit AXIS** 位宽差；③ `user_clk ↔ ui_clk` 的 AXIS FIFO ×2；④ AXI INTC 中断与每帧软件时序。任一项都可能吞 1–2 周 |
| 3 | **判据路径最短** | J1–J6 全是功能判据。A 有现成骨架可复用——`mig_verify_top`（自研 AXI4 主机：写突发→读回→比对，**离线已验证**），改造点是**地址源**（固定递增 → 槽选择器）与**数据源**（测试 pattern → 帧泵输出），AXI4 时序骨架不动；4KB 对齐槽位使单帧突发天然不跨 4KB 边界 |
| 4 | **不浪费** | A 的帧侧接口、槽结构、地址寄存器三样在演进到 B 时**原样保留**，只替换「AXI4 主机」这一层 |

### 3.4 澄清：随机读写**不是**选路依据

| 问题 | 路线 A | 路线 B |
|---|---|---|
| 「地址每次可选不同」怎么实现 | 硬件地址选择器：帧计数 / 递增 / LFSR / **寄存器指定** | 软件写 DMA 源地址寄存器或描述符 |
| 随机读是否支持 | ✅ 寄存器路径 = 任意地址 | ✅ 天然支持 |
| **每帧谁下命令** | 数据面自主，**每帧 0 软件开销**，延迟确定 | Simple 模式**每帧需软件配置**；SG 模式需预置描述符环 |
| 与原阶段三表述 | 偏离（原文写「MicroBlaze 跑 C 代码」） | 一致 |

→ 两条路**都能**满足「随机读写」，差异在「**每帧谁下命令**」。所以选路判据应看**工程量、风险与终态**，而不是"能不能随机"。

> 与开题报告 §4.5 的关系：那里的「② DDR4 大容量队列 + AXI DMA + 描述符环」属于**队列容量**阶段，触发条件是"出现 ≥3 端点同时向同一边发送的实测排队"。本期做的是**内存语义进环路的功能验证**，不是同一件事——**B 的时机仍留在 ②**，并未被否定。

### 3.5 三条接口预留（把"A 可能返工"降为"只换一层"）

| # | 预留 | 做法 | 演进到 B 时的动作 |
|---|---|---|---|
| 1 | **内存桥拆两层** | `frame_mem_if`（帧侧：8b ↔ 512b、槽地址生成、帧长邮箱）+ `axi4_master_bridge`（突发 / 4KB 边界 / 仲裁） | 只换 `axi4_master_bridge` |
| 2 | **选地址走寄存器** | 读槽号 + 模式寄存器，按 **AXI4-Lite 从机**语义设计 | 寄存器语义不变，改由 DMA 描述符驱动 |
| 3 | **接口保持 AXIS 语义** | 桥的进出以「帧」为单位（帧边界 + 帧长已知） | DMA 可直插，不必重造接口 |

## 四、"随机读写"怎么证明（判据）

| # | 判据 | 说明 |
|---|---|---|
| J1 | `init_calib_complete` = 1 | DDR4 校准完成——**阶段三至今未取得的判据** |
| J2 | 写入帧 vs 读出帧逐字节一致 | 内存读写正确性 |
| **J3** | **读出顺序 ≠ 写入顺序，且每帧与其槽位严格对应** | **随机读写的决定性证据** |
| J4 | 全量 10MB SHA256 一致 | 与 prj9 同口径，保证"内存进环路后业务不退化" |
| J5 | 读地址可控且可观测 | ILA 可见写槽号 / 读槽号 / 突发计数 / 帧计数 |
| J6 | ping 20/20 + UDP 12/12 仍全过 | 环路基本功能未被破坏 |

**J3 的具体测法（用 PC 侧脚本自动判定，答辩可当场复现）**：

| 测法 | 通过标准 |
|---|---|
| 连发 N 帧（N ≥ 槽数），看 ILA 写槽号 | 帧计数递增，多帧落在不同 slot |
| 上位机下发**乱序槽号序列**（如 7, 3, 255, 0, …） | 读出帧序 = 下发序列 |
| PC 给每帧 payload 带序号，按（槽号 → 序号）映射逐帧校验 | 乱序**不串帧**，内容与槽位一致 |
| 同槽连读两次 / 跳号读 / 回读已读槽 | 内容与首次一致 → 证明"按地址取"而非"按序弹" |

## 五、请导师拍板（5 个问题）

| # | 问题 | 我的建议 |
|---|---|---|
| **Q1** | 本轮验收是否**必须**走"MicroBlaze + AXI DMA 配置搬运"的机制？还是允许先交付功能判据、DMA 留到多队列阶段？ | **先交付功能里程碑，再演进到 DMA**（共同部分占大头，不浪费） |
| **Q2** | 「地址每次不一样」是"写侧分槽、读侧按序"，还是"**读侧每次指定不同地址**"？ | 后者（真随机读） |
| **Q3** | 读地址由谁定：硬件递增 / 硬件伪随机（LFSR）/ **上位机经 UDP 命令字或 MicroBlaze 寄存器指定**？ | 先递增拿基线，再做**软件可写寄存器**（同时拿到"随机读"与"控制面通路"） |
| **Q4** | 光回环形态：沿用 prj9 单板双笼外部跳线（渡光两次），还是等双板组网？ | 沿用单板双笼（组网暂缓） |
| **Q5** | 本期是否接受"**只做功能验证、不承诺吞吐提升**"的口径？ | 建议接受（DDR 带宽比链路高三个数量级） |

> 另有两条已可自行闭环、仅备案：阶段三原文的"MicroBlaze 跑 C 代码读写 DDR4"若走路线 A，机制上由"RTL 主机 + 软件可写地址寄存器"替代；原阶段四的 AXI DMA 留到多队列阶段。

## 六、确认后的实施顺序

| 里程碑 | 内容 | 判据 |
|---|---|---|
| **D0** | 复现 prj9 基线，确认环路仍无损 | ping + UDP 全过 |
| **D1** | **MIG 上板收尾**（解冻 `project_4` 位流） | **J1**：`init_calib_complete`=1 + 零比对误码 |
| **D2** | 内存桥 RTL + xsim 仿真（写 N 帧 → 读 N 帧，含乱序） | 仿真逐字节一致 |
| **D3** | 只插第一级内存（以太网 → 写 → 读 → pack → Aurora） | J2 / J6 |
| **D4** | 补齐第二级，形成两级内存全环路 | J4 |
| **D5** | 随机读判据 + 地址选择器（软件可写） | **J3** / J5 |
| **D6** | 判决计数器 + ILA 探针 + 测试报告归档 | 可观测可复现 |

## 七、主要风险与预案

| # | 风险 | 预案 |
|---|---|---|
| 1 | **MIG 上板未验证**（J1 至今未取得） | 列为第一步；位流在库、引脚已双来源交叉验证，风险可控 |
| 2 | 内存桥跨 `user_clk ↔ ui_clk` 引入新 CDC | 复用帧泵式格雷码异步 FIFO；ILA **按域分挂**（跨域采样曾致 WNS −2.639 ns） |
| 3 | `init_calib_complete` 未同步即发 AXI 读写 → 挂死 | 内存桥硬门控：等校准完成 + `ui_clk_sync_rst` 释放才放行 AW/AR |
| 4 | 自研 AXI4 主机的 4KB 边界与读写仲裁 | 槽 4KB 对齐（单帧不跨界）；先 xsim 仿真再上板 |
| 5 | 若导师要求必须走 DMA 机制 | 按 §3.5 三条预留平滑替换（只换 AXI4 主机层） |
