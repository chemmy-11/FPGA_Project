# DDR4 内存进环路 · 需求对齐汇报

**汇报人**：（学生）　**日期**：2026-09-29

**目的**：对齐您 09-24 布置的「内存读写进环路、特别是随机读写」的**需求理解**与**交付口径**。五个问题拍板后即可开工（实施草案已备好：[[操作文档/阶段三_prj10_内存进环路开工草案_2026-09-29]]）。

---

## 一、您的要求，我这样理解

**一句话复述**：现在数据是从网口进来、穿过光回环、再从网口回去的"直通"；改造后，数据在光路的**进出两侧各经过一次内存**——先写进指定地址，再**按指定的地址**读出来，地址每次可以不一样。

其中最关键的一条，我理解为**随机读写 = 读出顺序可以和写入顺序不同**：第 7 个写进去的，可以第 1 个被读出来，且读出来的内容必须就是当初存在那个地址的那一份数据。这样"内存"才是真正的内存——一个按地址存取的仓库，而不是一条更长的队列。**如果这个理解有偏差，请您指出**（对应 §四 Q2）。

## 二、本轮交付什么（验收标准先说清）

| 交付项 | 怎么验收 |
|---|---|
| DDR4 在本板跑通校准 | 校准完成信号亮起、读写自比对零错误（这块之前只做到生成位流，没上过板，本轮第一步补上） |
| 数据确实"经过内存" | 进出内存的每一帧逐字节一致 |
| **随机读写成立** | 我从电脑下发一串乱序地址（如 7, 3, 255, 0…），板子按这个顺序读出对应数据、原样发回，逐帧核对不串位；同一地址读两次结果相同 |
| 加了内存后业务不退化 | 与之前一样的全量数据 + 校验和比对，100% 一致；网络通断测试不受影响 |

**两点口径，想先和您对齐**：

1. **本轮是功能验证，不承诺提速——但它换来的两个能力是整个系统后续的直接地基**。DDR4 的带宽比这条链路高约三个数量级，把它放进环路改变的是"数据怎么存取"，不是"跑多快"（避免中期答辩被问"加了内存快了多少"时口径被动，§四 Q5）。它实际买到的是两个能力：
   - **突发吸收**：多个端点同时向一个出口发数据时（例如多个 Agent 的结果同时汇聚），先把数据接进内存、再按出口速率放出——从"第二帧就丢"变成"接得住、慢慢放"；
   - **调度的地基**："按地址取"意味着数据可以**不按到达顺序释放**——后续的优先级转发、按链路状况选路（拥塞感知调度），硬件上都从这一步开始。
   本轮先把这两个语义放进数据面并当场验证；收益数字等组网与调度实验再量化。
2. **基础是现成的，本轮是集成**。网络这一半（网口进、光回环、网口出）上一阶段已全部上板验证；内存这一半的引脚配置已与学长工程双份核对一致（107 个引脚全部吻合），DDR 控制器位流已在库。缺的只是把两半接起来。

## 三、技术路线（一段话）

数据进出内存这一段，我打算用**自己写的硬件模块**（纯 RTL 的内存桥）直连 DDR 控制器，"选哪个地址读"做成**软件可写的寄存器**，由电脑下发——这样随机读写的能力不受任何限制，MicroBlaze 只负责下参数、读状态，不进入数据通路。这与开题报告"数据面纯硬件 + 控制面软核"的定案一致，也是风险最小的路径（备选的 DMA 方案没有否定，留给后面做多队列的阶段，到时只替换一层，前功不弃）。

## 四、请您拍板的五个问题

| # | 问题 | 我的建议 |
|---|---|---|
| Q1 | 本轮验收是否**必须**体现"MicroBlaze + C 代码配置搬运"？还是允许先交付功能判据、DMA 机制留到多队列阶段？ | 先功能后机制（共同部分占大头，不浪费） |
| Q2 | "地址每次可选不一样"是指**读的时候由我指定不同地址**（真随机读），还是只要写的时候落在不同地址？ | 按前者设计与验收 |
| Q3 | 读地址由谁定：硬件自己递增 / 上位机指定？ | 先递增拿基线，再做上位机指定（同时拿到"随机读"和"控制通道"两个能力） |
| Q4 | 光回环沿用现在的单板双笼跳线，还是等双板组网后再做？ | 沿用单板（先把内存语义做扎实，组网并行推进） |
| Q5 | 本轮"只做功能验证、不承诺吞吐提升"的口径可以接受吗？ | 可以（理由见 §二） |

## 五、计划与时间

约 **4–5 周**：第 1 周补 DDR 校准上板（这也是原定 DDR 主线的第一步，一份工作两线共用）→ 第 2–3 周内存桥设计与仿真 → 第 3–4 周两级内存插入环路、随机读判据联调 → 收尾观测与测试报告。前置的基线复测和现有工程复用占很小比例，无采购。

## 六、风险交代（三条）

1. **DDR 上板是本轮唯一没验过的存量**——列为第一步，出了问题最先暴露、成本最低；
2. 内存桥跨两个时钟域——用上一阶段帧泵已验证的同款异步方案，观测探针按域分挂（有前车之鉴的坑，已入预案）;
3. 若您要求必须走 DMA 机制——接口已按"只换一层"预留，返工范围可控。
