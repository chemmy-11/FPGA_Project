## 一、项目架构总览（2026-09-04 定版）

```
端点层   PC(Docker 多Agent) ── GE1 千兆RJ45 ──┐
         树莓派(Agent/小模型) ── GE2 千兆 ──┤
         服务器(大模型) ── 接入方式待定 ────┤
                                            v
交换层   FPGA KU060（GTH ×32ch · 单板交换中心）
         ├ 以太网交换/协议栈（ARP/ICMP/UDP/TCP）
         ├ DDR4 4GB 缓存（MIG 在库）
         ├ 转发引擎（缓存/直通双模式）
         └ MicroBlaze 控制面（Vitis）

板间层   SFP+ ×4 ── Aurora 64b/66b 10G ×2 平行链路（GTH X1Y2 Quad：A=X1Y11 · B=X1Y9）
         └ 双 10G 平行链路即多路径实验对象（09-22 定案，不依赖第三块板）；多板/Fat-Tree 演进（加板后启用）
```

**关键定论**：端点均为标准以太网设备，一律经**千兆网口**接入（09-22 定案，SFP 口不再承载以太网）；Aurora 64b/66b = 板间干线定位（决策 #10），板间为同 Quad 双核**双 10G 平行链路**（决策 #13）。

## 二、决策记录（答辩叙事骨架）

### 1. 插入 IBERT 物理层自检（08-27 ✅）
物理层与协议层解耦。副产物：QUAD=X1Y2、参考钟 T6/T5@156.25MHz、控制脚版本 A 三项定案。

### 2. 跳过 8b/10b 裸调练手（08-27）
教学价值被 IBERT + 内环替代；概念已入 [[笔记和开发指南/光纤接口8b10b]]。

### 3. Aurora duplex 单核 + 内部环回（08-31 ✅）
同口收发（交换机形态）；跨口跳线不适配单核 duplex → 内环验证。

### 4. AXI 总线族并入 MIG（08-31）
MIG S_AXI = AXI4 活教材。

### 5. MIG/DDR4 搁置，提前引入网口（08-31 导师指示）
数据能进能出的最小系统优先；DDR 缓存后补（位流在库）。

### 6. 上下位机载体从网口降级为串口（08-31）
最小成本验证 SFP 正确性；网口推迟至联调前（后被决策 #7 提前）。

### 7. 以太网上位机通道提前并行（09-02）
UDP/ARP/ICMP 栈 = 网口线 + 大带宽上下位机 + 联调监控的共同地基。

### 8. 网口版先行，光口版顺延（09-02，无光电转）
协议栈核心两版相同 → 网口版先通，光口版调试量减半。

### 9. UDP+SFP 内环混合验证立项（09-03）
光电转缺失下验证 SFP 前端数据通路；project_7 承载。

### 10. 架构定版（09-04，导师确认）⭐
- **端点/上位机 = 标准以太网（千兆）**
- **Aurora 64b/66b = 板间干线**（加板后启用）
- **SFP 口协议 = 标准以太网**（端点全是以太网设备）
- 短期目标：① 上位机以太网传输 ✅ ② Aurora 64b/66b 内环数据级验证（进行中，[[汇报_prj8_数据级桥汇报_2026-09-04]]）
- project_7 挂起（光口承载以太网前端，多端点形态下复用）

### 11. 数据级桥改为"单向穿 Aurora"并硬门控（09-10）⭐
- **Aurora 只插在「栈 TX → PC」单向路径**：PC→栈 直连 RGMII；回显帧 dst=请求方 MAC，天然不重入栈
  → 自终止论证成立，**不需要第二例 udp_rx**（比 09-04 方案少一个解析器、少一处 CDC）
- **帧泵读侧被 `~channel_up` 硬门控**：Aurora 没起来时板卡对外完全不说话
  → **判据无旁路**：`P′==P` 只可能来自"数据真的穿了 64b/66b 编解码往返"（这是判据有效性的前提，不能再加旁路 fallback）
- **接口约定以 IP 源码定案**（[[结论_cross_Aurora64B66B_AXIS接口约定_2026-09-10]]）：第 1 字节 → `tdata[7:0]`；
  **末拍 tkeep 必须高位 lane 对齐**（`~(8'hFF>>N)`，与常见 Xilinx AXIS 的低位对齐相反）；RX 无 tready 不可反压
- 位流已产出且**时序收敛**（WNS=+1.062 ns）；上板单：[[操作文档/阶段二之八_prj8_数据级桥上板验证单_2026-09-10]]

### 12. 判决式调试 + 队列深化修复（09-21）⭐
- **真光链路（prj9）判据全过**：双笼 A↔B 数据渡光两次，帧泵格雷满判根因修复（f7c8be8）
- **会话 JSON 全量传输质量评测**：负载 = 本会话真实记录 10.3MB/7569 片；判决位流（三域 ILA + 六段差分链 + 冻结看门狗）定位 0.4% 丢失根因 = **pack 输出队列 2 深溢出吞 tlast 字 → 相邻帧合并**（算术闭合 7×2+9×2=32）；队列 2→16 深修复后**全量 100% + SHA256 一致**（历史首次）
- **真实业务传输层** `json_reliable.py`（选择性重传滑窗）：交付 100%/0 重传——确立"**FPGA 快路径 + 传输层可靠性**"架构叙事
- 方法沉淀：差分链对账（每级帧计数器逐段差分）定位效率远超抓波形；独立时钟域必须独立 ILA
- 详见 [[操作文档/阶段二之九_prj9_调试记录_04丢失根因定案_2026-09-21]] · [[操作文档/阶段二之九_prj9_测试报告_会话JSON全量传输质量评测_2026-09-21]]

### 13. 队列后端分步 + 接入/拓扑定案（09-22 定案；**队列分步已被 #14 修订为 DDR 先行**）⭐
- **队列后端分步（开题报告 §4.5）**：① **BRAM 多帧环形队列 + MicroBlaze 控制面**（先做——消除「单帧在途」、拿到真实结构容量、控制面可配置）→ ② **DDR4 大容量队列 + AXI DMA + 描述符环**（触发条件 = 实测出现 ≥3 端点同时向同一出边发送的排队；MIG 校准位流在库，解冻成本可控）——**分步策略 09-26 被 #14 修订：DDR 先行、BRAM 降为回退；判别实验改由 D3 承载**
- **接入方式定案**：端点（PC / 服务器 / 树莓派）一律经**千兆以太网口**接入 → 原「用 SFP 承载标准以太网」不再需要，`project_7` 保持挂起
- **板间拓扑定案**：两板各用同一 GTH Quad（X1Y2）内**两个 Aurora 64b/66b 核**（A = X1Y11、B = X1Y9，共用 156.25 MHz 参考钟），笼 A↔A、B↔B 各一根 LC 跳线 → **双 10G 平行链路**；多路径实验不依赖第三块板
- **光器件齐备**：10G SFP+ 模块 **4 只** + LC 跳线 **4 条**（用户确认）→ 双板组网**零采购**
- **风险重排**：**跨板转发从未验证 = 第一技术风险**（开题报告 §5.3 #1）；过载硬冻结 = 关键路径第一项（看门狗已就位）
- 详见 [[毕设方向与论文大纲/开题报告_2026-09-22]] §4.2 / §4.5 / §5.3 / §6 · [[AI-Infra系统设计/FPGA-AI-Infra-系统设计报告]]

### 14. DDR 先行定案（09-26 导师定案，修订 #13 分步策略）⭐
- **定案**：导师明确 **先做 DDR4**——#13 的「BRAM 先行 → DDR4 条件触发」分步作废；BRAM v2 降级为**回退方案**（仅当 D2 MIG 时序 WNS<0 时启用），接口按「队列后端可替换」设计保住 3–6 周投入的下限
- **D 线五步**（系统设计报告 v0.5 §8.1，FPGA 轨最高优先）：D1 MIG 解冻校准复验（prj4 位流在库）→ D2 队列后端 DDR 化（描述符环 + ui_clk CDC + 水位可观测）→ D3 容量判别复测 + 短帧延迟量化 → D4 缓存/直通双模式 → D5 AXI DMA 集成
- **立项依据（答辩口径）**：开题报告 4.2（DDR4 缓存+DMA）/ 4.3（MicroBlaze 控制）两章节交付物 + GB 级深队列 / 多队列基础设施（拥塞感知调度论文主线的地基）；**不是吞吐**——22.9 Mbps 是测量下界非结构极限（报告 §3.3.2 已修正归因），判别实验由 D3 承载，只影响叙事不影响决策
- **并行关系**：D 线（板内队列）与双板双链路组网（F1）正交并行；跨板转发判据跑在 D2 队列版帧泵上（合流点）
- 详见 [[AI-Infra系统设计/FPGA-AI-Infra-系统设计报告]]（v0.5 §3.3.5 / §8.1）
