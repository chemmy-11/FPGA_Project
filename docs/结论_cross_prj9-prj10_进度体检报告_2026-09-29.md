- **判据无假通过**：T4 确实比了逐字节内容；T3 的 256 帧读回比内容，能真正证明"未读帧零覆盖"；

- **边界（★核心）**：`sim/axi4_ram_model.v` 是**自定义端口集**的行为模型（无任何 ID/QoS 端口）、
  写响应延迟≈2 拍、读首拍延迟≈9 拍、**地址静默取低 20 位**。因此 PASS **只覆盖数据面功能**，
  **不覆盖**：(a) AXI4 端口合规性；(b) 真 MIG 的延迟/背压维度；(c) 绝对地址正确性。

### 3.2 第一性原理核算：**约束是端口并发与延迟，不是带宽**（★本轮最重要的技术结论）

用成员实测计数回归出的拍数模型（误差 <1%）：

```text
写：T_w = L + 3·ceil(L/64) + 4 + Lw        读：T_r = L + 2·ceil(L/64) + 4 + Lr
（L = 帧长字节；Lw/Lr = MIG 写响应/读首拍延迟；系数 3/2 = 每 beat 的死区拍）
```

| 量 | 替身模型（Lw≈2） | 真 MIG 假设（Lw=200, Lr=250） |
|---|---|---|
| 1466 B 设计点 写/读 | 5.14 µs（max） | **5.80 µs** |
| 单桥稳态吞吐 | 194.7k fps | **170.1k fps** = 线速 81.27k fps 的 **2.09×** |
| **两级桥链每帧（串行）** | 10.21 µs | **11.68 µs**（裕量仅 **1.05×**） |
| DDR 带宽占用 | 238 MB/s ÷ 19.2 GB/s = **1.2%** | 每帧 DDR 忙 **46/3691 拍 = 1.25%** |

**四条推论**：
1. **并行不成立**：AW/W/B 与 AR/R 是两组独立通道，**协议上可同拍并行**；但物理上 MIG 只有**一组 s_axi**，
   同一个 slave 口 → 两级桥必须过 interconnect，**读写会被串行化**。
2. **每帧各串行暴露一次往返延迟**：写 FSM 必须等 `BVALID` 才能回 IDLE（`axi4_master_bridge.v:175/277`），
   读 FSM 同理（:317/:420）。这是**结构性**的，不是实现疏漏。
3. **阈值**：流水化后可容忍 L>2152 拍；不流水则 **Lw+Lr>636 拍即破坏节拍**。真 DDR4 随机访问延迟量级
   正是**数十~数百拍** —— **处在同一数量级，必须实测**。
4. **因此**：prj10 记录里"单桥 3.11 µs/帧、节拍不变、端到端 +6 µs"的口径**必须改写**为
   "设计点 5.14–5.80 µs、两级串行 10.2–11.7 µs、裕量 1.05–1.20×"，否则答辩时会被一句"延迟翻倍"问倒。

**D1 的判词来自真综合（这是本轮最有价值的一次验证）**：
用 Vivado 2023.1 做单模块 `synth_design`（scratch，非工程），报 **6 条 CRITICAL WARNING**，其中
`[Synth 8-6858] multi-driven net Q is connected to at least one constant driver **which has been preserved, other driver is ignored**`
→ **综合保留常量驱动 GND、丢弃 FSM 驱动** ⇒ 上板 `out_inc/out_dec` **恒 0** → `stat_outstanding` 冻结。
**从"仿真器可能容忍"升格为"硬件必然发生"**。修法：`out_inc` 唯一驱动移入写 FSM 块、`out_dec` 移入读 FSM 块（逐拍等价）。
复验：多驱动扫描 NONE、**综合 6 → 0 条 CRITICAL WARNING**、`run_sim.bat` 判决行与 STAT **逐字一致**（Lead 亲跑复核：`PASS (0 errors)`，`wr_beats=rd_beats=8202`、`4k_violation=0`、`axi_proto_err=0`）。
**D2 修法**：描述符长度改用**真正入队字节数** `n_push_r`（结构上不可能与字节流失步）+ `W_DRAIN` 加 16 拍 liveness 上界（新增 `stat_len_err`）；回归：修前 `wst=6/w_pop=4095/w_len=8000` 永不恢复 → 修后 **`wst=0, len_err=1, wr_frame=2`，次帧逐字节正确，RESULT: PASS**。

**地址断言已成可判据（含反向验证，证明不是恒真）**：`addr == SLOT_BASE + slot*4096` / 4KB 对齐 / 不跨 4KB，
槽号取自桥自身 dbg 寄存器（真关系，不是 TB 自说自话）。反向验证：把 `EXPECT_BASE` 改错 → `viol_rel=6`；
把 RTL `SLOT_BASE` 改成非对齐 → `viol_rel=6 + viol_align=6`。**两个方向都变红**。
`SLOT_BASE=0x0010_0000` 是人为约定值，当前不与 MIG 解码冲突、也不与 MicroBlaze MCS 的 **LMB** 地址冲突；
**但若 W3 让 BD / AXI DMA 成为 MIG 的 AXI 主机，低区 `0x000000–0x2FFFFF` 就是未来的地址打架点**（待 W1 复核）。

> **方法论沉淀（两条，均已实测，建议进坑账本）**：
> ① **xvlog/xelab 对多驱动完全静默**（修前修后 WARNING 均为 0）→ "用 xvlog 代替真综合做快检"**对这个缺陷类别不成立**；
>    多驱动只能靠 `synth_design` 判。
