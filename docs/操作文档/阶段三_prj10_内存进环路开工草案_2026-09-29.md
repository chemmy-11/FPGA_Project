## 一、需求定界（内存语义，不是更深的 FIFO）

### 1.1 需求转写

**导师原话（2026-09-24）**：以太网发送的数据先写到内存 → 内存里选定某个地址（**每次可选不一样**）读出来 → 经光回环再存到内存 → 最后从内存读出经以太网发回；**核心是把内存读写、特别是随机读写放进整个环路**。

**转写**：在现有「以太网 ↔ 光回环」通路的光口**两侧**各插一级 DDR4（**写 + 按地址读**），数据面从"流式直通"变为"**按地址存储转发**"。

| 维度 | 现在（帧泵 = FIFO 语义） | 导师要求（内存语义） |
|---|---|---|
| 地址 | 硬件自行递增，对外不可见 | **地址是显式、可指定的一等参数** |
| 读出顺序 | 必然等于写入顺序 | **可不同于写入顺序** |
| 数据归属 | "第 N 个出来的那份" | "**存在地址 X 的那份**" |

**「随机读写」的判定式**：读出顺序 ≠ 写入顺序，且每帧内容与其槽位严格对应。这是"内存 ≠ 更深的 FIFO"的决定性证据，也是后续多队列 / 优先级 / 拥塞迁移 / 描述符环的地基。读法确认（写侧分槽读侧按序 vs 读侧每次指定不同地址）= **Q2，待拍板**；本草案按后者（真随机读）设计。

### 1.2 内存在整个系统中的两个实际作用（第一性原理 · 答辩口径）★ 2026-09-29 补

**前提（先排除错误预期）**：DDR **不提速**——带宽 19.2 GB/s（DDR4-2400×64b）≫ 千兆口 ~119 MB/s，差三个数量级、永不成为瓶颈；fabric 静态预算已在线速上（≈957–959 Mbps，[[操作文档/阶段二之十_prj9_传输效率与瓶颈判定实操单_2026-09-29|prj9 实操单 v2]] §三）。且当前单端点环路（PC↔单板↔PC）里 DDR **看不到收益**——它的价值在**容量与地址语义**，只在多端点 / 突发 / 优先级 / 断链场景激活。这正是 Q5「功能验证口径」的原因；收益量化由 D3（判别复测）与 F4（调度实验）承载。

**作用一：突发吸收——多对一拥塞时"先接住，再按线速放"**

交换的基本矛盾：**入侧聚合速率可瞬时超过出侧线速**。典型触发 = 开题 MoA 负载的**聚合相位**（多 Agent 输出同时涌向一个汇聚端，即经典 incast）与 ≥3 端点同发一条出边（#13 原触发条件）。现状对照：

| | 现状（帧泵单帧在途） | DDR 化之后 |
|---|---|---|
| 缓冲量 | BRAM 2048B = **1 帧** | 槽区起步 2MB；全 4GB ≈ **290 万帧**（1466B 口径） |
| 忙时第 2 帧 | **整帧丢弃**（R1，hs_busy 门控） | 入队等待 |
| 突发吸收能力 | 无（背靠背预算丢 0.5–2%，E2 待验证） | **≈32 秒满速千兆缓冲**（4GB×8bit ÷ 1Gbps） |

**作用二：拥塞感知调度的硬件前提（论文主线 F4 的地基）**

| F4 要的能力（开题 L3） | 硬件等价物 | 无 DDR 队列时 |
|---|---|---|
| 优先级（结果包先于状态包） | **乱序服务**（后到者先被读走） | FIFO 只能按到达序弹，做不了 |
| 水位超限触发反压不丢包 | **可测量的队列深度** | 单帧在途，深度 0/1，无水位可言 |
| 多队列（按端口 / 优先级） | 每队一块独立缓冲 | BRAM 深度给不了 |
| 拥塞迁移 / 断链重路由 | 迁移期间**帧有地方停** | 帧在途即丢 |

关键一行：**随机读 = 读出顺序可 ≠ 写入顺序 = 可乱序服务 = 调度器的定义**——这是导师强调随机读的深层原因。本单（W 线槽式桥）与 #14 D 线（D2 描述符环多队列）是**同一张 valid/len 表的两步演进**（§8.2）：W 线先证明"地址是数据面的一等参数"，D 线在其上长出多队列与并发。

**答辩一句话**：DDR 把 fabric 从"单帧直通的管道"变成"**带 GB 级缓冲的可寻址队列**"——突发时接得住（容量），调度时按优先级 / 链路状况决定释放顺序（随机读语义）；这是拥塞感知调度与缓存/直通双模式（D4）的硬件前提。本轮交付"能力存在"的判据（J1–J6），收益数字留 D3/F4。

## 三、拓扑（单板 · 两级内存桥）

**本期范围**：只做 KU060-① 单板 + 单板双笼光回环，**不做双板组网**（用户 09-24 明确）。板级事实沿用工程事实卡（part `xcku060-ffva1156-2-i` · 100MHz 差分 AK17/AK16 · 复位 AC34 · LED T23/T22 · 串口 COM7 · PC `192.168.1.102` · DDR4 4GB MT40A512M16HA-083E ×4 / 64bit / DDR4-2400 / MIG `ddr4_0`）。渲染版拓扑见 [[汇报/汇报_cross_内存进环路拓扑图与数据流向_2026-09-26.pdf|《拓扑图与数据流向》]]。

### 3.1 线性数据流

```text
 PC
  │ 千兆网线 · UDP/JSON 帧
  ▼
 ①[GE1 RGMII / YT8531] → ②[以太网栈 ARP/ICMP/UDP]
  │ 8b
  ▼
 ③[泵A frame_fifo_pump]  帧感知 CDC · BRAM 2048B 单帧中转   【帧边界 + 帧长已知】
  ▼
 ④╔═【内存桥① 写】 槽号 = 写帧计数器 · 地址 = ING_BASE + slot×4KB ═╗
   ╚═ 512b 打包 → AXI4 突发写 → ⑤[(DDR4) INGRESS 槽区] ══════════╝
 ⑥╔═【内存桥① 读】 槽号 = 读地址选择器（递增 / 外部指定）═════════╗
   ╚═ AXI4 突发读 → 512b 拆包 → 8b 流 ════════════════════════════╝
  ▼
 ⑦[pack 8→64] → ⑧[Aurora A · X1Y11] ══► 笼A ═LC 跳线══ 笼B ══► ⑪[Aurora B · X1Y9]
 ⑫[unpack_b → pack_b]  整帧存储转发（prj9 根因修复，防 TX 欠载楔死）
 ⑬[Aurora B TX] ══► 笼B ═LC 跳线══ 笼A ══► ⑯[Aurora A RX]
  ▼
 ⑰[unpack 64→8]   【帧边界 + 帧长已知】
  ▼
 ⑱【内存桥② 写 → ⑲[(DDR4) EGRESS 槽区] → ⑳【内存桥② 读】（同①结构）
  ▼
 ㉑[泵B frame_fifo_pump]（user_clk → eth_rxc CDC）→ ㉒[RGMII TX] ──► PC
```

**与 prj9 的差异**：prj9 里 `泵A → pack` 直连；本方案在 `泵A↔pack`、`unpack↔泵B` 之间各插一级内存（写+读）。**数据面存量模块全部零改动**（以太网栈/泵/pack/unpack/Aurora）；**新增 = 内存桥×2 + MIG + 命令通道（§六.4）**——"零改动"承诺的边界是数据面，控制面新增命令解析属本期工作。

### 3.2 单板形态与双板形态的等价性（答辩外推依据）

- **能外推**：内存进出、光段收发、64b/66b 编解码往返——内存永远在**光段两端**，此结构单板/双板不变（双板只换接线：对端变另一块板的同号核 + 中间加转发引擎）。
- **不能外推**：跨板链路建立、转发决策与查表、多路径寻址（属 F1/后续阶段）。

## 四、路线定案：A（自研 RTL 内存桥）

**分岔口只有一处**——不在"要不要内存"、不在"要不要软核"，只在"**数据怎么进出 DDR**"：

| 路线 | 数据怎么进出 DDR | 数据面执行者 |
|---|---|---|
| **A（定案建议）** | AXIS → **自研 RTL AXI4 主机** → 直连 MIG `S_AXI`（512b） | 纯硬件；MicroBlaze **可选**（只下参数、读计数器） |
| B | AXIS → **AXI DMA** → SmartConnect → MIG | AXI DMA IP，MicroBlaze 软件配置（**必需**） |

**一句话理由**：「随机读写」考的是「**地址是不是一等参数**」，不是「谁来搬数据」——地址参数化在 A 里同样成立；B 会让 MicroBlaze 进入每帧数据通路，把功能里程碑变成「BD 集成 + DMA + 中断 + 位宽迁移」四变量联调。

| # | 选 A 理由 | 说明 |
|---|---|---|
| 1 | 与开题报告一致 | 开题 v2 §4.1「板内双平面：数据面纯硬件 + MicroBlaze 控制面」的直接实现 |
| 2 | 风险面小一个数量级 | B 的四变量任一项都可能吞 1–2 周 |
| 3 | 判据路径最短 | `mig_verify_top`（自研 AXI4 主机，写突发→读回→比对，离线已验证）可复用——只改地址源（递增→槽选择器）与数据源（pattern→帧泵输出），AXI4 时序骨架不动 |
| 4 | 不浪费 | 帧侧接口、槽结构、地址寄存器三样演进到 B 时原样保留 |

**三条接口预留**（把"A 可能返工"降为"只换一层"）：

| # | 预留 | 做法 | 演进到 B 时 |
|---|---|---|---|
| 1 | 内存桥拆两层 | `frame_mem_if`（帧侧：8b↔512b、槽地址生成、帧长邮箱）+ `axi4_master_bridge`（突发/4KB 边界/仲裁） | 只换 `axi4_master_bridge` |
| 2 | 选地址走寄存器 | 读槽号 + 模式寄存器，按 **AXI4-Lite 从机**语义设计 | 寄存器语义不变，改由 DMA 描述符驱动 |
| 3 | 接口保持 AXIS 语义 | 桥进出以「帧」为单位（帧边界 + 帧长已知） | DMA 直插，不必重造接口 |

**改选 B 的条件（先定后测）**：导师明确要求本期验收必须体现「MicroBlaze + C 代码配置搬运」机制口径（Q1）；或进入多队列/描述符环阶段（B 是终态，按预留平滑替换）。

## 五、时钟域与 CDC 契约

| 时钟域 | 频率 | 来源 | 接口/位宽 | 状态 |
|---|---|---|---|---|
| `eth_rxc` | 125 MHz | PHY（YT8531） | GMII 8b | 已有 |
| `user_clk` | ≈151.5 MHz | Aurora A GT 恢复钟 → MMCM | AXIS 64b | 已有 |
| `user_clk_b` | ≈151.5 MHz | Aurora B | AXIS 64b | 已有 |
| `ui_clk` | **≈300 MHz** | MIG MMCM（4:1 推算，以生成报告为准） | **AXI4 512b** | **新增** |
| `init_clk` | 100 MHz | 板载差分 AK17/AK16 | 复位/DRP | 已有 |

| 跨界 | 机制 | 状态 |
|---|---|---|
| `eth_rxc` ↔ `user_clk` | 泵A/泵B（格雷码指针异步 FIFO + 4 相握手邮箱） | 已有 |
| **`user_clk` ↔ `ui_clk`** | **内存桥内异步 FIFO（512b 数据 + 帧长邮箱）** | **新增** |
| `init_clk` ↔ 各域 | 复位同步链 | 已有 |

> ⚠️ **铁律（prj9 血泪）**：`ui_clk` 域的 ILA **必须挂 `ui_clk`**——跨域采样曾把 WNS 打到 −2.639 ns 且抓到亚稳态值；判决计数器按域分挂。
> ⚠️ **MIG 硬门控**：内存桥必须等 `init_calib_complete` 同步进用户逻辑 + `ui_clk_sync_rst` 释放后才放行任何 AW/AR，否则挂死（坑位表在案）。

## 六、地址映射、槽结构与资源管理 ★ 含体检新增两节

### 6.1 地址空间（初版，W2 仿真前定稿）

```text
 DDR4 4GB · 32bit 字节地址
 0x0010_0000  INGRESS 槽区  槽 0…255 × 4KB = 1 MB   （ING_BASE）
 0x0020_0000  EGRESS  槽区  槽 0…255 × 4KB = 1 MB   （EGR_BASE）
 0x0030_0000  空闲（多队列 / 描述符环预留）
```

### 6.2 槽结构（定版口径，钉死）

- **4KB × 256 × 2 区 = 2MB**——4KB 对齐使单帧突发天然不跨 AXI 4KB 边界；单帧 ≤1538B（prj9 帧长契约，chunk=1466）。
- 槽内布局：`[15:0] frame_len` + 帧字节流；长度来源 = 泵的逐帧计数，**不重新解析以太网帧**。
- ⚠️ 学长工程"16 槽 × 64KB"仅作存量证据（§二），**本期不沿用**——两套口径并存曾致歧义（体检 P7），以本节为准。

### 6.3 槽资源管理协议 ★ 新增（体检 P5：回绕覆盖与非法读是"随机读写"能否自证的关键）

| 机制 | 规格 | 解决什么 |
|---|---|---|
| **读模式寄存器 MODE** | `SEQ`（顺序跟随，J2/J4 用）/ `RND`（外部指定槽号，J3 用） | 两类判据对槽管理的需求不同，显式分模 |
| **SEQ 写等读水位** | 写指针不得覆盖未读槽（追上即写停顿，`wr_stall_cnt` 计数可见）；PC pacing 下不触发 | J4 全量 10MB 过 1MB 槽区 = **10 次回绕**，无此机制必覆盖未读帧 |
| **RND 水位防护** | 命令槽号必须 < 当前写水位；硬件 clamp 到有效范围 + `ill_rd_cnt` 计数 | 随机读未写槽从**未定义行为**变为**定义行为**（可观测、可判读） |
| **槽有效/长度表** | 小 BRAM：256×1b（valid）+ 256×16b（len），写侧置位/读侧清除 | 帧长可变（≤1538B），读出长度不靠猜 |
| **PC 侧配合** | RND 模式测试时先发 N 帧（N≤256 驻留），再下发乱序读序列 | J3 测法的前提，见 §七 |

> 该协议与 #14 D 线 D2 的"水位可观测"是同一机制的两步——W 线先做功能版（单指针 + 水位），D 线升级为描述符环（多帧并发），复用同一张 valid/len 表。

### 6.4 命令通道（乱序槽号序列的载体）★ 新增（体检 P4）

| 方案 | 做法 | 工程量 | 备注 |
|---|---|---|---|
| **UDP 命令字（建议）** | 独立端口（如 1235）+ 独立小解析器（约百行），命令经 4 相握手邮箱进 `user_clk` 域寄存器；**不触碰现有 udp_rx/udp_tx 数据路径** | 小（纯增量） | 不引入 MicroBlaze/BD，与路线 A 自洽 |
| MicroBlaze AXI-Lite | 软核写地址/模式寄存器 | 中（BD 集成） | 若导师要求软核口径（Q3）则用；寄存器语义不变 |

**命令语义最小集**：`SET_MODE`（SEQ/RND）· `SET_RD_SLOT`（槽号）· `GET_WATERMARK`（写水位回读，供 PC 判定合法槽号范围）。

## 七、判据（J1–J6）

| # | 判据 | 说明 |
|---|---|---|
| J1 | `init_calib_complete` = 1 | DDR4 校准完成——**阶段三至今未取得的判据** |
| J2 | 写入帧 vs 读出帧逐字节一致 | 内存读写正确性 |
| **J3** | **读出顺序 ≠ 写入顺序，且每帧与其槽位严格对应** | **随机读写的决定性证据** |
| J4 | 全量 10MB SHA256 一致 | 与 prj9 同口径，"内存进环路后业务不退化" |
| J5 | 读地址可控且可观测 | ILA 可见写槽号/读槽号/突发计数/帧计数；寄存器可回读 |
| J6 | ping 20/20 + UDP 12/12 仍全过 | 环路基本功能未被破坏 |

**J3 具体测法**（PC 侧脚本自动判定，答辩当场复现）：

| 测法 | 通过标准 |
|---|---|
| 连发 N 帧（N ≥ 槽数），看 ILA 写槽号 | 帧计数递增，多帧落在不同 slot |
| 上位机下发**乱序槽号序列**（如 7, 3, 255, 0, …，经 §六.4 命令通道） | 读出帧序 = 下发序列 |
| PC 给每帧 payload 带序号，按（槽号 → 序号）映射逐帧校验 | 乱序**不串帧**，内容与槽位一致 |
| 同槽连读两次 / 跳号读 / 回读已读槽 | 内容与首次一致 → 证明"按地址取"而非"按序弹" |

### 8.2 与 #14 D 线的衔接（体检 P3 定案建议）

- **W 线（本单）**：内存语义进数据面的**功能验证**——槽式按地址读写、随机读判据。
- **#14 D 线**：**队列容量线**——D2 描述符环 + 多帧并发 + GB 级水位，D3 判别复测，D5 DMA。

## 九、静态带宽预算初算 ★ 新增（体检 P6；W2 仿真定稿）

帧长 ≤1538B → 512b 位宽下 24 拍/帧突发；`ui_clk`≈300MHz：

| 项 | 估算 | 依据 |
|---|---|---|
| 单桥每帧服务（写突发 + 读突发 + AXI 握手/反转 + MIG 读延迟） | ≈0.4–0.7 µs | 24 拍×2 ≈ 0.16 µs + 握手/反转 ~0.2–0.4 µs + MIG 读延迟 ~0.1–0.2 µs |
| 两级桥合计 | ≈1–1.4 µs/帧 | 远小于帧周期 12.304 µs（千兆 1466B 口径） |
| **结论** | **全链路节拍不变（≈957–959 Mbps 口径保留），端到端延迟 +1–1.4 µs** | 节拍器仍是泵B（12.21 µs，prj9 实操单 v2 §三）；桥服务 ≪ 泵服务 |

> SEQ 模式（J4）下数据流水穿过槽区（写等读水位不触发），吞吐口径与 prj9 一致；RND 模式（J3）是功能测试，不占吞吐口径。
