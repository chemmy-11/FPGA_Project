## 一、需求定界（内存语义，不是更深的 FIFO）

### 1.1 需求转写

**导师原话（2026-09-24）**：以太网发送的数据先写到内存 → 内存里选定某个地址（**每次可选不一样**）读出来 → 经光回环再存到内存 → 最后从内存读出经以太网发回；**核心是把内存读写、特别是随机读写放进整个环路**。

**转写**：在现有「以太网 ↔ 光回环」通路的光口**两侧**各插一级 DDR4（**写 + 按地址读**），数据面从"流式直通"变为"**按地址存储转发**"。

| 维度 | 现在（帧泵 = FIFO 语义） | 导师要求（内存语义） |
|---|---|---|
| 地址 | 硬件自行递增，对外不可见 | **地址是显式、可指定的一等参数** |
| 读出顺序 | 必然等于写入顺序 | **可不同于写入顺序** |
| 数据归属 | "第 N 个出来的那份" | "**存在地址 X 的那份**" |

**「随机读写」的判定式**：读出顺序 ≠ 写入顺序，且每帧内容与其槽位严格对应。这是"内存 ≠ 更深的 FIFO"的决定性证据，也是后续多队列 / 优先级 / 拥塞迁移 / 描述符环的地基。

**读法确认（Q2 回填 · 已定案 2026-09-30）**：

- **读侧 = 真随机**——读出顺序**不必等于**写入顺序，且每帧内容与其槽严格对应；读槽号由外部（本期 = 上位机）指定（判据 J3，测法见 §七）。
- **写侧 = 「怎么方便怎么写」**——写入布局（槽号分配、地址排布）自由，**唯一硬约束 = 任何已写数据必须能被读出来**（判据 J3′，测法见 §七）。
- ⚠️ **口径（防误读）**：「写侧布局自由」**≠** 可以省掉地址信息。**写槽号的选择规则必须确定且可复现**（例如「帧计数 mod 256」这类可复算的映射），否则读侧无从构造合法读序列（须配合 `GET_SLOT_MAP` 回读，§六.4），「**想取出来的时候能读出来**」就**不可证**。
- **本单不采用的另一种理解**：「写侧分槽、读侧恒按写序读出」（＝更深的 FIFO）。它在 Q2 原话下已排除——原话要求读侧「真的随机读」。
- 该读法正是 §1.2 作用二（乱序服务 ＝ 调度器定义）的判据化。

### 1.2 内存在整个系统中的两个实际作用（第一性原理 · 答辩口径）★ 2026-09-29 补

**前提（先排除错误预期）**：DDR **不提速**——带宽 19.2 GB/s（DDR4-2400×64b）≫ 千兆口 ~119 MB/s，差三个数量级、永不成为瓶颈；fabric 静态预算已在线速上（≈957–959 Mbps，[[操作文档/阶段二之十_prj9_传输效率与瓶颈判定实操单_2026-09-29|prj9 实操单 v2]] §三）。且当前单端点环路（PC↔单板↔PC）里 DDR **看不到收益**——它的价值在**容量与地址语义**，只在多端点 / 突发 / 优先级 / 断链场景激活。这正是 Q5 功能验证口径（2026-09-30 已定案：暂不要求提高端口速率）的原因；收益量化由 D3（判别复测）与 F4（调度实验）承载。

**作用一：突发吸收——多对一拥塞时"先接住，再按线速放"**

交换的基本矛盾：**入侧聚合速率可瞬时超过出侧线速**。典型触发 = 开题 MoA 负载的**聚合相位**（多 Agent 输出同时涌向一个汇聚端，即经典 incast）与 ≥3 端点同发一条出边（#13 原触发条件）。现状对照：

| | 现状（帧泵单帧在途） | DDR 化之后 |
|---|---|---|
| 缓冲量 | BRAM 2048B = **1 帧** | 槽区起步 2MB；全 4GB ≈ **290 万帧**（1466B 口径） |
| 忙时第 2 帧 | **整帧丢弃**（R1，hs_busy 门控） | 入队等待 |
| 突发吸收能力 | 无（背靠背预算丢 0.5–2%，E2 待验证） | **≈32 秒满速千兆缓冲**（4GB×8bit ÷ 1Gbps） |

**作用二：拥塞感知调度的硬件前提（论文主线 F4 的地基）**

| F4 要的能力（开题 L3） | 硬件等价物 | 无 DDR 队列时 |
|---|---|---|
| 优先级（结果包先于状态包） | **乱序服务**（后到者先被读走） | FIFO 只能按到达序弹，做不了 |
| 水位超限触发反压不丢包 | **可测量的队列深度** | 单帧在途，深度 0/1，无水位可言 |
| 多队列（按端口 / 优先级） | 每队一块独立缓冲 | BRAM 深度给不了 |
| 拥塞迁移 / 断链重路由 | 迁移期间**帧有地方停** | 帧在途即丢 |

关键一行：**随机读 = 读出顺序可 ≠ 写入顺序 = 可乱序服务 = 调度器的定义**——这是导师强调随机读的深层原因。本单（W 线槽式桥）与 #14 D 线（D2 描述符环多队列）是**同一张 valid/len 表的两步演进**（§8.2）：W 线先证明"地址是数据面的一等参数"，D 线在其上长出多队列与并发。

**答辩一句话**：DDR 把 fabric 从"单帧直通的管道"变成"**带 GB 级缓冲的可寻址队列**"——突发时接得住（容量），调度时按优先级 / 链路状况决定释放顺序（随机读语义）；这是拥塞感知调度与缓存/直通双模式（D4）的硬件前提。本轮交付"能力存在"的判据（**J1–J6 + J3′**），收益数字留 D3/F4。

**与 prj9 的差异**：prj9 里 `泵A → pack` 直连；本方案在 `泵A↔pack`、`unpack↔泵B` 之间各插一级内存（写+读）。**数据面存量模块全部零改动**（以太网栈/泵/pack/unpack/Aurora）；**新增 = 内存桥×2 + MIG + 命令通道（§六.4）**——"零改动"承诺的边界是数据面，控制面新增命令解析属本期工作。

### 3.2 单板形态与双板形态的等价性（答辩外推依据）

- **能外推**：内存进出、光段收发、64b/66b 编解码往返——内存永远在**光段两端**，此结构单板/双板不变（双板只换接线：对端变另一块板的同号核 + 中间加转发引擎）。
- **不能外推**：跨板链路建立、转发决策与查表、多路径寻址（属 F1/后续阶段）。

## 四、路线定案：A（自研 RTL 内存桥）

**分岔口只有一处**——不在"要不要内存"、不在"要不要软核"，只在"**数据怎么进出 DDR**"：

| 路线 | 数据怎么进出 DDR | 数据面执行者 |
|---|---|---|
| **A（已定案，Q1）** | AXIS → **自研 RTL AXI4 主机** → 直连 MIG `S_AXI`（512b） | 纯硬件；MicroBlaze **可选**（只下参数、读计数器） |
| B（后继，Q1 第二步） | AXIS → **AXI DMA** → SmartConnect → MIG | AXI DMA IP，MicroBlaze 软件配置（**必需**） |

**两步走（Q1 回填 · 已定案 2026-09-30）**：A 是**现在做**的一步，B 是**A 的功能判据全部通过之后**再叠加的第二步——**B 不推翻 A**（帧侧接口、槽结构、地址寄存器原样演进，§四条预留即为此存在）。导师原话「先实现功能，然后再加上软核」是本序的唯一依据；**本单不把 Q1 读作「A 作废、改做 B」**。

**一句话理由**：「随机读写」考的是「**地址是不是一等参数**」，不是「谁来搬数据」——地址参数化在 A 里同样成立；B 会让 MicroBlaze 进入每帧数据通路，把功能里程碑变成「BD 集成 + DMA + 中断 + 位宽迁移」四变量联调。

| # | 选 A 理由 | 说明 |
|---|---|---|
| 1 | 与开题报告一致 | 开题 v2 §4.1「板内双平面：数据面纯硬件 + MicroBlaze 控制面」的直接实现 |
| 2 | 风险面小一个数量级 | B 的四变量任一项都可能吞 1–2 周 |
| 3 | 判据路径最短 | `mig_verify_top`（自研 AXI4 主机，写突发→读回→比对，离线已验证）可复用——只改地址源（递增→槽选择器）与数据源（pattern→帧泵输出），AXI4 时序骨架不动 |
| 4 | 不浪费 | 帧侧接口、槽结构、地址寄存器三样演进到 B 时原样保留 |

**三条接口预留**（把"A 可能返工"降为"只换一层"）：

| # | 预留 | 做法 | 演进到 B 时 |
|---|---|---|---|
| 1 | 内存桥拆两层 | `frame_mem_if`（帧侧：8b↔512b、槽地址生成、帧长邮箱）+ `axi4_master_bridge`（突发/4KB 边界/仲裁） | 只换 `axi4_master_bridge` |
| 2 | 选地址走寄存器 | 读槽号 + 模式寄存器，按 **AXI4-Lite 从机**语义设计 | 寄存器语义不变，改由 DMA 描述符驱动 |
| 3 | 接口保持 AXIS 语义 | 桥进出以「帧」为单位（帧边界 + 帧长已知） | DMA 直插，不必重造接口 |

> **三条预留的目的（Q1 回填）**：正是让 Q1 的「**A → B 两步走**」**不返工**——第一步（A）交付功能判据，第二步（B）只换 `axi4_master_bridge` 一层，帧侧接口 / 寄存器语义 / AXIS 语义三样全部原样继承。**因此：任一条预留被砍，都等于把 Q1 的两步走重新变成一次性选型。**

**B 的启动条件 = A 的功能判据全部通过后（Q1 定案）**：

- **主条件**：J1–J6 + J3′（§七）全部通过——即「先实现功能」这一步交齐，才「再加上软核」。
- **关系**：两者**不是并列关系**——主条件是**门**，加速条件只是说「即使功能判据已过，也不必立刻做 B」；**任何情况下 A 都不作废**（B 落地时只换 `axi4_master_bridge` 一层，三条预留见上）。
- **已排除的旧口径**：「导师要求本期验收必须体现 MicroBlaze + C 机制」——Q1 答复已明确先 A 后 B，该前置条件不成立。

## 六、地址映射、槽结构与资源管理 ★ 含体检新增两节（Q2/Q3 已回填）

### 6.1 地址空间（定版；W2 仿真已按此实现）

```text
 DDR4 4GB · 32bit 字节地址
 0x0010_0000  INGRESS 槽区  槽 0…255 × 4KB = 1 MB   （ING_BASE）
 0x0020_0000  EGRESS  槽区  槽 0…255 × 4KB = 1 MB   （EGR_BASE）
 0x0030_0000  空闲（多队列 / 描述符环预留）
```

### 6.2 槽结构（定版口径，钉死；Q2 下仍然成立：写侧布局自由 ≠ 槽结构可省）

- **4KB × 256 × 2 区 = 2MB**——4KB 对齐使单帧突发天然不跨 AXI 4KB 边界；单帧 ≤1538B（prj9 帧长契约，chunk=1466）。
- 槽内布局：`[15:0] frame_len` + 帧字节流；长度来源 = 泵的逐帧计数，**不重新解析以太网帧**。
- ⚠️ 学长工程"16 槽 × 64KB"仅作存量证据（§二），**本期不沿用**——两套口径并存曾致歧义（体检 P7），以本节为准。

### 6.3 槽资源管理协议 ★ 新增（体检 P5：回绕覆盖与非法读是"随机读写"能否自证的关键）

| 机制 | 规格 | 解决什么 |
|---|---|---|
| **读模式寄存器 MODE（Q2 已定案）** | **`RND` = 唯一必须支持的读模式**（读槽号由外部＝上位机指定，J3/J3′ 用）；**`SEQ` = 对照模式**（顺序跟随，只作拿基线的对照，J2/J4 用），**不再是主路径** | Q2 原话「读的时候真的随机读」→ 随机读是**要求本身**，顺序读只是回归对照 |
| **SEQ 写等读水位** | 写指针不得覆盖未读槽（追上即写停顿，`wr_stall_cnt` 计数可见）；PC pacing 下不触发 | J4 全量 10MB 过 1MB 槽区 = **10 次回绕**，无此机制必覆盖未读帧 |
| **写槽号选择规则（Q2 新增硬约束）** | 规则必须**确定且可复现**（本单取「写帧计数器 mod 256」）；由 `GET_SLOT_MAP`（§六.4）向 PC 暴露「帧序号 ↔ 槽号」映射 | 「写怎么方便怎么写」的边界：**布局可自由，映射必须可复算**——否则「想取出来的时候能读出来」（J3′）不可证 |
| **RND 水位防护** | 命令槽号必须 < 当前写水位；硬件 clamp 到有效范围 + `ill_rd_cnt` 计数 | 随机读未写槽从**未定义行为**变为**定义行为**（可观测、可判读） |
| **槽有效/长度表** | 小 BRAM：256×1b（valid）+ 256×16b（len），写侧置位/读侧清除 | 帧长可变（≤1538B），读出长度不靠猜 |
| **PC 侧配合** | RND 模式测试时先发 N 帧（N≤256 驻留），再下发乱序读序列 | J3 测法的前提，见 §七 |
| **RND 读语义（破坏性读 · 2026-09-30 逐行核实）** | **RND 读完成后，被服务槽 `full_bit` 被清 0（= 退休）**；同一槽再读 → `stat_ill_rd++` + 定长空应答（`rlen=0`）。RTL 证据：`axi4_master_bridge.v:441-442`（R_FIN 里 `rd_retire<=1` / `rd_retire_slot<=r_slot`，**不带 `r_rnd` 条件**）→ `:132-133`（`if (rd_retire) full_bit[rd_retire_slot] <= 1'b0; // retire wins on collision`）；RND 唯一分支在 `:445`（`if (!r_rnd) rd_seq_slot <= rd_seq_slot + 1`，只管 SEQ 指针）。行为已被用例固定：`sim/mem_bridge_tb.sv:322-324` T5b（retired slot → defined empty）。 | **J3′ 成立的前提**：随机置换里**每个槽恰好读一次**（读回集合 = 写入集合）；**不需要**非破坏性读 |
| **槽复用纪律（批量级 · 2026-09-30 补）** | **RND 模式的槽复用是「批量级」的：一批写满后必须把该批读空（或读到一个约定的安全水位），写侧才继续推进。** 依据：破坏性退休（上一行）＋写侧「槽已 FULL 即拒收」——`axi4_master_bridge.v:179 wire w_no_room = full_bit[w_slot_next];`（`:178` 写槽号 = `stat_wm[7:0]`，顺序推进）→ 拒收在 `:295-297 W_DRAIN` 里计 `stat_wr_stall++`。故**只随机读了前 k 个槽就继续写**时，写指针会依次撞上仍 FULL 的槽 → `wr_stall_cnt` 连续累积，直到那些槽也被读走才停。 | 这是「写怎么方便怎么写」（Q2）在**破坏性读**下的必然推论，不是缺陷。**两个计数器必须分清**：`wr_stall_cnt` 累积 = 复用纪律被触发（上一批没读空就又写）；`ill_rd_cnt` 递增 = 越界 / 重读已退休槽（命令本身非法）。**J3′ 的「每槽恰好读一次」正是这条纪律的判据形态** |

> 该协议与 #14 D 线 D2 的"水位可观测"是同一机制的两步——W 线先做功能版（单指针 + 水位），D 线升级为描述符环（多帧并发），复用同一张 valid/len 表。

> **RND 读语义钉死（2026-09-30 逐行核实 RTL 后的订正）**：`prj10_W2_mem_bridge_design_note_2026-09-29.md:71` 把 RND 越界/非 FULL 槽列为 ill_rd，语焉不详之处由此行补全——**RND 是「一次性取走」语义**：读完即退休，再读同槽回定长空应答（可计数，非未定义行为）。
> ⚠️ **因此**：§七 的「同槽连读两次，内容一致」**在本 RTL 下不作通过标准**（第二次按设计返回空应答）；**J3′ 只依赖「每槽读一次」**。这条语义一旦被改动（例如为了让 RND 也可重读而改成「RND 不退休」），J3′ 的读回集合会**静默缺帧**——改动者必须同时重跑 J3/J3′ 与 T5b。

### 6.4 命令通道（乱序槽号序列的载体）★ 新增（体检 P4）

| 方案 | 做法 | 工程量 | 备注 |
|---|---|---|---|
| **【本期定案】UDP 命令字** | 独立端口（如 1235）+ 独立小解析器（约百行），命令经 4 相握手邮箱进 `user_clk` 域寄存器；**不触碰现有 udp_rx/udp_tx 数据路径** | 小（纯增量） | **Q3 定案落点**：原话「我们现在可以先做由上位机控制」→ 本期地址由上位机定，不引入 MicroBlaze/BD，与路线 A 自洽 |
| MicroBlaze AXI-Lite（**后继**） | 软核写地址/模式寄存器 | 中（BD 集成） | **Q3 理想终态**：原话「最理想的目的是用软核加上 C 来控制自己的读写位置」——**A 的功能判据通过后**再接（与 Q1 第二步同源）；寄存器语义不变，故本期按 AXI4-Lite 从机语义设计预留 |

**命令语义最小集**：`SET_MODE`（SEQ/RND）· `SET_RD_SLOT`（槽号）· `GET_WATERMARK`（写水位回读，供 PC 判定合法槽号范围）· **`GET_SLOT_MAP`（槽映射回读：帧序号 → 槽号）**。

> **`GET_SLOT_MAP` 为什么是必须的（Q2 回填）**：随机读要求 PC 能构造**合法**的读序列；而写侧布局自由（Q2），PC 无法凭空知道「哪一帧在哪个槽」。取水位的 `GET_WATERMARK` 只给出**范围**，给不出**映射**——没有 `GET_SLOT_MAP`（或等价机制），J3 的「乱序序列」就只能靠猜，J3′ 的「全部读回」无法构造。**备注**：若写成「写槽号 = 帧计数 mod 256」这类固定规则，该映射可由 PC 本地复算（`GET_SLOT_MAP` 退化为校验用途）；规则一旦变更，回读即为唯一依据。

## 七、判据（J1–J6 + J3′ 可取出性；Q2 已回填）

| # | 判据 | 说明 |
|---|---|---|
| J1 | `init_calib_complete` = 1 | DDR4 校准完成——**阶段三至今未取得的判据** |
| J2 | 写入帧 vs 读出帧逐字节一致 | 内存读写正确性 |
| **J3** | **读出顺序 ≠ 写入顺序，且每帧与其槽位严格对应** | **随机读写的决定性证据**——证「顺序可乱」（读侧真随机，Q2） |
| **J3′（Q2 新增）** | **可取出性：写进 N 帧后，用随机顺序把 N 帧全部读回，读回的集合与写入的集合逐帧逐字节一致（集合级，不抽样）** | 对应 Q2 原话「**想要取出来的时候能读出来**」——证「一个都不少、都能取出来」（写侧硬约束） |
| J4 | 全量 10MB SHA256 一致 | 与 prj9 同口径，"内存进环路后业务不退化" |
| J5 | 读地址可控且可观测 | ILA 可见写槽号/读槽号/突发计数/帧计数；寄存器可回读 |
| J6 | ping 20/20 + UDP 12/12 仍全过 | 环路基本功能未被破坏 |

**J3 与 J3′ 的区别（Q2 回填，防混判）**：

| | 证什么 | 对应 Q2 原话 | 失败长什么样 |
|---|---|---|---|
| **J3** | 「顺序可乱」——读出顺序 ≠ 写入顺序，且逐帧内容与槽对应（**允许抽样路径**） | 「读的时候真的随机读」 | 读出顺序恒等于写入顺序（= 退化成 FIFO），或乱序时串帧 |
| **J3′** | 「一个都不少」——**集合级**证明：写入集合 = 读回集合，逐帧逐字节 | 「只要存在一个地方，想要取出来的时候能读出来就行」 | 有一帧读不出来 / 读回内容不符 / 只能抽样证明（未覆盖全集合） |

> 判定口径：**J3 通过 ≠ J3′ 通过**（乱序能读对，仍可能漏掉读不出来的帧）。本期两条都要过。

**J3 具体测法**（PC 侧脚本自动判定，答辩当场复现）：

| 测法 | 通过标准 |
|---|---|
| 连发 N 帧（N ≥ 槽数），看 ILA 写槽号 | 帧计数递增，多帧落在不同 slot |
| 上位机下发**乱序槽号序列**（如 7, 3, 255, 0, …，经 §六.4 命令通道） | 读出帧序 = 下发序列 |
| PC 给每帧 payload 带序号，按（槽号 → 序号）映射逐帧校验 | 乱序**不串帧**，内容与槽位一致 |
| 跳号读 / 回读**未读**槽 | 内容与写入一致 → 证明「按地址取」而非「按序弹」 |
| 同槽连读两次（**当前语义下第二次应为空应答**） | 第二次 `rlen=0` + `stat_ill_rd++` → 证明 RND「一次性取走、读完即退休」（§六.3；RTL `:441-442`/`:132-133`，用例 `mem_bridge_tb.sv:322-324`）。**注**：v0.1 曾写「两次内容一致」，与在案 RTL 相悖，**已订正**（详见 §六.3 注） |

**J3′ 具体测法（可取出性 · 集合级）**（PC 侧脚本自动判定）：

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 1 | PC 写 **N 帧**（N = 槽数 256 或其整倍数，覆盖全部写槽），每帧 payload 带**唯一序号 + 帧内递增模式** | 写入帧计数 = N；`GET_WATERMARK` 回读水位 = N（未回绕时） |
| 2 | 经 §六.4 下发**随机排列的完整槽号序列**（256 个槽号的一个随机置换，**不重复、不遗漏**） | 读序列 = 下发序列（与 J3 共用同一序列生成器） |
| 3 | 把读回的 N 帧按序号收齐，与写入的 N 帧**逐帧逐字节**比对（SHA256 逐帧） | **集合相等**：读回集合 = 写入集合，**0 缺帧 / 0 多余 / 0 字节差异** |
| 4 | 故意**漏发**一个槽号再跑一遍（负向验证） | 必须报**缺 1 帧**（证明判据不是恒真「全过」） |
| 5 | 故意**重发**一个槽号（同一槽读两次） | 第二次按 §六.3 语义回**定长空应答**（`rlen=0`）且 `ill_rd_cnt` 递增 → 按「命令数 = N+1、实取帧 = N、集合仍相等」判读（**不是**「两次内容一致」） |

## 九、静态带宽预算（按 2026-09-29 二次核查实测定稿；Q2/Q5 已回填）

**口径源**：[[操作文档/阶段三_prj10_W3前置清单_2026-09-29]] §2.1/§2.2（逐行 RTL 复核 + 实测计数回归模型）+ [[调试记录/阶段三_prj10_内存桥RTL与仿真记录_2026-09-29]] §四。帧长 ≤1538B → 512b 位宽下**设计点 1466B = 23 拍/帧**；`ui_clk` = **300.12 MHz**（真 MIG 位流实测）。

### 9.1 服务时间（设计点 1466 B）

| 项 | **测定值（09-29 口径）** | 依据 |
|---|---|---|
| 单桥写服务 | **5.14 µs**（替身模型 Lw≈2 拍）/ **5.80 µs**（Lw=200 拍） | 实测计数回归模型 `T_w = L + 3·ceil(L/64) + 4 + Lw`（L=1466，`axi4_master_bridge.v:197-205`） |
| 单桥读服务 | 同量级（读首拍延迟 Lr 暴露一次）；单桥服务 = **max(写, 读)**（读写是**并行两个 FSM**） | 同上 `:400-410`；W2 实测读 3.07 µs（混合帧长） |
| 单桥端口硬上限 | **300 MB/s / 方向**（`W_FILL` / `R_UNPACK` 各 1 字节/ui_clk @300 MHz） | 同上（双向合计 ≈600 MB/s） |
| **两级桥串行（最坏同一帧穿两桥）** | **10.21 µs**（替身）/ **11.68 µs**（含 Lw/Lr） | 两次单桥服务串起来 |
| **裕量** | **1.20× / 1.05×** —— **能跑，但薄**（结论分叉点，见 §9.3） | 12.304 ÷ 10.21 / 11.68 |

> ⚠️ **旧值作废（2026-09-30 Q2/二次核查回填）**：本单 v0.1 写的 **「单桥 0.4–0.7 µs / 端到端 +1–1.4 µs」作废**——它只算了 AXI 突发本体（24 拍 ≈0.16 µs），**漏掉 8b↔512b 逐字节转换**（每帧 1466 字节要逐字节装载/拆包，这才是真实服务时间的主项）。同样作废的还有 W2 记录早期的「两级桥 ≈6.2 µs、端到端 +6 µs」——**`3.11/3.07 µs/帧` 是混合帧长均值，不可作设计点引用**（W3 前置清单 §2.2）。

### 9.2 正确读法：三个周期不能混

| 量 | 值 | 含义 |
|---|---|---|
| 帧周期 | **12.304 µs** | 千兆 1466 B 口径的**帧间隔** |
| 泵服务周期（节拍器） | 12.21 / 12.24 µs | 泵B / 栈TX（prj9 实操单 v2 §三） |
| 单桥服务时间 | **5.14 / 5.80 µs** | 一趟**写+读**合并的桥占用（读写并行 FSM） |
| 两级桥串行服务 | **10.2 / 11.7 µs** | **最坏同一帧穿两桥的串行和**；正常流水下**不逐帧相加**（同一帧穿两桥才有此最坏值） |

**判据式**：节拍不破 ⇔ **单桥服务 < 帧周期**（5.14 / 5.80 ≪ 12.304 → 2.1× 余量）；帧间隔期间两级桥可各自完成 1–2 帧，中间桥是流水重叠而非累加。

| 项 | 值 |
|---|---|
| 全链路节拍 | **不变**（≈957–959 Mbps 口径保留，节拍器仍是泵B） |
| 端到端延迟 | **+10.2–11.7 µs（两级桥串行；含 Lw/Lr）** |
| 帧率 | 单桥稳态 **194.7k fps（替身）/ 170.1k fps（含 Lw/Lr）** vs 线速 **81.27k fps** → 2.39× / 2.09× |

### 9.3 约束不是带宽，是端口并发与延迟（Q5 直接落点）

| 量 | 值 | 来源 |
|---|---|---|
| DDR 侧占用 | 写 **0.515 GB/s** + 读 **0.521 GB/s**（服务期内）→ 按帧周期摊平各 **0.130 GB/s** | `W_FILL`/`R_UNPACK` 字节率换算 |
| MIG 持续上界 | ≈**10.6–16.3 GB/s**（DDR4-2400×64bit 理论 19.21 GB/s，打 55–85% 折损） | 算术 |
| **DDR 占用率** | 桥只用 **≈3–5%/方向（合计 ≈6–10%，按服务期口径）**；**每帧只忙 46/3690 拍 = 1.25%**（按帧周期口径，含空闲） | 上两行相除 |

→ **两条口径都远低于饱和**：Q5 定案「暂不要求提高端口速率」下，**DDR 带宽不是约束**；真正的瓶颈是**端口并发**（每方向 300 MB/s 硬上限）与**延迟暴露**（每帧写等 `BVALID`、读等首拍各一次，`axi4_master_bridge.v:175/277/317/420`）。**不流水时 `Lw+Lr > 636 拍` 即破坏节拍**（阈值 = 帧周期 3690 拍 − 固定开销）。
→ 若要加固，方向是**多 outstanding / 读写分端口流水**，**不是加带宽**（W3 前置清单 §2.1）。

### 9.4 W3 前置硬阻断（本预算的适用前提）

预算成立的前提是 W3 能换真 MIG；清单见 [[操作文档/阶段三_prj10_W3前置清单_2026-09-29]]，**4 项硬阻断**：**B1** 桥缺 12 个 AXI4 端口（无法与真 MIG 例化）· **B2** 时序零余量（WNS=+0.024 / WHS=+0.004 ns）· **B3** 真 MIG 的 Lw/Lr 未实测（本文 5.14/5.80 µs 是替身+回归模型值，**非真 DDR4 实测**）· **B4** 尾拍部分 WSTRB 灰色地带（非 64 B 整倍数帧必测）。**这些项未清完前，§9.1 的串行服务时间是推算上界，不是实测结论。**
