# 调试记录：prj9 0.4% 相邻对丢失根因定案（2026-09-21）

## 一、问题

全量 10MB 会话传输稳定丢失 ~0.4%（26-32 帧），呈**相邻对**分布，与节奏无关（1/2/5ms 同率），损坏与乱序恒为 0。

## 二、装备：判决位流 build9v（git d9327bd）

此前查不到的装备原因：**B 通道（user_clk_b 域）从未有过自己的 ILA**。本轮：

1. 新增 ILA2 @ user_clk_b（B 域信号严禁挂 A 域/eth 域 ILA——独立时钟域必须独立 ILA）；
2. 六段差分链计数器：`pfwd_wr→pfwd_rd→pk_frames→echo_b_rx→echo_b_tx→up_frames→prev_wr`；
3. 溢出/错误事件计数器（pk_ovf_cnt / echo_b_ovf_cnt / hard/soft_err_cnt / 断链事件）；
4. 泵A 冻结看门狗（hs_busy 连续 >2M 拍 ≈ 13ms = 楔死，记事件数）；
5. pack 的 `o_overflow` 由粘滞电平改单拍脉冲（配计数器给出事件幅度）；
6. 配套 `verdict_capture.ps1`：快照→传输→快照→差分→自动判决一条龙。

## 四、根因机制

`axis_word_pack` 输出队列仅 **2 深**。Aurora TX 偶发反压（tready 瞬时停顿：时钟校正插入/内部缓冲），队列满时**新完成的字被丢弃**——若被丢弃的字携带 **tlast（帧尾）**，帧边界被吞，**相邻两帧在 Aurora 层合并成一根长帧**；合并帧到 PC 后长度/校验不对被静默丢弃 → **两帧成对消失**。

算术闭合：7 次合并 × 2 + 9 次合并 × 2 = **32 = PC 实丢**。

「相邻对」签名、「与节奏无关」（反压是随机的，与输入 pacing 无关）、「损坏恒 0」（丢的是整帧不是坏字节）——全部签名一次解释。

顺带修正的假象：此前把 A.TX→纤→B.RX 段差额误读为「光纤段丢失」——实际是 pack A 丢 tlast 字在**下游**表现出来的帧合并。

## 五、修复

输出队列 2→16 深（吸收最坏反压深度），从根上消灭丢字。位流重建中，预期全量 0 丢失 + SHA 一致。

## 五B、修复验证（2026-09-21 晚，build9w WNS=+1.082ns）

- 差分链：六段全部 +7570（7569 业务 +1 触发 ping），段内丢失全 0；溢出计数 pk_ovf/eb_ovf = **0/0**（修复前 7/9）；
- 看门狗/断链/错误计数全 0。

## 六、方法沉淀

- **差分链对账**：全路径每级一个帧计数器，一次运行后逐段差分——比抓波形定位快一个数量级；
- **独立时钟域必须独立 ILA**（B 域信号挂 A 域 ILA = 亚稳态值 + 时序违例）；
- mark_debug 单比特网注意综合拆网/改名（`dbg_echo_b_ovf` 误声明 16 位 → `get_nets` 精确匹配落空）；
- ILA 触发探针用 `NAME ==` 精确匹配（新增强计数器后 `*ch_up*` 会污染匹配）；
- 后台构建必须读全量作业输出（wrapper exit 0 ≠ Vivado 成功），并核对位流时间戳。
