若这档就 FAIL → 命令通道没通，见判读表。

## 第 5 步：J3 / J3′ 主轮（**严格模式**，W5 核心判据）

~~~powershell
python scripts\j3_random_read.py --nslots 256 --no-write-echo --json-out out\w5_j3_main.json
~~~

> **为什么必须加 `--no-write-echo`**：`SET_MODE(RND)` 生效后桥① **不再自动读**，写阶段就不该有任何回显。若仍看到「写阶段回显 N 帧」，说明模式没切过去（或命令没生效）——这正是要抓的。默认档（容忍回显）只作对照，**不作 W5 判据**。

**通过标准（三条全对）**：
1. **J3**：到达顺序 = 命令顺序（0 错位）；且**读出顺序 ≠ 写入顺序**（逆序对数远大于 0）；
2. **J3′**：收帧 256 / 期望 256，**缺 0 · 多 0 · 字节差异 0**；
3. **计数**：`u_wr_frame` 增量 = 256、`u_rd_frame` 增量 = 256（每槽恰好读一次）。

## 第 6 步：负向轮 A（漏发必须报出来）

~~~powershell
python scripts\j3_random_read.py --nslots 256 --neg-a --no-write-echo --json-out out\w5_j3_nega.json
~~~

**通过标准**：脚本报**恰好缺 1 帧**（并指出缺哪个 seq），`u_rd_frame` 增量 = 255。
**意义**：证明「全读回」判据**不是恒真**——少读一个槽时它真的会报。

## 第 7 步：负向轮 B（重发同槽 = 破坏性读语义）

~~~powershell
python scripts\j3_random_read.py --nslots 256 --neg-b --no-write-echo --json-out out\w5_j3_negb.json
~~~

**通过标准**：命令数 = N+1、实取 = N、集合仍相等（缺 0 / 多 0）；第二次读同一槽**观测到「空」**（桥① 读完即退休 → 定长空应答，**这是设计语义，不是丢包**）。
> ⚠️ **不要**用「同槽连读两次内容一致」当通过标准——本 RTL 是**一次性取走**语义（实施单 §六.3 已钉死）。

## 第 8 步：ILA 对账（J5 可观测性 + 非法读计数）

~~~powershell
vivado -mode batch -source scripts\ila_snap.tcl -notrace
~~~

快照落 `out\j4_snap_<时间戳>\ila0..3.csv`（脚本名沿用 W4）。**判读**：

| 探针（ila3, ui 域） | 期望 |
|---|---|
| `dbg_mem_ill`（非法读计数） | **主轮 0** · 负向 A 0 · **负向 B +1** |
| `dbg_mem_nofrm`（空读计数） | 与 `dbg_mem_ill` 同源佐证，负向 B 递增 |
| `dbg_mem_stall`（写停顿） | 主轮 0（写满 256 槽恰好停住）；若持续增长 = 槽复用纪律被触发 |
| `dbg_mem_wslot / dbg_mem_rslot` | 写槽顺序推进、**读槽随机跳变**（J5「读地址可控且可观测」的直接证据） |
| `dbg_mem_wbeats / dbg_mem_rbeats` | 读写突发数（J5「突发计数」） |

**ILA1（eth 域）另有** `dbg_cmd_rx`（收命令数）、`dbg_cmd_err`（错帧数）、`dbg_cmd_respbsy`（响应占用）；**ILA0（user 域）**有 `dbg_cmd_mode`、`dbg_cmd_slot`、`dbg_cmd_exec`、`dbg_cmd_trig`。

## 失败判读表（按现象查）

| 现象 | 首查 | 处置 |
|---|---|---|
| 第 4 步就 FAIL：`GET_WATERMARK` 无应答 | 命令是否发到**广播 IP** `192.168.1.255:1235`（不是板 IP）；PC 防火墙是否放行 UDP 1235；脚本两个本地口 1235/1236 是否被占（`udp_verify` 之类占 1234 也要关） | 关占用进程 → 重跑；仍不应答看 ILA1 `dbg_cmd_rx` 是否增长（增长=收到了但没执行 → 看 `dbg_cmd_err`） |
| `SET_MODE` 有应答但**写阶段仍回显** | 桥① 是否真进 RND（ILA0 `dbg_cmd_mode` 应为 1） | 模式位没进桥 → 报我 |
| `READ_SLOT` 有应答但**收不到数据帧** | `dbg_cmd_trig` 是否随命令增长；桥① `rd_frame` 是否增长；`dbg_mem_rslot` 是否跟着命令跳 | trig 不增 → 命令没执行；rd_frm 不增 → 桥没读（槽号越界？看 `dbg_mem_ill`） |
| 主轮**缺帧** | `u_wr_frame` 增量是否也少了（写侧就丢） | 写侧少 → 泵A 忙丢（降速 `--pace-us 3000`）；写侧对但读侧少 → 读侧问题，报我 |
| 主轮**字节差异** | 是否只有个别帧坏 | 单帧坏 = 链路/内存偶发，重跑；成片坏 = 停止并报我 |
| 负向 B **没报空读** | ILA `dbg_mem_ill` 是否 +1 | 没 +1 = 退休语义没生效 → 报我 |
| 板子**冻结**（ping 全丢） | — | 重烧位流即恢复（`program_loop.tcl` 再跑一次），保存日志发我，**勿反复重试** |
