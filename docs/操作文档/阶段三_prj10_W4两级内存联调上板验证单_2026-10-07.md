# 阶段三 · prj10 W4 两级内存联调 上板验证单（2026-10-07 · J4 判据）

> **一句话**：烧一块位流，把"去程 + 回程都过一遍 DDR4"的两级内存全环路跑完六项判据。**全部通过 = W4 完成：数据面从『网口→内存→光→内存→网口』全环闭合，两级桥共享 MIG 无冲突。**
>
> 位流：`D:\FPGA\prj\project_10\prj_loop\out\aurora_mem_bridge.bit`（**2026-10-07 修复重建版**）
> 探针：`D:\FPGA\prj\project_10\prj_loop\scripts\probes.ltx`（4 个调试核：user / eth / user_b / ui 四域）
>
> **W4 相对 W3 场次3 改了什么**：W3 只在**插入侧**插了一级内存（泵A → 桥① → pack）；W4 把**回程也插一级**——解包输出 → **桥②（EGRESS 0x0020_0000 写 DDR → SEQ 读回）** → 泵B → 网口。两座桥经**自研 `axi_arb_2to1` 仲裁器**共享同一个 MIG（SmartConnect / AXI Interconnect 在 2023.1 均锁 IP Integrator，坑账本 #22）。仲裁器 B/R 响应路由已由 Lead 修复为**按 grant 路由**（原按 bid/rid[0] 路由，两桥常量 ID 相同会导致板上死锁——上板前审查拦截，未流入任何已烧位流）；位流于 2026-10-07 重建。

## 第 6 步：ILA 双桥计数对账（J4-5）

**操作**（四步跑完、板子还活着时做；冻结了先重烧再做）：


**预期现象**：打印各核 `SNAP_OK`，产物落在 `out\j4_snap_<时间戳>\ila0..3.csv`（ila_snap.tcl 由 Lead 同日创建，直接照抄命令即可）。

**判读表**（把 CSV 发回 AI 时也用这张表说话）：

| 观测（ila3 = ui_clk 域） | 通过时应为 |
|---|---|
| 桥① `mem_wm / mem_wr_frm / mem_rd_frm` | **三量相等**（wr_frm = rd_frm = wm），且**与第 5 步 PC 收到数（7022）一致**（wm 是累计提交帧数 · 16 位计数，槽区回绕不影响该口径） |
| 桥② `mem2_wm / mem2_wr_frm / mem2_rd_frm` | **同上，独立一套**（mem2 三量相等 = 7022） |
| `mem_bresp` / `mem_len_err` 类错误计数 | **= 0**（bresp_err、len_err、ill_rd、noframe 全 0） |
| `mem2` 侧错误计数 | **= 0**（同上） |
| `dbg_mem_u_wr` / `dbg_mem_u_drop`（ila0，user 域） | u_wr = 7022；**drop 可解释**（PC pacing 下应为 0；非 0 则说明桥用户侧拒收，单独上报） |
| `dbg_mem2_u_wr` / `dbg_mem2_u_drop` | 同上（mem2 一套） |

**一句话判据**：**两座桥各自"写帧 = 读帧 = 水位"、错误计数全 0、用户侧无不可解释丢弃**——这就是"两级内存全环路闭合"的板端证据。

**不符合时怎么办**：见判读表第六行（先指出哪一级断：mem 还是 mem2）。
