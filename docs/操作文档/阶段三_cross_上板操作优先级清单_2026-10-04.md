## 三、【② 高风险】DDR4 内存校准首次上板（15 分钟见结果）

### ⚠️ 先看这条（重要，我已提前查出）

我复核代码时发现：**这版校准位流的复位极性接反了**——板上复位键**不按**的时候，内存核反而一直处在复位状态，**校准根本不会启动**。表现就是 **T22 永远不亮**。

- **快速验证**：**按住板上复位键不放**，看 T22 是否亮起来（或脚本里"ui_clk 在跑"是否出现）。亮 = 就是这个问题，**不是内存条/引脚的问题**。
- **处置**：把现象发我 → **我出一版修正位流**（改一行 + 重新构建，约半小时）。修好后你补烧一次即可。
- **在此之前**：不要按"校准失败"去折腾速率档、引脚、重烧——那些不是原因。

### 你要做的

**第 1 步｜烧位流**

```powershell
cd D:\FPGA\prj\project_4
vivado -mode batch -source scripts\program_mig.tcl -notrace
```

看到 `PROGRAM_OK` + `调试核数量 = 1` + `ui_clk 在跑` 就算烧好了。

**第 2 步｜看两盏灯**

| 灯 | 亮 = 什么 |
|---|---|
| **T22** | 内存校准完成 |
| **T23** | 写进去的 256 拍数据读回来逐字节一致 |

**两盏都亮 = 这项过了** ✅ 拍照、记时间。

**第 3 步｜顺手抓波形**（用来算读写往返延迟，对内存桥设计有用）

1. Vivado → Hardware Manager → 找到调试核 **u_ila**
2. 触发条件：**probe_state（状态机当前步骤）等于 1**
3. 采样深度拉最大 → Run trigger
4. **File → Export → Export ILA Data** 存 CSV，放 `毕设\截图归档\`

### 结果对照

| 现象 | 含义 | 你做什么 |
|---|---|---|
| **T22 不亮，但按住复位键就亮** | **复位极性反了**（见上面"先看这条"）| 告诉我，我出版修正位流 |
| T22 不亮、按住复位键也不亮 | 校准真的没过 | 拍照 + 脚本输出发我；我按顺序出两版：先**降速档**，再**把突发缩到 64 拍以内** |
| T22 亮、T23 灭 | 校准成功但比对有错 | 把 ILA 里 **probe_err** 的数字发我 |
| 两盏都亮 | ✅ 过了 | 拍照 + CSV 发我 |

**别自己反复重烧**：烧录没错时重烧解决不了问题，拍照发我最快。
