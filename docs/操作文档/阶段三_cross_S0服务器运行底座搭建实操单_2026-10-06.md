# 阶段三 · S0 服务器运行底座搭建实操单（Windows + WSL2）

> **目标**：在服务器上搭出 **Windows 11 宿主 + WSL2 Ubuntu Linux 服务层**，使本地 LLM 服务**先于 FPGA 独立跑起来**，并通过 **S0-1…S0-7** 七条判据。
> **执行主体**：**由人在服务器上操作**（AI 不接触该主机）——本单给出可粘贴命令与判读表，执行结果回报后由 AI 归档。
> **依据**：[[规划_cross_AI-Infra系统设计报告_2026-10-06]] §3.0 / §8.2；[[AI-Infra系统设计/服务器操作系统与本地 LLM 推理层架构修订报告]]。
> **一句话**：**Windows 是宿主，WSL2 是 Linux 服务层**；GPU 由 Windows 驱动经 CUDA on WSL 提供，**WSL2 内不装 Linux 显示驱动**。

## 3. 逐步操作

### 步骤 1 · 确认 Windows 侧基线（S0-1 起）

```powershell
# 以管理员身份打开 PowerShell（Win+X → 终端(管理员)）
winver                                   # 记下版本与 Build，须 >= 22621
Get-CimInstance Win32_ComputerSystem | Select-Object Manufacturer, Model, TotalPhysicalMemory
Get-CimInstance Win32_Processor | Select-Object Name, NumberOfCores, NumberOfLogicalProcessors
nvidia-smi                               # Windows 侧应看到 RTX 4090 D / 驱动 566.14 / CUDA 12.7
Get-NetAdapter | Format-Table Name, InterfaceDescription, Status, LinkSpeed -AutoSize
```

> **S0-1（Windows 工作能力）**：本步骤不改变任何东西——它是**基线记录**。S0-1 的完整判据是「实验室 Windows-only 软件正常工作、无明显性能或设备访问冲突」，**须在后续步骤全部完成后回头复核**（尤其确认 WSL2 未抢占设备/内存影响原工作）。

---

### 步骤 2 · 安装 / 更新 WSL2

```powershell
wsl --version                            # 已有则看版本；报错/无输出说明未装
wsl --update                             # 更新到最新（含内核）
wsl --set-default-version 2              # 确保默认 WSL2
wsl --status                             # 看默认版本与内核
```

若完全未安装：

```powershell
wsl --install                            # Win11 一条命令装好 WSL2 + 默认发行版
# 装完需重启一次
```

> ⚠️ `wsl --install` 会自动启用「虚拟机平台」与「适用于 Linux 的 Windows 子系统」两个 Windows 功能；**若提示需要重启，就重启**，别跳过。

---

### 步骤 3 · 部署 Ubuntu 发行版

```powershell
wsl --list --online                      # 看可选发行版
wsl --install -d Ubuntu-24.04            # 推荐 LTS
# 首次进入会要求设置 Linux 用户名与密码（记牢，后续 sudo 要用）
wsl -l -v                                # 确认 STATE=Running、VERSION=2
```

**位置与容量**（服务器有 3.7TB SSD，建议别把发行版放 C 盘）：

```powershell
# 查看发行版安装位置（默认在 %LOCALAPPDATA%\Packages\...）
wsl --list -v
# 如需迁移到数据盘：导出 -> 注销 -> 导入到目标路径
wsl --export Ubuntu-24.04 D:\wsl\ubuntu-24.04.tar
wsl --unregister Ubuntu-24.04
wsl --import Ubuntu-24.04 D:\wsl\Ubuntu-24.04 D:\wsl\ubuntu-24.04.tar --version 2
```

> ⚠️ `--import` 后**默认用户会变回 root**；如需恢复普通用户，写入 `/etc/wsl.conf` 的 `[user]` 段（见步骤 4）。

---

### 步骤 4 · 启用 systemd

在 WSL 内（`wsl` 进入 Ubuntu 后）创建配置文件：

```bash
sudo tee /etc/wsl.conf > /dev/null <<'EOF'
[boot]
systemd=true

[user]
default=<你的 Linux 用户名>

[interop]
enabled=true
appendWindowsPath=true
EOF
```

回到 Windows 侧重启实例使配置生效：

```powershell
wsl --shutdown
wsl -d Ubuntu-24.04 -- systemctl is-system-running
```

> **期望输出**：`running`（或 `degraded`——通常是个别无关单元失败，可 `systemctl --failed` 查，不影响本项目）。
> ⚠️ **必须 `wsl --shutdown` 才生效**——`wsl.conf` 不是热加载的。

---

### 步骤 5 · 配置 mirrored networking

在 **Windows 侧**编辑 `%USERPROFILE%\.wslconfig`（不存在就新建）：

```ini
[wsl2]
networkingMode=mirrored
# 可选：限制 WSL 可占用的内存与 CPU，避免影响 Windows-only 工作
# memory=64GB
# processors=32

# 可选：允许从宿主通过 localhost 访问 WSL 服务
[experimental]
hostAddressLoopback=true
```

```powershell
wsl --shutdown
wsl -d Ubuntu-24.04 -- ip addr          # 应能看到与宿主一致的网卡（镜像）
```

> ⚠️ **mirrored ≠ 网络已通**：该模式只是让 WSL 参与宿主网络，**入站访问仍需配防火墙**（步骤 8）。
> ⚠️ 该模式要求 **Windows 11 22H2（Build 22621）及以上**——本机 22621，**正好在边界上**，若行为异常先复核 Build。

---

### 步骤 6 · GPU 可见性验证（**S0-2**）

```bash
# WSL 内
nvidia-smi
```

**判据 S0-2**：`nvidia-smi` 正确识别 **RTX 4090 D**，显存显示 **24564 MiB** 左右。

> ❌ **绝对不要**在 WSL2 内安装 Linux NVIDIA 显示驱动（如 `apt install nvidia-driver-XXX`）——GPU 由 **Windows 宿主驱动**经 CUDA on WSL 提供，重复安装会破坏通路。**要编译 CUDA 程序时才装 Linux CUDA Toolkit**（步骤 7）。

---

### 步骤 7 · CUDA 可用性验证（**S0-3**）

最省事的路径：**不单独折腾 CUDA 样例**，直接进步骤 10 装 Ollama，让它加载模型并出 token——**那本身就是最强的 CUDA 可用性证明**。

仅在需要**编译** CUDA 程序时，才在 WSL 内安装 Linux CUDA Toolkit（版本与本机 Windows CUDA 12.7 匹配，按 NVIDIA 官方 CUDA on WSL 指南操作）。

**判据 S0-3**：一个 **Linux CUDA 应用能正确调用 GPU**。建议与 S0-6 合并验证。

---

### 步骤 8 · 防火墙与 LAN 可达（**S0-4**）

在 Windows 侧放行入站（示例端口 443，按实际改）：

```powershell
# 普通防火墙规则
New-NetFirewallRule -DisplayName "WSL LLM API" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 443

# mirrored 模式下 WSL 走 Hyper-V 防火墙，需一并放行
Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultInboundAction Allow
```

验证（从 **PC** 上发起，不是从服务器本机）：

```powershell
Test-NetConnection -ComputerName <服务器IP> -Port 443
```

**判据 S0-4**：PC / FPGA 所在实验室网络**能访问 WSL2 中的 nginx / LLM 服务**。

> ⚠️ **多网卡必做**：确认哪块网卡承载实验室网络，必要时调整路由优先级
> `Set-NetIPInterface -InterfaceAlias "<网卡名>" -InterfaceMetric 10`
> **禁止 Wi-Fi 作为 LLM API 的长期生产路径**。

---

### 步骤 9 · 自动拉起 + 真实重启验证（**S0-5**）

> ⚠️ **本步是全单最容易想当然的一步**：**systemd 只管「WSL 实例已启动之后」的 Linux 服务**；「Windows 启动 → 自动拉起 WSL 实例」**是宿主层职责**，必须单独做。

**候选方案（需实测选择，不预设哪个一定行）**：

```powershell
# 方案 A：任务计划，计算机启动时触发，无论用户是否登录
$action    = New-ScheduledTaskAction -Execute "wsl.exe" -Argument "-d Ubuntu-24.04 -u root -e /bin/true"
$triggerA  = New-ScheduledTaskTrigger -AtStartup
$principal = New-ScheduledTaskPrincipal -UserId "SYSTEM" -RunLevel Highest
Register-ScheduledTask -TaskName "WSL-LLM-Autostart" -Action $action -Trigger $triggerA -Principal $principal

# 方案 B：用户登录时触发（更简单，但要求有人登录）
$triggerB = New-ScheduledTaskTrigger -AtLogOn
Register-ScheduledTask -TaskName "WSL-LLM-Autostart-Logon" -Action $action -Trigger $triggerB
```

**验证必须是真的重启**：

```powershell
Restart-Computer
# 重启后不登录（方案 A）或登录后（方案 B），等待 1-2 分钟，然后：
wsl -d Ubuntu-24.04 -- systemctl is-active ollama nginx
wsl -d Ubuntu-24.04 -- curl -s -o /dev/null -w "%{http_code}" http://localhost/health
```

**判据 S0-5**：**真实重启 Windows 后**，WSL2 服务自动恢复，**Ollama 与 nginx 均达 Ready**。

> ⚠️ **不能用手动 `wsl` 命令替代重启测试**——那验证的是「手动启动能起来」，不是本题要的「自动恢复」。
> ⚠️ 另需留意 WSL 的**空闲回收**：若实例被回收，systemd 服务随之停止。必要时在 `.wslconfig` 调 `vmIdleTimeout`，**以实测为准**。

---

### 步骤 10 · Ollama + nginx 最小闭环（**S0-6**，S1 的起点）

**装 Ollama（WSL 内）**：

```bash
curl -fsSL https://ollama.com/install.sh | sh
sudo systemctl enable --now ollama
systemctl status ollama --no-pager
```

**拉模型（27B 级 Q4，约 16GB，下载耗时长——建议先启动后台拉取）**：

```bash
ollama pull <27B-Q4-模型名>        # 具体型号按 S1 选型实测确定
ollama run <模型名> "你好"          # 冒烟：能出字说明推理通路与 GPU 均正常
```

**装 nginx 并配最小反代 + SSE 透传**：

```bash
sudo apt-get update && sudo apt-get install -y nginx
sudo tee /etc/nginx/sites-available/llm > /dev/null <<'EOF'
upstream llm {
    server 127.0.0.1:11434;
    keepalive 16;
}
server {
    listen 443 ssl;
    # ssl_certificate ...; ssl_certificate_key ...;   # 证书按实际配置
    location /human/ {
        proxy_pass http://llm/;
        proxy_http_version 1.1;
        proxy_buffering off;            # 流式必须关
        proxy_read_timeout 600s;
    }
}
EOF
sudo ln -sf /etc/nginx/sites-available/llm /etc/nginx/sites-enabled/llm
sudo nginx -t && sudo systemctl enable --now nginx
```

**判据 S0-6**：**统一 API 完成一次完整流式推理**（客户端 → nginx → LLM → SSE → 客户端），即客户端能看到**逐块吐出**，而不是等全部生成完一次性返回。

---

### 步骤 11 · GE2 接入（**S0-7**，与 F3 联动）

**前置未解**：先确认**哪个物理网口做 GE2**（当前 X722 断开、活跃为 Wi-Fi）。

**判据 S0-7**：服务器经 GE2 接入后，至少完成 `Server ↔ GE2 ↔ FPGA` 的**基础网络连通与数据判据**（ping + udp_verify，口径见设计报告 §3.3.9 端点接入规范）。

> ⚠️ 本步与 FPGA 侧 F3 绑定；**在网口未定案前不得动 GE2**（设计报告风险 #19）。

## 5. 坑位速查（按踩中概率排序）

| # | 坑 | 现象 | 处置 |
|---|---|---|---|
| 1 | **在 WSL2 内装 Linux NVIDIA 驱动** | `nvidia-smi` 失效 / CUDA 不可用 | **卸掉**，GPU 只由 Windows 宿主驱动提供 |
| 2 | **改了 `.wslconfig` / `wsl.conf` 没重启实例** | 配置「没生效」 | `wsl --shutdown` 后再进 |
| 3 | **以为 mirrored 开了网络就通** | PC 访问不到服务 | 补防火墙规则（普通 + Hyper-V 防火墙两条） |
| 4 | **多网卡抢路由** | FPGA 通路/内网互相干扰 | 明确 `InterfaceMetric`；Wi-Fi 不做生产路径 |
| 5 | **「Windows 启动 = Linux 服务已启动」** | 重启后服务不在 | 宿主级自动拉起 + **真实重启验证**（步骤 9） |
| 6 | **发行版装在 C 盘** | C 盘被 vhdx 吃满 | 用导出/导入迁到数据盘 |
| 7 | **虚拟化未开** | `wsl --install` 报错 | BIOS 打开 VT-x / VT-d（**归人**） |
| 8 | **WSL 内存无上限** | 影响 Windows-only 工作 | `.wslconfig` 设 `memory=` |
