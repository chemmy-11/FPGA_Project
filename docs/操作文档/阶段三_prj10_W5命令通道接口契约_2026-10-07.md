## 一、设计依据（侦察结论，2026-10-07）

| 事实 | 出处 | 推论 |

## 二、PC ↔ FPGA 协议 v1

### 2.1 命令帧（PC → 板）

UDP；**目的 IP = 192.168.1.255**（广播，故被官方栈丢弃）；**目的端口 = 1235**；目的 MAC = `ff:ff:ff:ff:ff:ff`（广播 IP 由内核自动填）。

**载荷 ≥ 8 字节**：

| 偏移 | 内容 |
|---|---|
| 0..3 | magic `"P10C"` = `50 31 30 43` |
| 4 | opcode |
| 5 | arg0 |
| 6..7 | arg1（小端 16bit） |
| 8..N | 保留（可为空） |

**opcode 表**：

| opcode | 名称 | 语义 |
|---|---|---|
| `0x01` | SET_MODE | `arg0` = 0(SEQ) / 1(RND)。仅切模式，不触发读 |
| `0x02` | READ_SLOT | `arg0` = 槽号；语义 = **置 RND 模式 + 设读槽号 + 触发一次读**（user 域 `rd_req` 单拍） |
| `0x03` | GET_WATERMARK | 回读 `u_wr_frame` / `u_rd_frame` |
| `0x04` | GET_SLOT_MAP | 回读映射规则号 + 写水位 + 当前写槽指针 |

### 2.2 应答帧（板 → PC）

UDP；源 IP = 192.168.1.10；源端口 = 1235；**目的 = 命令帧的源 MAC / 源 IP / 源端口**（从命令帧头部捕获，无需 PC 侧配置）。
**载荷固定 12 字节**：

| 偏移 | 内容 |
|---|---|
| 0..3 | magic `"P10R"` = `50 31 30 52` |
| 4 | opcode（回显） |
| 5 | status：0=OK · 1=参数非法 · 2=忙/丢弃 |
| 6..7 | value16（小端） |
| 8..9 | value16b（小端） |
| 10..11 | value16c（小端，保留/计数） |

**各命令的返回**：

| opcode | value16 | value16b | value16c |
|---|---|---|---|
| SET_MODE | 0 | 0 | 0 |
| READ_SLOT | 已 clamp 的槽号 | 触发序号（自增，PC 可对账） | 0 |
| GET_WATERMARK | `u_wr_frame`（累计受理帧数） | `u_rd_frame`（累计读出帧数） | `u_buf_drop` |
| GET_SLOT_MAP | `u_wr_frame` | 当前写槽指针 = `u_wr_frame mod 256` | **规则号 = 1**（表示「写槽 = 帧计数 mod 256」） |

> 说明：水印与计数取 **user 域**（`frame_mem_if.ro_u_*`），避免再引入 ui→eth 的第二跳 CDC；ui 域细节计数（`ill_rd`/`wr_stall`/突发数）由 ILA 提供（J5）。

### 2.3 数据帧（被读出的帧）如何回 PC

READ_SLOT 触发桥① 从指定槽读出整帧 → pack → Aurora → B 回显 → unpack → 桥②(SEQ) → 泵B → PC。**PC 收到的是一帧普通 UDP 回显数据**（载荷 = 当初写进去的内容），与应答帧（端口 1235 + magic `P10R`）可按 magic 区分。

## 三、RTL 模块契约：`cmd_channel.v`

位置：`D:\FPGA\prj\project_10\prj_loop\rtl_patch\cmd_channel.v`（prj10 派生区，与 `udp_tx.v` 补丁同级；**官方文件零改动**）。

~~~verilog
module cmd_channel (
    // ---------- eth_rxc 域（gmii_rx_clk，125MHz） ----------
    input  wire        clk_eth,
    input  wire        rst_eth_n,      // sys_rst_n（低有效）
    input  wire        gmii_rx_dv,     // RX 总线并联 tap
    input  wire [7:0]  gmii_rxd,
    output reg         resp_tx_en,     // 响应帧字节流（注入顶层 mux）
    output reg  [7:0]  resp_txd,
    output reg         resp_busy,      // 1 = 本模块占用 TX；顶层据此切换 mux
    output reg  [15:0] cmd_rx_cnt,     // 收到合法命令帧数
    output reg  [15:0] cmd_err_cnt,    // 校验失败/截断帧数

    // ---------- user_clk 域（151.5MHz） ----------
    input  wire        clk_user,
    input  wire        rst_user_n,     // ~aurora_rst（高有效复位的取反）
    input  wire [15:0] u_wr_frame,     // frame_mem_if.ro_u_wr_frame
    input  wire [15:0] u_rd_frame,     // frame_mem_if.ro_u_rd_frame
    input  wire [15:0] u_buf_drop,     // frame_mem_if.ro_u_buf_drop
    output reg         cfg_mode,       // 0=SEQ 1=RND   → u_mem.cfg_mode
    output reg  [7:0]  cfg_rd_slot,    //               → u_mem.cfg_rd_slot
    output reg         rd_req_pulse,   // 单拍：触发一次读（RND）
    output reg  [15:0] cmd_exec_cnt,   // 执行完成的命令数
    output reg  [15:0] rd_trig_cnt     // 触发读次数（= READ_SLOT 成功数）
);
~~~

**CDC**：eth ↔ user 之间用 **4 相握手邮箱**（req/ack 电平握手 + 数据保持，AGENTS.md §5.1 合规形式；`frame_mem_if` 的 CDC 清单里已声明本工程尚未使用该形式，W5 首次使用）。**不得**用多比特直采。

**时序要求**：
- `rd_req_pulse` 必须是 **user_clk 域单拍**；
- `cfg_mode`/`cfg_rd_slot` 必须在 `rd_req_pulse` **之前至少 1 个 user_clk** 稳定；
- 连续两条命令之间 PC 侧保证 ≥1ms 间隔（脚本内做），RTL 不需处理背靠背。

**顶层集成（由 Lead 做，Teammate 不用碰）**：
1. 例化 `cmd_channel`；
2. `u_mem.cfg_mode/cfg_rd_slot` 改接命令通道输出（原来硬接 `1'b0/8'h00`）；
3. `mem_rd_req` 生成改为：SEQ→原自动逻辑；RND→`rd_req_pulse`；
4. **应答注入点 = RGMII TX 末级**（`gmii_to_rgmii` 输入前的 mux，eth_rxc 域）：
   `rgmii_txd_o/rgmii_tx_en_o = cmd_takeover ? resp_txd/resp_tx_en : 泵B输出`，
   其中 `cmd_takeover` 仅在 TX 末级空闲 ≥64 拍时置位、保持到整帧发完。
   > ⚠️ **2026-10-07 集成期订正（重要）**：初版把注入点放在**泵A 输入**（`stack_txd/stack_tx_en`），实测**行不通**——泵A→桥① 是**内存写侧**，RND 模式下桥① 不再自动读，应答帧会被写进槽里、要等读序轮到它才出得来 → **ACK 事实上到不了 PC**（`GET_WATERMARK` 自锁，J3 无法驱动）。故应答必须**绕开两级内存桥**，从网口末级直出。该点同时满足：零 CDC（`gmii_to_rgmii` 内 `assign gmii_tx_clk = gmii_rx_clk`）、满足 IFG、不占槽、不抬 `wr_stall`、不改动任何官方模块。
5. ILA 探针：eth 域加 `cmd_rx_cnt/cmd_err_cnt/resp_busy`；user 域加 `cfg_mode/cfg_rd_slot/cmd_exec_cnt/rd_trig_cnt`；
6. `create_project.tcl` 加 `rtl_patch/cmd_channel.v`。

## 四、J3 / J3′ 测试流程（PC 脚本依据）

### 4.1 主轮（J3 + J3′ 共用前置）

| 步 | 动作 | 通过标准 |
|---|---|---|
| 0 | `SET_MODE(RND)`；`GET_WATERMARK` 取基线 | status=0；记 `wr0/rd0` |
| 1 | 连发 **N=256 帧** 数据（每帧载荷 = `seq(4B) + 帧内递增模式`，发往 **1234** 端口，正常单播） | 发完后 `GET_WATERMARK`：`u_wr_frame − wr0 = 256` |
| 2 | 生成 **256 槽的随机置换**；逐条 `READ_SLOT(slot)`，每发一条等对应数据帧回来 | 数据帧按**命令顺序**到达（J3：读出顺序 ≠ 写入顺序） |
| 3 | 校验每帧内容 = 该槽应含的 `seq` 帧，逐字节 | **0 串帧**（J3）；**集合相等、0 缺帧/0 多余**（J3′） |

**槽↔帧映射**（写侧规则，可本地复算，**含基线偏移**）：写侧规则是「槽 = `u_wr_frame` mod 256」，故本轮第 k 帧（k 从 0 起）→ 槽 `(wr0 + k) mod 256`，其中 `wr0` = 步骤 0 的 `u_wr_frame` 基线。
> ⚠️ **2026-10-07 订正**：初版写「第 k 帧 → 槽 k mod 256」**漏了基线**。N=256 时 `wr0` 恰为 256 的倍数才等价；**N<256 时真板会把帧写进 `wr0..wr0+N−1` 而非 `0..N−1`**（脚本按基线推导，实测修正前 N=16 必挂）。

> **写阶段回显口径**：`SET_MODE(RND)` 生效后桥① **不再自动读**，写阶段**不应有任何回显**（严格模式 `--no-write-echo` 即断言这一点）。若观察到「写阶段回显 N 帧」，说明模式未真正切换 —— **不是正常现象**，须当失败处理（旧位流/SEQ 模式下才会出现，W4 的 `udp_verify` 即此现象）。

### 4.2 负向轮（防判据恒真）

| 轮 | 构造 | 必须观测到 |
|---|---|---|
| 负向 A（**漏发**） | 置换里**故意去掉 1 个槽** | 脚本报 **恰好缺 1 帧**；`u_rd_frame` 增量 = 255 |
| 负向 B（**重发**） | 置换里**故意重复 1 个槽** | 第二次该槽返回**空应答**（桥① 无数据帧输出 → PC 侧超时/空）+ ILA `ill_rd_cnt` **+1**；判读口径 = 「命令数 = N+1、实取帧 = N、集合仍相等」（**不是**「两次内容一致」，见实施单 §六.3 RND 破坏性语义） |

### 4.3 计数对账（与 ILA 快照配合）

| 计数 | 出处 | 期望 |
|---|---|---|
| `u_wr_frame` | GET_WATERMARK | 主轮 +256 |
| `u_rd_frame` | GET_WATERMARK | 主轮 +256（每槽恰好读一次） |
| `ill_rd_cnt` | ILA（ui 域 `dbg_mem_ill`… 见 W4 探针名） | 主轮 **0**；负向 A 0；负向 B **+1** |
| `wr_stall_cnt` | ILA | 主轮 0（写满 256 槽恰好停住，不需再写） |
| `rd_slot/wr_slot` | ILA（`dbg_mem_rslot/wslot`） | 随机跳变（J5 可观测性） |

## 附录 v1.1（2026-10-07，Lead 发布，立即生效）

**背景**：响应注入 mux（`cmd_takeover ? resp : stack`）必须**避免在回显帧中途切换**——否则会切断一帧在途的栈 TX。

**新增端口**（`cmd_channel.v`，eth_rxc 域）：

~~~verilog
input  wire  tx_idle,   // 顶层给出：stack_tx_en 已连续 ≥64 拍为空
~~~

**发送前置条件**：`resp_busy` 只能在 **`tx_idle == 1` 且本模块有完整应答帧待发** 时拉高；拉高后**保持到整帧发完**（`resp_tx_en` 末拍之后）再释放，中途不得因 `tx_idle` 变化中断。

**防御性要求**：上一条命令应答未发完又来新命令时（PC 侧 ≥1ms 间隔，正常不会发生），**丢弃新命令并让 `cmd_err_cnt` 递增**，不得覆盖正在发送的应答。

**顶层实现（Lead 负责）**：

~~~verilog
reg [6:0] stack_idle_cnt;   // stack_tx_en=0 时递增, ≥64 置 cmd_tx_idle
reg       cmd_takeover;     // resp_busy 上升且 tx_idle=1 时置位, resp_busy 落下时清零
wire [7:0] pump_a_txd   = cmd_takeover ? cmd_resp_txd   : stack_txd;
wire       pump_a_tx_en = cmd_takeover ? cmd_resp_tx_en : stack_tx_en;
~~~

**TB 补充要求**：驱动 `tx_idle`——先给 0 断言「永不 resp_busy」，再给 1 观察发送；并加一条负向断言。
