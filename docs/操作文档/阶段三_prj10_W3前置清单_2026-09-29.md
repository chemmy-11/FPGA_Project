## 二、两项设计输入（决定架构取向，不是阻断）

### 2.1 约束是**端口并发与延迟**，不是 DDR 带宽

| 量 | 值 | 来源 |
|---|---|---|
| 桥的硬上限 | **每方向 300 MB/s**（`W_FILL`/`R_UNPACK` 各 1 字节/ui_clk @300 MHz） | `axi4_master_bridge.v:197-205 / :400-410` |
| 设计点服务时间（1466 B） | 写 **5.14 µs**（替身）/ **5.80 µs**（Lw=200）；读同量级 | 实测计数回归模型 `T_w=L+3·ceil(L/64)+4+Lw` |
| 单桥稳态吞吐 | **194.7k fps（替身）/ 170.1k fps（含 Lw/Lr）** = 线速 81.27k fps 的 **2.39× / 2.09×** | 同上 |
| **两级桥串行** | **10.21 µs（替身）/ 11.68 µs（含延迟）** → 裕量仅 **1.20× / 1.05×** | 同上 |
| DDR 侧需求 | 桥按 3.1 µs/帧：写 0.515 + 读 0.521 GB/s；按帧周期摊平各 **0.130 GB/s** | `W_FILL/R_UNPACK` 字节率换算 |
| MIG 持续上界 | **≈10.6–16.3 GB/s**（DDR4-2400×64bit 理论 19.21 GB/s 打 55–85% 折损） | 算术 |
| **占用率** | 桥只用 **6–10%**；DDR 每帧只忙 **46/3690 拍 = 1.25%** | 同上 |
| 单帧延迟 | DDR 随机访问延迟暴露为**每帧各一次**（写等 `BVALID`、读等首拍）；阈值：不流水时 **Lw+Lr>636 拍即破坏节拍** | `axi4_master_bridge.v:175/277`（写唯一回 IDLE 路径）、`:317/420`（读同） |

→ **结论**：W3 的正确目标不是"DDR 够不够快"，而是"**两级桥的串行服务时间 + 延迟暴露会不会顶穿 12.30 µs 帧周期**"。
当前推算 1.05× 裕量 —— **能跑，但薄**。若要加固，方向是**多 outstanding / 读写分端口流水**，不是加带宽。

### 2.2 口径订正（W2 记录里必须按这个读）

- `3.11 µs/帧`、`3.07 µs/帧` = **混合帧长均值**，**不可作设计点引用**；
- 设计点（1466 B）= **5.14 / 5.80 µs**；两级桥 = **10.2 / 11.7 µs 串行**；
- 原"端到端 +6 µs"应改为"**+10~12 µs**"。
