## 0. 一句话原理与架构

```
PC --RJ45(GE1)--> [官方 UDP 栈，原样] --回显--> PC      （L2 验证与 project_6 完全一致）
                       |
        TAP: PC 原始帧（eth_rxc 域 125M#1）
                       v
        帧泵（自研：双钟 FIFO + 帧握手，跨到 userclk2 域 125M#2）
                       v
        PCS/PMA TX（1000BASE-X，GT X1Y8=光口D）--内环[config bit0=1]--> PCS RX
                       v
        udp_rx 第二例（官方模块，仅解析不回发）→ rec_pkt_done → T22 粘滞灯 + ILA
```

- **自终止性**（为什么不会无限回声）：内环回帧 = UDP 回显（目的 MAC = PC ≠ 板卡 MAC），udp_rx 第二跳按 MAC 过滤直接丢弃；udp_rx2 本身不回发。
- **为什么要帧泵**：栈（eth_rxc，PHY 晶振）与 PCS（userclk2，GT 参考钟）是两个独立 125M 源，GMII 直连必采样违例——帧门控搬运保帧完整。

## 3. ILA 抓帧比对（进阶，帧级证据）

1. HW Manager 中该位流已带 mark_debug 探针（综合时已标注）→ **Set Up Debug**（同 Aurora 流程）自动列出：
   - `dbg_rx2_data[7:0] / dbg_rx2_en / dbg_rx2_done / dbg_rx2_num[15:0]`——内环回帧的解析流
   - `dbg_status[15:0]`（PCS 状态字）、`dbg_mmcm`（PCS 时钟锁定）
   - `dbg_pump_wr / dbg_pump_rd / dbg_pump_drop[15:0]`——帧泵收/发/丢帧计数
2. 触发条件：`dbg_rx2_done` ↑（上升沿）；
3. 判读：`dbg_rx2_num` = UDP 载荷字节数（与发送文本等长）；`dbg_rx2_data` 流中能看到帧结构——开头 `8'h55 ×7 + 8'hD5`（前导码）→ 目的 MAC = PC 的 MAC（**注意：回环的是 PC 原始帧，目的 MAC 是 PC 不是板卡**）→ … → 载荷 ASCII = 发送文本；
4. 三个计数器应满足 `dbg_pump_wr = dbg_pump_rd = 发送帧数`，`dbg_pump_drop = 0`（人工节奏下）。

### ILA 计数器四分定位

| dbg_pump_wr | dbg_pump_rd | 结论 | 处置 |
|---|---|---|---|
| 0 | 0 | TAP 无数据进泵 | 查 GE1 链路/PC 是否真发了（先确认步 3 有回显） |
