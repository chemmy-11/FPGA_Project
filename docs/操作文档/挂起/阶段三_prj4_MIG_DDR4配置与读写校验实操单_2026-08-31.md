# 阶段三 · MIG/DDR4 配置与读写校验（配置定版卡）

> ⏸️ **状态（2026-09-10 归档）：挂起，待 DDR 解冻**——位流已产出（布线/时序全绿）、定版卡完备，仅剩上板收尾。恢复入口见 [[操作文档/挂起/README]]。
>
> ⚠️ 下方"当前态……批处理构建中 🔄"是 2026-08-31 的快照，实际已产出位流；以本横幅为准。

> 🎯 **定位**：5 阶段路线第 3 步。MIG = DDR4 控制器 + **AXI4 从接口**——配它的过程就是 AXI4 总线族最好的活教材（AXI4-Lite 你在 M1 摸过，AXI4-Stream 在 Aurora 例程见过，本步补齐 AXI4）。**AXI 理论与 MIG 实操合并推进，不再单独啃协议**。
> **为什么先做这个**：缓存转发模式需要大容量缓冲，板载 DDR4 是唯一选择；MIG 独立验证通过后，阶段四的 DMA 才有对接对象——每步只引入一个新变量。
>
> 📌 **实施记录（2026-08-31，全脚本批处理，用户委托执行）**——三个方法论级发现：
> 1. **MIG 的引脚分配根本不需要 GUI Pin Selection**：实测生成物证明，IP 自身 xdc 只含 IOSTANDARD + 时序，**不含任何 PACKAGE_PIN/站位 LOC**；引脚是**用户侧对 IP 顶层端口的普通约束**（`c0_ddr4_*` 端口名与官方 KU_IO.xdc 完全同源）。Pin Selection GUI 只是辅助生成这些约束的帮手。
> 2. **MIG 例程（MCS 流量发生器）可跳过**：自研最小 AXI4 主机 `mig_verify_top.v`（256-beat 写突发 → 读回 → 逐拍比对 → 误码计数，~200 行）完成验证——这本身就是"AXI4 学习最小集"的满分实践。
> 3. **坑**：MIG 生成 xdc 给 `c0_sys_clk` 默认 IOSTANDARD=DIFF_SSTL12，与本球实证可用的 DIFF_HSTL_I_12 冲突 → 用户约束后处理覆盖。
> **当前态**：`ddr4_0` IP（MT40A512M16HA-083E / 64-bit / AXI4-512 / 2400 档）脚本化配置 + 生成 ✅；`mig_verify_top.v` + `mig_verify_pins.xdc`（107 脚 + sys_clk 覆盖 + reset/LED）入工程 ✅；批处理构建中 🔄。
>
> **分工**：GUI 点击/上板归你；异常发我判读。预计：确认项 10min + MIG 配置（Pin Selection 是体力活）2~3h + 编译 30min + 上板 20min。

## 0. 第一性原理推导链

| # | 需求 | 推导 | 落到的参数 |
|---|------|------|-----------|
| 1 | 缓存转发需要大缓冲 | 板载 DDR4（GB 级）唯一选择 → FPGA 需要 DDR4 控制器 | **MIG IP** |
| 2 | 10G 线速有效 9.7Gbps ≈ 1.2GB/s | DDR4-2400 × 64-bit 理论 19.2GB/s ≫ 1.2GB/s | 带宽充裕，缓存转发无瓶颈 |
| 3 | 数据面 CPU 不碰数据 | MIG 以 **AXI4 从设备**身份挂在数据面，主人是 DMA（阶段四） | Controller Interface = AXI4 |
| 4 | DDR4 上电必须先校准 | ZQ 校准 + 读眼训练完成前访问 = 挂死 | **第一判据 = init_calib_complete** |
| 5 | 不写一行代码就能验 MIG | MIG 例程自带流量发生器 + 数据比对器（与 Aurora frame_gen/check 同思想） | 判据 = 例程比对错误恒 0 |

## 1. 板卡事实（官方 KU_IO.xdc 实测，2026-08-31 提取，107 信号）

| 信号组 | 数量 | 说明 |
|--------|------|------|
| `c0_ddr4_dq` | **64**（0~63） | **数据位宽 64-bit = 4 片 x16 芯片** |
| `c0_ddr4_dqs_t` / `dm_dbi_n` | 8 对 / 8 | 每字节一根 DQS 差分对 + 一个 DM |
| `c0_ddr4_adr` | **17**（0~16） | adr[16] 存在 = 16Gb 级密度特征 |
| `c0_ddr4_ba` / `bg` | 2 / 1 | bank 组寻址 |
| `ck_t/ck_c`、`cs_n`、`cke`、`odt`、`act_n`、`reset_n` | 各 1 | **单 Rank**（cs_n 只有一根） |

## 2. 开工前确认项 ✅ 已全部确认（2026-08-31：芯片丝印 + 手册拓扑图 + 原理图时钟/电源页）

| 项 | 确认值 |
|----|--------|
| 芯片 | **4 片 MT40A512M16**（DDR4，每片 8Gbit x16）——⚠️ MT40A 前缀=**DDR4**，论文里别写成 DDR3 |
| 总容量 | **32Gbit = 4GB**（64-bit 总线）|
| IO 速率 | **最高 DDR4-2400** → 2400M×64 = **153.6 Gbps = 19.2 GB/s** 理论带宽（10G 线速有效 1.2GB/s 的 **16 倍余量**）|
| 内存时钟驱动 | **FPGA 输出**：`DDR4_CLK_P/N` → 颗粒 **K7=CK_T / K8=CK_C**（FPGA 侧球 = AE16/AE15，即官方表 `c0_ddr4_ck_t/c`）；`DDR4_CKE` → 颗粒 K2 |
| 系统参考时钟 | **无独立内存时钟振荡器**——手册拓扑图：100MHz 差分时钟（=板载 AK17/AK16 晶振）进 BANK 45，MIG System Clock 直接共用 |
| 电源方案 | **DDR_1V2** → VDD/VDDQ；**DDR_2V5** → VPP（2.5V）；**TPS51200DRGR**（U3）生成 **DDRVTT** 端接电压（REFIN 取自 DDR_1V2）+ VTTREF |
| 信号 Bank | **BANK 44/45/46**（Pin Selection sanity check：DDR4 脚都应落在这三个 bank）|

## 3. MIG IP 配置定版表（IP Catalog → Memory Interface Generator → DDR4）

> ⚠️ 已无 TBD 项（§2 全部确认），照抄即可。GUI 页序以 2023.1 实际为准。

| 配置项 | 定版值 | 为什么 |
|--------|--------|--------|
| Memory Type | Components → **DDR4 SDRAM** | 板载贴片芯片非内存条 |
| Memory Part | **MT40A512M16 系列**（下拉按封装/速度变体选，如 MT40A512M16HA-083E） | 4×8Gb x16；丝印无速度后缀 → 时钟周期按板卡标称 2400 档设定，变体选与丝印封装一致的 |
| Data Width | **64** | §1 实测 4×x16 |
| Memory Voltage | 1.2V | DDR4 规格 |
| Clock Period /PHY ratio | **首选 DDR4-2400 档（tCK=833ps，板卡标称速率）**；init_calib 失败且引脚复核无误时降档重试（DDR4-1600 带宽仍 12.8GB/s ≫ 1.2GB/s 需求） | 板卡手册标称 2400；降档是合法保险，不丢判据 |
| Controller Interface | **AXI4**（非 UI/Native） | #3：DMA 的主人身份 |
| AXI Data Width | MIG 推荐值（64×ratio，通常 256/512） | 内部位宽打包 |
| AXI ID Width / Arbitration | 默认 | 单 DMA 主设备，无仲裁压力 |
| System Clock | **Differential**，100 MHz（10ns） | AK17/AK16 板载晶振（IBERT/Aurora 同源） |
| Reference Clock | No | 内部 PLL 即可 |
| Debug 选项 | 勾选 | 例程带 VIO/状态观测 |
| **Pin Selection 页** | **逐 signal 对照官方 KU_IO.xdc 填入（107 个）** | ⚠️ **本实验最大的体力活 + 唯一的正确性关口**：byte lane 顺序/DQS 配对必须与 PCB 一致，错一个 calib 必败。**照抄官方表，零自由发挥** |

## 4. 流程骨架（7 步）

1. 新工程 `D:\FPGA\project_4`，名 **mig_ddr4_cal**（part=`xcku060-ffva1156-2-i` 非 CIV）；
2. IP Catalog → **Memory Interface Generator (MIG)** → DDR4 → 按 §3 配置（Pin Selection 逐脚对照官方表）→ Generate；
3. **Open Example Design**（MIG 例程自带流量发生器 + 比对器，无需手写逻辑）；
4. **30 秒自检**：exdes 生成的 xdc 里抽查 5 个脚（`c0_ddr4_dq[0]`、`dqs_t[0]`、`adr[0]`、`dm_dbi_n[0]`、`reset_n`）与官方 KU_IO.xdc 一致；sys_clk 落在 AK17/AK16；
5. 综合 → 实现 → 位流；
6. 上板：**init_calib_complete 指示灯亮**（第一判据，上电后约几百 ms）→ 例程流量发生器自动跑 → 比对错误指示灯**不亮**；
7. ILA/VIO 截图归档 `D:\FPGA\mig_ddr4\docs\`。

## 6. 坑位速查

| 症状 | 先查什么 |
|------|---------|
| init_calib 不完成 | Pin Selection 与 PCB 不符（byte lane/DQS 配对）——照官方表逐脚复核；Memory Part 密度选错 |
| 例程比对错误非 0 | 速率档与 part 速度等级不匹配；先确认 calib 完成才看比对 |
| MIG 报引脚冲突/非法 | 手工填 Pin Selection 时 bank 归属错——用 MIG 的 DRC 提示逐个消 |
| 综合 DRC 报 IOSTANDARD | DDR4 引脚电平（SSTL12_DCI/POD12）由 MIG 生成 xdc 管理，别手工覆盖 |
| calib 完成但 AXI 访问挂死 | init_calib_complete 未同步进用户逻辑就发读写 |
| 例程被重生成覆盖 | 老坑：补丁永远做在新生成文件里 |

## 7. AXI4 学习最小集（配着 MIG 的 S_AXI 讲，答辩可直接用）

| 概念 | 一句话 | 在 MIG 里的对应 |
|------|--------|----------------|
| 5 通道 | 写地址 AW / 写数据 W / 写响应 B / 读地址 AR / 读数据 R，各自 VALID/READY 握手 | S_AXI 的 5 组端口 |
| Burst/Beat | 一次地址 + 连续 N 拍数据；len=拍数-1，size=每拍字节 | DDR4 行/列突发映射 |
| 4KB 边界 | 一个 burst 不得跨 4KB 地址界 | DMA 描述符对齐的根源 |
| ID 与乱序 | 不同 ID 的传输可乱序完成 | 多主设备（未来多 DMA）仲裁基础 |
| Outstanding | 地址发了不等数据，流水化 | 带宽打满的关键 |
