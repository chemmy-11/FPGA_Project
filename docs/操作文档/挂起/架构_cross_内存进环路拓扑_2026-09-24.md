# 内存进环路 · 整体架构与拓扑（草案 v0.3）

> ⚠️ **已整合（2026-09-29）**：本文全部内容（拓扑/时钟域/地址映射/决策点/选路建议）并入 [[操作文档/阶段三_prj10_内存进环路开工草案_2026-09-29]]（并修补槽管理/命令通道/静态预算缺口、里程碑重编 W0–W6）。本文件转为**历史留档**，不再更新；对导师沟通请用 [[汇报/汇报_阶段三_prj10_内存进环路需求对齐_2026-09-29]]。

> **来源**：导师 2026-09-24 口头要求——「把内存的读写功能加进去：以太网数据先写到内存，再从内存读出（地址每次可选不同）；经光回环再存一次内存；最后从内存读出经以太网发回。核心是把内存读写、尤其是随机读写放进整个环路。」
> **状态**：本文是**对齐用草案**，不是实施单。开工前需确认 §5 的七个决策点；**A/B 选路建议见 §7**。

## 0. 一句话架构

在现有「PC → 以太网栈 → 光回环 → PC」单向穿 Aurora 的通路里，**在光口两侧各插入一级「DDR4 内存（写 + 按地址读）」**，使数据从"流式直通"变为"**按地址存储转发**"——内存语义（而非 FIFO 语义）进入数据面。

**为什么必须强调"按地址读"**：现有 `frame_fifo_pump` 是 BRAM 做的 FIFO，地址对用户不可见、读出顺序恒等于写入顺序。导师要求的"多读几个数据、地址不一样"，本质是要证明**读出顺序可以不同于写入顺序，而每一帧的内容仍与其槽位严格对应**——这才是内存，不是更深的 FIFO。它是后续多队列、优先级、拥塞迁移与描述符环的地基。

### 1.3 单板形态与双板形态的等价性（为什么单板双笼可以外推）

```text
【单板 · 本期】内存被放在"光段"的两端，对端是同一块板的另一个 Aurora 核（只做回显）

  以太网栈 ─► 内存①(写/读) ─► pack ─► Aurora A.TX
                                        │ 笼A(Y11)
                                        ║ LC 跳线（渡光 1）
                                        │ 笼B(Y9)
                                     Aurora B.RX ─► 回显 ─► Aurora B.TX
                                        │ 笼B(Y9)
                                        ║ LC 跳线（渡光 2）
                                        │ 笼A(Y11)
  以太网栈 ◄─ 内存②(写/读) ◄─ unpack ◄─ Aurora A.RX

【多板 · 将来】同一套数据面逻辑，只换接线：对端变成另一块板的同号核，中间多一个转发引擎

  板①: 以太网栈 ─► 内存① ─► Aurora A.TX
                              │ 笼A(Y11)
                              ║ LC 跳线（板间干线）
                              │ 笼A(Y11)
  板②: 以太网栈 ◄─ 内存② ◄─ [转发引擎] ◄─ Aurora A.RX
```

> **能外推**：内存进出、光段收发、64b/66b 编解码往返 —— 内存永远在**光段两端**，这个结构不变。
> **不能外推**：跨板链路建立（两条 `channel_up` 独立）、转发决策与查表、多路径寻址（属后续阶段）。

### 2.2 路线 A / B 的分岔口只有一处

分岔口**不在**“要不要内存”，也**不在**“要不要软核”——**只在“数据怎么进出 DDR”这一层**：

| 路线 | 数据怎么进出 DDR | 数据面执行者 |
|---|---|---|
| **A** | AXIS → **自研 RTL AXI4 主机** → 直连 MIG `S_AXI`（512bit） | 纯硬件；MicroBlaze 可选（只下参数、读计数器） |
| **B** | AXIS → **AXI DMA** → SmartConnect → MIG | AXI DMA IP，由 MicroBlaze 软件配置（必需） |

> **分岔图与 A/B 逐项对比表（12 个维度）见 [[汇报/汇报_cross_内存进环路拓扑图与数据流向_2026-09-26.pdf|《拓扑图与数据流向》]] 的「A / B 两版的差别与分叉点」；选路建议见本文 §7。**

> 因此：D0（复现基线）、D1（MIG 上板）、地址/槽规划、判据与主机侧脚本，**两条路共用，绝不会浪费**。

## 3. 时钟域与接口契约

| 时钟域 | 频率 | 来源 | 接口 / 位宽 | 状态 |
|---|---|---|---|---|
| `eth_rxc` | 125 MHz | PHY 晶振（YT8531） | GMII 8b | 已有 |
| `user_clk` | ≈151.5 MHz | Aurora A GT 恢复钟 → MMCM | AXI4-Stream 64b | 已有 |
| `user_clk_b` | ≈151.5 MHz | Aurora B | AXI4-Stream 64b | 已有 |
| `ui_clk` | **≈300 MHz** | **MIG MMCM（4:1 比例推算，以生成报告为准）** | **AXI4 512b** | **新增** |
| `init_clk` | 100 MHz | 板载差分 AK17/AK16 | 复位 / DRP | 已有 |

**跨时钟域点**：

| 跨界 | 机制 | 状态 |
|---|---|---|
| `eth_rxc` ↔ `user_clk` | 泵A / 泵B（格雷码指针异步 FIFO + 4 相握手邮箱） | 已有 |
| **`user_clk` ↔ `ui_clk`** | **内存桥内异步 FIFO（512b 数据 + 帧长邮箱）** | **新增** |
| `init_clk` ↔ 各域 | 复位同步链 | 已有 |

> ⚠️ **铁律（来自 prj9 血泪）**：`ui_clk` 域的 ILA **必须挂 `ui_clk`**。跨域采样曾把 WNS 打到 **-2.639 ns**，且抓到的是亚稳态值。同理，内存桥的判决计数器要按域分挂。

> ⚠️ **MIG 硬门控**：坑位表记录「`init_calib_complete` 未同步进用户逻辑就发 AXI 读写 → 挂死」。内存桥必须先等校准完成 + `ui_clk_sync_rst` 释放才放行任何 AW/AR。

## 4. 内存地址映射与槽结构

### 4.1 地址空间划分（初版提案）

```text
 DDR4 4GB · 32bit 字节地址
 0x0000_0000  ┌────────────────────────────────┐
              │ MIG 保留 / 对齐                  │
 0x0010_0000  ├────────────────────────────────┤  ING_BASE
              │ INGRESS 槽区   槽 0 … 槽 255     │  SLOT = 4KB（对齐 AXI 4KB 边界）
              │ 每槽: [len 16b][payload …]      │  容量 = 1 MB
 0x0020_0000  ├────────────────────────────────┤  EGR_BASE
              │ EGRESS  槽区   槽 0 … 槽 255     │  容量 = 1 MB
 0x0030_0000  ├────────────────────────────────┤
              │ 空闲（多队列 / 描述符环预留）      │
 0xFFFF_FFFF  └────────────────────────────────┘
```

### 4.2 槽结构

- **定长槽**：每槽 4KB，天然满足 AXI「一个突发不得跨 4KB」的约束；
- **槽内布局**：`[15:0] frame_len` + 帧字节流（完整以太网帧，含前导/CRC 口径沿用泵的约定）；
- **写槽号**：帧计数器（0..255 回绕）——保证连续多帧落在**不同地址**，这正是导师说的"数据存的地址会不一样"；
- **读槽号**：由读地址选择器给出（三选一，见 §5）；
- **长度来源**：泵已经逐帧计数，桥直接取用，不需要重新解析以太网帧。

## 7. 路线选择建议（A vs B）——面向「随机读写」要求

> 追加于 2026-09-28。导师 09-24 要求「把 DDR4 加进环路、**特别要实现随机读写**」。§2.2 只给出分岔口位置，本节给出**选择结论、理由、接口预留与判据测法**。

### 7.1 结论

**走路线 A（自研 RTL 内存桥），但把「选地址」做成软件可写寄存器（§5 的 D7），并给路线 B 预留插入点。**

一句话理由：**「随机读写」考的是「地址是不是一等参数」，不是「谁来搬数据」**——地址参数化在 A 里同样成立；而 B 会让 MicroBlaze 进入每一帧的数据通路，把一个功能里程碑变成「BD 集成 + DMA + 中断 + 位宽迁移」四变量联调，与中期节点（2026-12 ～ 2027-01）不匹配。

### 7.2 先纠正一个可能的误解：随机读写不是选路的依据

| 问题 | 路线 A | 路线 B |
|---|---|---|
| 「地址每次可选不同」怎么实现 | 硬件地址选择器：帧计数 / 递增 / LFSR / **寄存器指定** | 软件写 DMA 源地址寄存器或描述符 |
| 随机读是否支持 | ✅ 寄存器路径 = 任意地址 | ✅ 天然支持 |
| **每帧谁下命令** | 数据面自主，**每帧 0 软件开销**，延迟确定 | Simple 模式**每帧需软件配置**；SG 模式需预置描述符环 |
| 与原阶段三表述 | 偏离（原文写「MicroBlaze 跑 C 代码」） | 一致 |

→ 两条路**都能**满足「随机读写」，差异在「每帧谁下命令」。所以选路判据应看**工程量、风险与终态**，而不是「能不能随机」。

### 7.3 选 A 的四条理由（按权重）

1. **与开题报告定案一致**：开题报告 v2 §4.1 已定「**板内双平面：数据面纯硬件 + MicroBlaze 控制面**」。A 是这句话的直接实现；B 把软核放进数据通路，反而要回头改开题表述。
2. **风险面小一个数量级**：B 要同时解决四件事——① Block Design 与纯 RTL 顶层共存；② 参考实现 **32bit** ↔ 我们 **64bit AXIS** 的位宽差；③ `user_clk ↔ ui_clk` 的 AXIS FIFO ×2；④ AXI INTC 中断与每帧软件时序。任一项都可能吞掉 1–2 周。
3. **判据路径最短**：J1–J6 全是功能判据。A 有现成骨架可复用——`mig_verify_top`（自研 AXI4 主机：写突发 → 读回 → 比对，离线已验证），改造点集中在**地址源**（固定递增 → 槽选择器）与**数据源**（测试 pattern → 帧泵输出），AXI4 时序骨架不动；且 4KB 对齐槽位使单帧突发天然不跨 4KB 边界。
4. **不浪费**：共同部分（建工程 / MIG 上板 / 引脚 / 地址规划 / 判据 / 主机侧脚本）A/B 共用；A 的帧侧接口、槽结构与地址寄存器三样在演进到 B 时原样保留，**只替换「AXI4 主机」这一层**。

> 与开题报告 §4.5 的关系：那里的「② DDR4 大容量队列 + AXI DMA + 描述符环」属于**队列容量**阶段，触发条件是「出现 ≥3 端点同时向同一边发送的实测排队」。本期做的是**内存语义进环路的功能验证**，不是同一件事——B 的时机仍留在 ②。

### 7.4 消除「返工风险」的三条接口预留

（§2.2 里 A 的唯一缺点是「若终态为 B，自研 RTL 桥会被 DMA 取代」；三条预留把它降为「只换一层」）

| # | 预留 | 做法 | 演进到 B 时的动作 |
|---|---|---|---|
| 1 | **内存桥拆两层** | `frame_mem_if`（帧侧：8b ↔ 512b、槽地址生成、帧长邮箱）+ `axi4_master_bridge`（突发 / 4KB 边界 / 仲裁） | 只换 `axi4_master_bridge` |
| 2 | **选地址走寄存器** | 读槽号 + 模式（递增 / 伪随机 / 外部指定），按 **AXI4-Lite 从机**语义设计 | 寄存器语义不变，改由 DMA 描述符驱动 |
| 3 | **接口保持 AXIS 语义** | 桥的进出以「帧」为单位（帧边界 + 帧长已知），与 pack/unpack 的 AXIS 64b 对齐 | DMA 可直插，不必重造接口 |

### 7.5 「随机读写」判据怎么测（J3 具体化）

| 判据 | 测法 | 通过标准 |
|---|---|---|
| 写入地址分布 | 连发 N 帧（N ≥ 槽数），看 ILA 写槽号 | 帧计数递增，多帧落在不同 slot |
| **乱序读出** | 上位机下发乱序槽号序列（如 7, 3, 255, 0, …） | 读出帧序 = 下发序列 |
| **地址 ↔ 内容严格对应** | PC 给每帧 payload 带序号，按（槽号 → 序号）映射逐帧校验 | 乱序不串帧，每帧内容与其槽位一致 |
| 反证「不是 FIFO」 | 同槽连读两次 / 跳号读 / 回读已读槽 | 内容与首次一致 → 按地址取，非按序弹 |
| 可观测 | ILA：写槽号 / 读槽号 / 突发计数 / 帧计数 | 四者同屏；寄存器值可经软核读回 |

> 这组判据同时证明「内存语义」与「随机读写」，且 PC 侧脚本即可自动判定，答辩可当场复现。

### 7.6 什么条件下改选 B（先定后测）

- 导师明确要求本期验收**必须**体现「MicroBlaze + C 代码配置搬运」的机制口径（即阶段三原文）；或
- 进入**多队列 / 描述符环**阶段（原阶段四）——此时 B 是终态，按 §7.4 的预留平滑替换。

**给导师的一句话汇报口径**：

> 内存进环路先按路线 A 交付随机读写判据——纯 RTL 内存桥 + 软件可写地址寄存器，MicroBlaze 只做控制面；AXI DMA 与描述符环留到多队列阶段。这样开题报告「数据面纯硬件 + 控制面软核」的定案不变，中期风险最低。
