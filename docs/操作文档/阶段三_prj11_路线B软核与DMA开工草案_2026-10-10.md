# 阶段三 · prj11 路线 B 实施单 v1.0 —— 软核 + C 控制 + AXI DMA（MicroBlaze 控制面正式版）

> **审定通过并升格实施单 v1.0（2026-10-10）**：用户批复「可开工」（含工程落位定案：新开 prj11）。
>
> 定位：**Q1 定案的第二步、Q3 的理想终态**。导师原话（2026-09-30）：
> ①「建议先走路线 A，先实现功能，然后再加上软核，这种路线 B」
> ②「他最理想的目的是用软核加上 C 来控制自己的读写位置。但是我们现在可以先做由上位机控制」
> **启动条件已满足（2026-10-09）**：路线 A 判据 J1–J6 + J3′ 全部上板通过，W0–W6 收口。
>
> **落地工程定案（2026-10-10 用户）**：路线 B **新开 `prj/project_11/`**（fork prj10），**prj10 整目录冻结为路线 A 资产**——沿用 prj8→prj9→prj10 的派生纪律，血缘链再续一环。

## 二、A 交付的地基（prj11 以 fork 方式整体继承）

- **寄存器语义**（W5 命令通道契约，B 一字不改）：`SET_MODE(0x01)` / `SET_RD_SLOT(0x02)` / `GET_WATERMARK(0x03)` / `GET_SLOT_MAP(0x04)`；写槽规则号 = 1（写槽 = 帧计数 mod 256，`wr_slot_ptr` 独立游标）。
- **数据面**：两级内存桥（INGRESS `0x0010_0000` / EGRESS `0x0020_0000`，各 256 槽 × 4KB）+ 自研 `axi_arb_2to1`（grant 锁存路由）+ MIG `ddr4_0`（AXI 512b @ ui_clk 300MHz）。
- **判据基线**：DDR 四档逐字节 / 导师原话四环节（`mentor_verify.py`）/ 10MB 100%+SHA / 速率 1466B **82.67k fps 零丢帧（≈969 Mbps）**——B 的每一步都以"**不低于此或退化可归因**"为回归线。
- **可观测性**：W6 三件套（`w6_inventory.py` / `w6_healthcheck.py` / `w6_archive.py`）继续作为收口门槛。

## 三、目标架构（B 版数据通路）

```
                    ┌───────────────── BD 子系统（新增，prj11 内）────────────────┐
                    │  MicroBlaze ──M_AXI(Lite)──► SmartConnect ──► (引出 BD)     │
                    │      │本地                    │AXI-Lite 从口  │AXI 主口      │
                    │  [UART/定时器]              (控制面)       AXI DMA(512b)   │
                    └──────────────────────────────┬──────────────┬─────────────┘
                                                   │              │
              控制面：写 cfg_mode/cfg_rd_slot、     │              │ 数据面：替换 axi4_master_bridge
              读水位/槽映射（寄存器组包一层         ▼              ▼ （DMA 的 AXI 主口接仲裁器）
              AXI4-Lite 从机）              axi_lite_regs    axi_arb_3to1（2to1 扩为 3 主）
                                                   │              │
                     frame_mem_if（帧侧，原样）◄────┘              ▼
                     8b↔512b、槽表、帧长邮箱                        MIG ddr4_0 S_AXI
```

与 A 的差别**只有两处**：数据面换一层（自研 AXI4 主机 → AXI DMA）、控制面加一路（UDP 命令通道旁新增软核 AXI-Lite 写同一组寄存器）。

## 四、集成路线二选一（本草案推荐方案 Y）

| 方案 | 做法 | 评估 |
|---|---|---|
| X：BD 全包（`0DMA_uart2ddr` 风格） | 全设计搬进 Block Design，MIG/DMA/软核/现有 RTL 全在 BD 内 | **否决**：把已上板验证的 A 版数据面整个打散重排（XDC/ILA/时序全重来），违背「B 不推翻 A」；工作量与风险远超收益 |
| **Y：BD 子系统挂 RTL 顶层（推荐）** | prj11 fork prj10/prj_loop 后，新建小 BD 只装 MicroBlaze + AXI DMA + SmartConnect + UART；AXI-Lite 从口与 DMA AXI 主口**引出 BD**，接到 prj11 的 RTL 顶层；MIG、两级桥、帧侧**全部不动** | A 版**目录级**冻结（prj10 零写操作）；BD 只承担"新增件"；血缘链与 prj8→prj9→prj10 一致，可回退 |

方案 Y 的四个落点：

0. **工程落位**：新建 `D:\FPGA\prj\project_11\`，fork 自 prj10/prj_loop（`create_project.tcl` 改源头；源件优先取 prj10 本地副本——`rtl_patch/` 系列与 IP 定版——减少对 prj9 的直接依赖）。**fork 完整性判据 = 文件级对照 + 全仿真回归逐字一致**（W4 双回归同款做法），板上证明并入 B1 场次。
1. **控制面**：新增 `rtl_patch/axi_lite_regs.v`——把 W5 寄存器组（cfg_mode / cfg_rd_slot / 水位 / 槽映射只读）包成 AXI4-Lite 从机；**UDP 命令通道保留**（双主：两路都可写，寄存器加 2 bit「最近控制者」标识；J_B2 判据要求软核路径独立复现判据，不依赖 UDP）。
2. **数据面**：DMA 的 AXI4 主口接 `axi_arb_2to1` 扩展版（**3 主 1 从**，级联两个 2to1 或改写为参数化；grant 锁存路由纪律不变，配联合仿真负向对照——坑账本 #23 教训）。
3. **换层次序**：**先桥②（EGRESS 出向读，DMA MM2S）后桥①（INGRESS 入向写，DMA S2MM）**——读路径失败不污染写入数据，且 J3/J3′ 判据可先行。

## 七、双轨排布

- **轨 A（AI 离线）**：B0 核查 → **prj11 脚手架（fork + 回归）** → BD 生成 Tcl（`create_bd_b.tcl`，幂等）→ `axi_lite_regs.v` + 单元 TB（正负对照）→ 仲裁器 3 主扩展 + 联合仿真 → C 程序（hello → 寄存器自测 → J3/J3′ 驱动序列）→ B 版构建脚本（沿用 WNS 门限）。
- **轨 B（用户上板场次）**：B1 一场（A 基线复现 + 点灯 + 寄存器回读）· B2 一场（软核版导师原话）· B3 每级一场（四档 + 10MB）· B4 一场（速率回归）。每场判读表随验证单发布。

## 八、与既有线的关系

- **D 线**：B3 即 **D5（AXI DMA）** 的实际落点，两线合流；D2（队列后端 DDR 化）可复用 B 的 DMA 搬运与描述符环。
- **E 线**：互不阻塞（E2 背靠背专场用 prj10 A 版位流即可跑，与 prj11 并行排期）。
- **论文口径**：B2 = 开题报告 §4.1「板内双平面：数据面纯硬件 + MicroBlaze 控制面」的**完整实现**；A→B 两步走本身可作为"控制面可演进架构"的论证素材；prj8→9→10→11 血缘链即"复用-派生-冻结"开发模式的完整案例。
