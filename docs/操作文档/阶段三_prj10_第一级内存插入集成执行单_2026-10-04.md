## 二、集成设计：要动的只有**两根线**

### 2.1 拦截点（这是全单最核心的一处）

在 prj9 顶层 `aurora_udp_bridge.v` 里，泵A 的输出原本**直接**进打包器：

```verilog
// 现状（prj9 顶层）
axis_word_pack u_pack (
    .in_data  (pump_fwd_data),   // ← 泵A 输出
    .in_valid (pump_fwd_en),
    ...);
```

改成**先过内存桥**：

```verilog
// 改后（新派生顶层）
// 泵A 输出 → 内存桥写侧
frame_mem_if u_mem (
    .wr_data  (pump_fwd_data),   // 原样接
    .wr_en    (pump_fwd_en),     // 原样接
    .wr_hold  ( ),               // 不接（见 §三 取舍）
    .rd_data  (mem_rd_data),     // 新增线
    .rd_en    (mem_rd_en),       // 新增线
    .rd_req   (mem_rd_req),      // 新顶层生成
    ...);
// 内存桥读侧 → 打包器
axis_word_pack u_pack (
    .in_data  (mem_rd_data),     // 原本是 pump_fwd_data
    .in_valid (mem_rd_en),       // 原本是 pump_fwd_en
    ...);
```

**除此之外，以太网栈 / 帧泵 / 打包 / 解包 / Aurora 一律零改动。**

### 2.2 派生顶层，不动原件

- 新文件：`prj\project_10\rtl\aurora_mem_bridge.v`
- 做法：**整份复制** prj9 的 `rtl\aurora_udp_bridge.v` → 改名 → 只按 §2.1 改那两根线 + 加内存核实例与引脚
- **prj9 的原顶层保留不动**（对照用；也是"prj9 零改动"承诺的兑现方式）

### 2.3 时钟：一对引脚不能有两个端口

| 需求 | 处理 |
|---|---|
| Aurora 需要 100M 差分参考钟（AK17/AK16） | prj9 已有端口 `init_clk_p/init_clk_n` + IBUFDS + BUFG → 产生 `init_clk` |
| 内存核也需要同一对引脚（它管这叫 `sys_clk_p/n`） | ⚠️ **2026-10-05 构建实证修正**：**不能把 `init_clk_p/n` 直连 MIG 的 `c0_sys_clk_p/n`**——MIG 差分模式内部自带 IBUFDS，与顶层继承的 IBUFDS 构成双输入缓冲，综合直接拒绝（[Synth 8-5535]）。**正确做法**：工程内 MIG 副本改 `CONFIG.System_Clock = No_Buffer`（端口变单端 `c0_sys_clk_i`），由**顶层 IBUFDS 的输出** `init_clk_i`（BUFG 前）喂入——一个 IBUFDS、两个负载（Aurora 数字逻辑经 BUFG + MIG MMCM），合法且同源。改配置用 `set_property CONFIG.System_Clock No_Buffer [get_ips ddr4_0]`（import_ip 已把 xci 拷进工程 .srcs，**不碰 prj_uiclk/prj4 原件**）；改后必须 `reset_target all + generate_target all + reset_run ddr4_0_synth_1`，否则顶层综合读到旧差分 stub 报端口不存在（[Synth 8-11365]）。已固化进 `create_project.tcl` / `build_debug.tcl` |

⚠️ **不要**再新增一对 `sys_clk_p/n` 端口——同一物理引脚绑两个端口会直接报错。

### 2.4 复位：内存核的 `sys_rst` 是**高有效**

```verilog
// prj9 顶层端口是 sys_rst_n（板载按钮 AC34，低有效）
wire mig_sys_rst = ~sys_rst_n;      // ← 必须取反！
.u_ddr4 ( .sys_rst (mig_sys_rst), ... );
```

> **为什么单列一条**：prj4 现有例程（`mig_verify_top.v` 第 248 行）**直接**把 `sys_rst_btn` 接到了 `sys_rst`，极性是反的——结果是"按钮不按 = 内存核一直处于复位 = 校准永远不完成"。**本单的新顶层必须写对**；prj4 那边是另一张单的事（见 §六）。

### 2.5 LED 与探针

| 灯 | 集成后的含义 | 理由 |
|---|---|---|
| **T23** | **链路**（channel_up）| 保持 prj9 原义——这是所有上板判据的**硬前提**，别抢 |
| **T22** | **内存校准完成** | 原 prj9 的"观测灯"让位给校准指示（本轮最需要看的信息） |

**ILA 必须按域分挂**（血泪教训：跨域采样曾把时序打到 −2.639 ns）：
- `ui_clk` 域一个：槽指针（`ro_dbg_wr_slot`/`ro_dbg_rd_slot`）、写水位 `ro_wm`、拒收/非法读/长度错三计数器、`calib_ok`
- `user_clk` 域一个：帧计数（`ro_u_wr_frame`/`ro_u_rd_frame`/`ro_u_buf_drop`）

## 三、设计取舍（要写进代码注释，别让下一个人猜）

| 取舍 | 决定 | 理由 / 代价 |
|---|---|---|
| `wr_hold`（上游暂停） | **不接** | 帧泵不支持暂停；桥在缓冲满时**整帧拒收并计数**（`ro_u_buf_drop`）。代价：突发下会丢帧但**可见**。若上板发现丢帧明显，再单独立项给泵加暂停能力 |
| 读写模式 | **SEQ**（`cfg_mode=0`） | 帧按写入顺序读出，与"不退化"判据一致；随机读是后续单独验收项 |
| `rd_req` 生成 | `ro_wm != 0 && !rd_busy` 时给 **1 拍脉冲** | 避免空读把 `noframe`（无帧）计数刷爆 |
| **帧间空隙** | **上板前必查** | 打包器靠 `in_valid` 的下降沿识别帧尾；**必须确认**内存桥读侧两帧之间至少有一个空闲拍。若不足 → 在桥的读侧加"最小帧间隔计数器"（几行） |

### 步骤 2｜合并约束（**注意排除清单 + 必改一处**）

新 XDC = prj9 的 `aurora_udp_bridge.xdc` **全文** + prj4 的 `mig_verify_pins.xdc`（在 prj4 **根目录**）里的 **DDR 引脚行**。

**合并时必改一处（否则判据 2 自相矛盾）**：prj9 XDC 第 92 行的 `set_false_path -quiet -to [get_pins ...]   # 行尾注释` ——Tcl 行尾 `#` 不是注释而是多余参数 → 必产 1 条 CRITICAL WARNING [Common 17-165]（prj9 构建日志实证，坑账本 #19）。**在合并副本里把该注释移成独立行**（1 行改动，prj9 原件不动）——这样判据 2"综合 0 CRITICAL WARNING"才可能达成。

## 六、已知缺陷与风险

| # | 项 | 说明与处置 |
|---|---|---|
| 1 | **prj4 例程复位极性反了（已实证 `mig_verify_top.v:248`）——直接冲击最近的场次2/D1** | 低有效按钮直连高有效 `sys_rst` ⇒ **松开按钮 = MIG 持续复位 = 校准永远不完成；按住 AC34 不放 = MIG 释放复位可校准**。本单集成顶层按 §2.4 写对即可；但 **D1（场次2，烧 prj4 现有位流）必须先处置**：要么操作单写明"按住 AC34 不放再判读 T22"，要么按红线走派生修复（复制 `mig_verify_top.v` 改 1 行取反）重出位流——**不处置则 D1 必得"校准不亮"的假阴性**。需同步进 [[操作文档/阶段三_cross_上板操作优先级清单_2026-10-04]] 场次2 判读表 |
| 2 | 时序零余量 | 内存核域本来只剩 +0.024 ns；虽然加了桥的前置工程测到 +0.030 ns，但**余量仍属零余量级**——每次 RTL 改动都要重跑实现看 WNS |
| 3 | 跨时钟域 | 桥内部用格雷码异步 FIFO ×5（已验证）；**ILA 绝不跨域采样**。澄清：前置工程的 951 寄存器 no_clock 问题（udiv 分频自造时钟无约束）**在本集成工程不适用**——user_clk 来自 Aurora IP，IP 自带 XDC 生成时钟约束；但建完后仍应跑一次 `check_timing` 确认 no_clock=0 |
| 4 | 校准前不得发 AXI | 桥内已有硬门控（校准前零 AXI 活动，仿真验证过）；不要绕过 |
| 5 | **帧间空隙 + 帧中欠载（两条，后者更致命）** | ① 帧间空隙：打包器靠 `in_valid` 下降沿识别帧尾，两帧间至少一个空闲拍。② **帧中欠载**：prj9 原 pack 上游是帧泵——"整帧缓存后**无间隙**泵出"（frame integrity 契约）；换成内存桥读侧后是 **FWFT FIFO 边发**（`est==1` 只要 `!rb_empty` 就 pop）——若 DDR 读回节拍（AXI 往返 + beat 间隙）跟不上 user_clk 消费，**帧中间断流 → Aurora TX 64b/66b 帧协议违例 → TX 楔死**（= 09-20 B 回显裸 FIFO 直通的同款根因，当年靠级联整帧缓存修掉）。静态算术大概率能跟上（rb 写 300 MB/s > 读 ~156 MB/s，FIFO 深 4096 B ≥ 整帧 1538 B），**但无仿真/算术论证不得上板**。处置二选一（开工前定）：(a) 桥读侧改"rb 水位 ≥ 帧长再开始发射"（攒满整帧再发，与帧泵同语义；需把 `u_rd_bytes` 空接的 `rd_level` 引出，~5 行）；(b) 用 W2 的 Lw/Lr 延迟模型 + pack 行为模型仿真证明最坏档无帧中气泡 |
