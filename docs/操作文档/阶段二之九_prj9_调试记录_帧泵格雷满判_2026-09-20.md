# 调试记录：帧泵 wr_full 伪满楔死（prj9 真光链路）

## 一、现象

- prj9 双笼 A↔B 位流（回显路径裸 FIFO 版与 unpack→pack 版**行为完全相同**）：
  - ping 20/20 全过（<1ms）
  - udp_verify：L=26 ✓ L=27 ✓ **L=28 起全部超时**
  - 之后 ping 也 0/3、0/5——**整条回显路径永久楔死**（重烧恢复，必现）
- T23 常亮（channel_up_a & channel_up_b 均为 1），hard/soft_err = 0

## 二、定位过程（判别实验链）

1. **换 B 回显架构无效**（裸 FWFT FIFO → unpack→pack 整帧存储转发，楔死点分毫不差）→ 排除 B 侧实现，确认为确定性楔死（第 26 帧）。
2. **ILA 两阶段尸检**（ila_cap_wedge.tcl / ila_cap_wedge3.tcl）：
   - ILA0（user_clk）：pk_frames=up_frames=prev_wr=**25/25/25** 完美平衡，pk_ovf=0，ch_up=1 → **光纤回显路径无辜**。
   - ILA1（eth_rxc）阶段1：5 次 ping 期间 stack_txen **零触发**——栈没产生任何回复帧。
   - ILA1 阶段3：抓到干净 ARP 请求 + **stack_txen=72 拍**（栈在发 ARP 回复），但 pfwd_wr 停在 25、pfwd_drop=0。
3. **三难排除法**：帧到达 ∧ 栈在发 ∧ 泵零写入零丢弃零完成 → 唯一自洽解：**wr_valid 被 wr_full 永久挡死**（wr_cnt 恒 0 → 既不完成也不丢弃，与全部证据吻合）。
4. **读码发现公式错误**（frame_fifo_pump.v）：
   assign wr_full = (wr_bin_next[AW] != rd_ptr_g_s2[AW]) && (wr_bin_next[AW-1] != rd_ptr_g_s2[AW-1]);
   —— 二进制 wr_bin_next 与格雷码 rd_ptr_g_s2 逐位混比；累计字节跨 2048（FIFO 深度回绕）后伪真，读侧空闲时永不解除。

## 三、仿真复现（证据闭环）

| 测试台 | 旧代码 | 修复后 |
|---|---|---|
| 40 帧慢节奏（86B×40，跨回绕） | 24 完成 + **16 无声消失** | 20+20 全对账（丢弃为 TB 节奏快于泵周转，合规） |
| 200 帧紧节奏（写指针累计 8600B 跨回绕 4 次） | — | 100+100 全对账 |

修复期二次踩坑（C22b）：帧原子性门控初版把 hs_busy 释放与 frm_dropping 耦合，释放窗口（单拍）恰逢丢弃帧中途被永久错过（仿真 40 帧只完成 1）——改为释放不受 frm_dropping 门控，半帧防护由 frm_dropping 独立保证。

## 四、修复（git f7c8be8）

1. **满判改标准 Cummings 格雷满**：wr_full = (bin2gray(wr_bin_next) == 拼接(~rd_ptr_g_s2 高两位, rd_ptr_g_s2 低位))
2. **帧原子性**：忙时到达的帧整帧不进 RAM（frm_dropping 粘滞到帧尾），丢弃帧字节不再推走写指针
3. **复位对称化**：泵A 写侧、泵B 读侧复位统一为 ~aurora_rst（原不对称会在链路抖动时单侧复位→指针失配）
4. （同 commit）B 回显由裸 FIFO 改为 unpack→pack 级联——与 prj8 第一根因同解

## 六、方法论沉淀

- “计数器全对账 + 零触发”是定位楔死类问题的黄金组合：先证无辜段，再逼出唯一自洽解。
- 板上必现的 bug 必能在仿真复现——复现前不动手修（本轮又验证一次）。
- 修并发逻辑时警惕“顺手加固”引入的新耦合（C22b 教训：防护与释放解耦）。
