# prj10 W5 · 命令通道与随机读：交付 + 时序阻断定案（2026-10-07）

> **一句话**：**功能侧全部做完并已自证，卡在时序**——把 `cfg_mode` 从常量接成真信号后，桥① 里那条「RND 读决策」组合锥在 300MHz 下**根本走不完**（4.226ns / 3.333ns），而它在 W2–W4 一直是**死逻辑**（被常量折叠），所以历次时序收敛记录都不覆盖它。
> **结论**：**不可带病上板**（见 §五）。W5 恢复点 = 「RTL 与脚本齐备 + 时序修法已设计」，等决策后实施。

> ## ⚠️ 本记录的 §四（根因）与 §六（修法）已被第二轮修订
> 第二轮按第一性原理重新取证后修正了三处：① 超预算的是**整条读命令解码锥**（FWFT 组合读出+比较+选择+三张 256:1 查表），不是“RND 专属逻辑”（`cmd_rnd` 是这条锥的**选择信号**，SEQ 下同样活）；② W4 通过只是因为常量折叠，且其残段「寄存器索引→len_tab→+63→r_beats」本身只剩 **+0.008ns**，所以“只切一刀”不够；③ SEQ 指针扫描的守卫也挂在 FIFO 输出上，需一并改。
> **最新状态**：cut-1 已实施并实测 **WNS -1.121 → -0.494**（失败端点 5011→3464），四仿真全绿；cut-2 触发 Vivado 综合崩溃（3 次可复现）已回退留证。**当前停在 -0.494ns，仍不可上板。**
> 详见 [[调试记录/阶段三_prj10_W5时序收敛_第二轮根因重定与修复_2026-10-08]]。

## 二、集成期拦下的两个真缺陷（都在上板前）

| # | 缺陷 | 后果 | 处置 |
|---|---|---|---|
| 1 | **应答走泵A 输入 → 桥① 写侧** | RND 模式下桥① **不再自动读** → 应答帧被写进槽里、要等读序轮到它才出得来 → **ACK 事实上到不了 PC**（`GET_WATERMARK` 自锁，J3 无法驱动） | 注入点改为 **RGMII TX 末级**（`gmii_to_rgmii` 输入前）：绕开两级内存桥、零 CDC（`assign gmii_tx_clk = gmii_rx_clk`）、满足 IFG、不占槽不抬 `wr_stall` |
| 2 | **`cmd_hold` 多驱动**（解析块置位 / 执行块清零，两个 always 写同一 reg） | 综合后 `opt_design` 报 `[DRC MDRV-1] Multiple Driver Nets` → 实现直接中止 | 拆成「单驱动标志 + 单拍握手」：执行块拉 `cmd_take`，解析块见 `cmd_take` 清 `cmd_hold`；**修后单元 TB 复验仍 PASS/FAIL(68)** → 语义未变 |

> **教训（已入坑账本 #25）**：多驱动**单元仿真抓不到**（Verilog 允许多块写同一 reg，仿真按最后赋值裁决），只有综合/DRC 才判非法 ⇒ **「仿真 PASS」不等于「可实现」**。

## 四、根因（证据链）

### 4.1 事实

```
Design Timing Summary
WNS=-1.142  TNS=-1094.646  失败端点 4040 / 127539     WHS=+0.004（过）
Timing constraints are not met.

Intra Clock Table（分域）
  eth_rxc        +0.838  0 失败      ← 命令通道 eth 侧：无影响
  user_clk       +1.099  0 失败      ← 命令通道 user 侧：无影响
  user_clk_b     +1.645  0 失败
  init_clk       +7.365  0 失败
  mmcm_clkout0   -1.142  **4040 失败 / 63283**   ← 全部集中在 ui_clk(300MHz)
  mmcm_clkout5   +6.857  0 失败

报告时序最差路径（前 12 条全部同型）
  Source      : u_mem/u_rd_cmd/rd_bin_reg[0]_replica/C
  Destination : u_mem/u_bridge/stat_ill_rd_reg[*]/CE      ← 非法读计数器
  Data Path   : 4.226ns（logic 1.328 / route 2.898），9 级（CARRY8/LUT4/LUT5×2/LUT6×3/MUXF8/RAMD32）
  Requirement : 3.333ns  → 缺口 -0.893…-1.142ns
```

### 4.2 机制

1. **RND 决策锥在 ui_clk 域**：`axi4_master_bridge.v:376-381,426-440`
   ```
   rc_data(FIFO 出) → cmd_slot/cmd_rnd → in_range/clamp_slot → eff_slot
     → full_bit[eff_slot]（256:1 分布式 RAM 查表，RAMD32+MUXF8）→ rd_target_ok
     → stat_ill_rd 的 CE / 读发起（r_slot/len_tab/r_beats/空应答）
   ```
2. **它在 W2–W4 是死逻辑**：`cfg_mode` 此前硬接 `1'b0`（`aurora_mem_bridge.v` 原 `:cfg_mode(1'b0)`），`cmd_rnd` 恒 0 ⇒ 综合把**整条 RND 分支常量折叠掉**，该锥从未进入时序报告。SEQ 分支的 `full_bit[rd_seq_slot]` 索引是**寄存器**（`rd_seq_slot`），所以 SEQ 一路都能收敛（W4 +0.008 即证）。
3. **W5 把它接活**：命令通道把真 `cfg_mode` 送进桥 ⇒ 该锥复活，**且它从来就不满足 3.333ns**（逻辑 1.33 + 布线 2.90）。
4. **为什么是「大面积微缺口」**：4040 个端点平均缺口仅 ≈0.27ns ⇒ 典型**拥塞放大**（同锥的 CE/扇出把周边路径一起拖过线），所以看到的是「4040 个端点失败」而不是「一条路径失败」。

### 4.3 判别实验（排除「探针拥塞是主因」）

- 假设 A：300MHz 的 ILA3 被我从 179bit 加到 275bit（+96bit）导致拥塞 → 是主因。
- 实验：**把 96bit 全裁掉**（回到 W4 已知良好配置）+ 换 W4 最优配方 → **仍 -1.1 量级**。
- ⇒ **假设 A 被否**：探针只是放大项，**根因是该组合锥本身超预算**。（副作用：本次裁探针后 `rpt` 里仍出现 CLB 路由拥塞报告，说明 ui 域本就在拥塞边缘。）

> 顺带排除：`report_timing` 的 4040 端点里最差 12 条全是 `stat_ill_rd[*]/CE`，**没有一条是 ILA 寄存器**（`u_ila_3_CV/...`）为终点的探针路径 ⇒ 不是「探针接线太长」问题。

## 五、为什么不可带病上板

未收敛的是**功能路径**，不是观测路径：

- `stat_ill_rd` 的 CE 锥同时决定「这一拍要不要判非法读」⇒ 时序违例意味着**判定可能采到错误值**：可能把非法读当合法（去读一个未写槽 → 取回垃圾帧），或把合法读当非法（回空应答、J3′ 缺帧）。**J3/J3′ 的判据本身就是「每槽恰好取一次」，一旦槽决策抖动，测试结论不可信**。
- 缺口最小也有 0.89ns（≈27% 周期），不是「偶发亚稳态」量级，是**必然出错**。
- 因此 W4 定的构建门限（**WNS ≥ 0 且 WHS ≥ 0 才可上板**）必须继续执行：本次构建已加 WNS 门限，**不写位流**。

## 六、修法（两条路线，首选 A）

### 路线 A（首选）：桥内给 RND 单独加一拍决策态 —— SEQ 路径零改动

**思路**：把长锥从中间切开——先寄存 `eff_slot`（前半段：比较/加法，无 256:1 查表），下一拍再做 256:1 查表与判决。

```verilog
// 新增状态 R_RNDDEC + 两个寄存器（示意）
R_IDLE: if (rc_rd_en) begin
    if (cmd_rnd) begin
        rnd_slot_q    <= in_range ? cmd_slot : clamp_slot;   // 只做比较/选择（~0.7ns）
        rnd_inrange_q <= in_range;
        rstate        <= R_RNDDEC;                           // 下一拍再查表
    end else begin /* 原 SEQ 单拍路径：逐字不动 */ end
end
R_RNDDEC: begin
    // 索引是寄存器 rnd_slot_q ⇒ 路径变成 rnd_slot_q → full_bit/len_tab(256:1) → CE
    //  ≈2.0–2.5ns，满足 3.333ns
    ...
    rstate <= R_IDLE;
end
```

**预期收益**：把 4.23ns 拆成 ~1.0ns + ~2.5ns 两段 ✓。
**代价与风险**：RND 读多 1 拍（PC 侧 ≥1ms 间隔，无感）；`r_rnd`/`ill_rd`/`noframe`/`rd_wr_en` 等语义保持（判决结果相同，只是晚一拍）；**SEQ 路径不动 ⇒ W2 六用例 STAT（`hold_cycles=24100`）应逐字不变**。
**必须复验**：W2 六用例（含 T5/T5b 的 RND 非法读/退休语义）+ W4 联合 TB（两桥+仲裁器）+ 仲裁器单元 + 重建后 WNS≥0。

### 路线 B（不推荐）：动 ui_clk 频率或 MIG 配置

把 300MHz 降到 ~250MHz 可立刻给出余量，但要改 MIG 配置/重新生成 IP 并**重跑 J1 校准判据**，代价与风险都远高于 A，且掩盖 RND 逻辑本身过深的问题。

### 路线 C（备选，正交）：把 RND 判决搬出 300MHz 域

`full_bit/len_tab` 是 ui 域资源；若要搬到 user 域需重建跨域镜像表，改动面大，仅在前两条都不可行时考虑。
