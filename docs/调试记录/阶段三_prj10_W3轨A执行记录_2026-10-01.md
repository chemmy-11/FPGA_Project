## 一、A1（B1）：补 12 个 AXI4 端口

**改动（4 个文件）**：

| `rtl/axi4_master_bridge.v` | 新增 `m_axi_awid[3:0]`/`bid[3:0]`/`arid[3:0]`/`rid[3:0]` + `awlock/awcache/awprot/awqos` + `arlock/arcache/arprot/arqos`；常量赋值块 |

**取值依据**（D1 断点核查 §3.1）：`awid/arid` 在 MIG 内部是**功能字段**（`r_channel.sv` 把 ID 搬进读事务缓冲再驱动 `rid`），必须给合法值；
本桥每个 FSM 单突发在途，**写用 ID=0、读用 ID=1** 即可区分两流且无需重排跟踪；`bid/rid` 不参与比较（仅 VALID 限定）。

**回归判据（硬门）**：`run_sim.bat` 六用例 PASS，且 STAT 行与基线**逐字节一致**：

```text
STAT service: wr=933 ui-cycles/frame (3.11 us @300MHz)  rd=920 (3.07 us)
```

→ **端口补齐零行为变化**（同样的拍数、同样的计数）。

**附带复跑：地址断言三档**（A1 改了 3 个 TB 的连线，必须确认判据没被削弱）：

## 二、A2（B3-α）：可变延迟模型四档扫

**方法**：`axi4_ram_model` 新增 `W_RESP_DLY`（默认 0 = W2 波形逐拍一致）；TB 顶层新增 `AR_LAT_T`/`W_DLY_T` 参数，
用 `xelab -generic_top` 重展开，四档 = 目标测得延迟 `(Lw, Lr)`：

| 档 | (W_DLY, AR_LAT) | 实测目标 (Lw, Lr) | wr 拍/帧 | rd 拍/帧 | 判据 |
|---|---|---|---|---|---|
| 1 | (0, 8) | (2, 9) ← **= W2 基线** | **933** | **920** | PASS |
| 2 | (48, 49) | (50, 50) | **982** | **961** | PASS |
| 3 | (198, 199) | (200, 200) | **1132** | **1111** | PASS |
| 4 | (498, 499) | (500, 500) | **1432** | **1155** | PASS |

四档全部：六用例 PASS、`4k_violation=0`、`axi_proto_err=0`、`ill_rd=3`（与基线同）、WSTRB illegal=0。

**三条结论**：
1. **写路径对 Lw 严格 1:1**：ΔW_DLY = +48/+150/+300 → Δwr = **+49/+150/+300** 拍，精确吻合
   `T_w = L + 3·ceil(L/64) + 4 + Lw`。→ 09-29 的回归模型**在仿真中得到独立验证**。
2. **读路径在高延迟下部分被吸收**：ΔAR_LAT = +41/+150/+300 → Δrd = +41/+150/**+44**。
   即 500 拍档下读延迟没有再 1:1 暴露（FSM 在等待期间仍有其他工作在推进）。
   **如实记录**：这条与写路径不同，不做整齐化解释；W3 上板实测 Lw/Lr 时按实测回填。
3. **节拍安全**：最坏档（500,500）单桥服务 1432 拍 ≈ **4.77 µs**，仍 < 帧周期 12.30 µs（3690 拍）；
   两级桥串行按 2× 计 ≈ **9.5 µs**，裕量 ≈ **1.29×** —— 比 09-29 纸面推算的 1.05× **更好**（纸面把延迟按最坏串行叠加，实测有重叠吸收）。

## 三、A3（B4）：尾拍 WSTRB 专项 ★ 抓到真缺陷 D3

**新增 TB**：`sim/a3_tail_tb.sv`（帧长 1000/1466/1538 × 两档延迟），除逐字节比对外，
**独立监视 WSTRB 掩码形状**：合法 = 全 1（满拍）或 **LSB 连续**（尾拍），且 partial 掩码只能出现在 burst 末拍。

### 3.1 缺陷 D3（修前实测）

```text
[A3] wstrb: full=64 tail=0 illegal=0      <- 3 帧 64 个 beat，全部"满掩码"
```

1000/1466/1538 **都不是 64 的整数倍**，本应有 3 个 partial 尾拍（40/58/2 字节）。
实测 **0 个** → 尾拍 `wstrb` 是**上一拍残留的全 1 掩码**。

**根因**（`rtl/axi4_master_bridge.v`）：`w_strb_r` **只在帧首（W_IDLE）清零**，拍与拍之间不清；
尾拍只写入前 N 个 lane（置 1），其余 lane 保留上一拍的 1。`w_data_r` 同样保留脏字节。
→ 每帧**多写最多 63 字节**（内容 = 上一拍残留）到帧尾之后。

**影响分级（第一性原理）**：
- **今天不破判据**：多写的字节落在**该帧自己的 4KB 槽内**，读回按描述符长度取数 → J2/J3/J4 全过（这也解释了 W2 为何没抓到）。
- **属于真缺陷**：① 主设备写了它并未声明的字节（AXI 语义上 `wstrb` 就是"哪些 lane 有效"的声明）；
  ② **一旦布局变成紧凑打包**（D2 描述符环 / 背靠背帧），这 63 字节会**覆盖下一帧的头**；
  ③ 若未来开 ECC（当前 `Ecc=false`）会误报。
- **判据教训**：B4 原本被列为"灰色地带"——实测证明它**不是灰的，是缺陷**；这正是该实验存在的意义。

### 3.2 修复与复验

**修法**（1 行）：`W_PUSH` 握手时 `w_strb_r <= 64'd0;`（`w_bi` 同时归零，随后按字节置位）→ 每拍掩码独立。

```text
[A3] tail beat: awlen=15 wstrb popcount=40   <- 1000 mod 64 = 40 ✓
[A3] tail beat: awlen=22 wstrb popcount=58   <- 1466 mod 64 = 58 ✓
[A3] tail beat: awlen=24 wstrb popcount=2    <- 1538 mod 64 =  2 ✓
[A3] wstrb: full=61 tail=3 illegal=0
=== A3 TAIL-WSTRB SIM: PASS (0 errors) ===   （两档延迟均 PASS）
```

**回归**：`run_sim.bat` 六用例 PASS，**STAT 判据行与基线逐字一致**（wr=933 / rd=920 未变）；
WSTRB 监视器从"full=8198, tail=4（假象）"变为 **"full=7655, partial_tail=547, illegal=0"**（真象）。

**这条结论的意义（B2 关闭）**：09-29 的担忧是"MIG 零余量（+0.024 ns），任何 ui_clk 域新增逻辑都可能立刻 WNS<0"。
实测：把 `frame_mem_if` + `axi4_master_bridge`（含 5 个 CDC FIFO 与两级 FSM）放进**真 `ddr4_0`** 旁边之后，

⚠️ **诚实边界**：① 这是**前置工程**（不含 Aurora/以太网），完整 A4 的 WNS 仍需在完整工程上复核一次；
② 余量 +0.030 ns 仍是**零余量级**——**每次 RTL 改动都必须重跑实现看 WNS**（这条纪律不因本次通过而放松）；
③ 本工程未出位流（A5 只到 route 与报告，够判 B2）。

**判读三分支**（照 W3 开工文档）：WNS≥0 → 出位流待场次3；<0 但 >−0.5 ns → 优化重跑；仍 <0 → **停下上报**（#14 BRAM v2 回退是路线决策点）。

**受阻**：官方 DDR4 行为模型（`ddr4_model.sv` + `arch_package`/`proj_package`/`MemoryArray`/`StateTable`）的**编译顺序与包含关系**：
`interface.sv` 反向 `include` `ddr4_sdram_model_wrapper.sv`，直接用自定义 wrapper（`DDR4_8G_X16`）会出现
`proj_package/MemArray` 未声明与递归包含。**正解 = 走 IP 自带 sim 流程**（`generate_target simulation/example`
产出的编译脚本里带官方文件顺序），而非手工拼编译命令。

**更精确的受阻点**（2026-10-01 补充）：即便用"宏垫片"绕开 `interface.sv ↔ wrapper` 的互相包含，
仍报 `MAX_ROW_ADDR_BITS is not declared`（`arch_package.sv` 使用该宏，而**发布树里没有它的定义**）——
说明**必须由 IP 自己的 sim 生成流程补齐**（`generate_target simulation` / example design 会带出正确的
macro 集与编译顺序），手工拼 `xvlog` 命令行走不通。

**结论**：**A0 不阻塞 A4/A5，也不阻塞 W3**——桥与 MIG 的接口合规性由 **A4/A5 的真 MIG 例化 + 综合**直接验证，
