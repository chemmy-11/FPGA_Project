## 二、设计要点（与开工草案的对应）

1. **只缺对接的分层**（草案 §四）：`frame_mem_if`（帧侧，留）/ `axi4_master_bridge`（AXI+槽表，**路线 B 时只换这层**）/
   `async_fifo`（CDC）。三条接口预留全部落地。
2. **槽策略**（草案 §六.3 落地为可执行语义）：4KB×256×2 区；写槽 = `wm[7:0]`，槽仍 FULL 则**拒收**（绝不覆盖未读帧）；
   SEQ 读最老未读槽（指针扫描，与 RND 混用安全）；RND 越界 → `ill_rd_cnt++` 且 clamp 到 `wm-1`，
   命令槽非 FULL → `ill_rd_cnt++` 且回**定长 0 空应答**——随机读未写槽从"未定义"变"定义 + 可计数"。
3. **CDC 纪律**（AGENTS §五.1）：跨域只有两种形式——格雷指针异步 FIFO ×5、2FF 同步器 ×1（outstanding 格雷码镜像）。
   **槽表单时钟（ui_clk）**，无跨域表风险。
4. **MIG 硬门控**（prj4 教训）：`init_calib_complete` 未同步进本域前，**一个 AW/AR 都不发**（T6 实测：300 拍内 AXI 活动 = 0），
   且门控期间帧在 FIFO 里排队不丢、校准后照常落盘。

## 四、静态预算：W2 实测 vs 草案估算（**草案 §九 需修正**）

> ⚠️ **2026-09-30 口径订正（本节数字作废，勿再引用）**：下表 3.11/3.07 µs 是**混合帧长的平均服务时间**（受 26–1466 B 短帧摊薄），**不是 1466 B 设计点**。
> 经 09-29 深夜独立复核（实测计数回归模型 `T_w = L + 3·ceil(L/64) + 4 + Lw`，误差 <1%），**设计点口径**为：
> 单桥 1466 B = **5.14 µs（替身模型）/ 5.80 µs（Lw=200 拍）**；读写是**共享同一 AXI 端口的两个 FSM**，
> **两级桥链每帧串行 Tw+Tr = 10.21 µs（替身）/ 11.68 µs（含延迟）**，相对帧周期 12.304 µs 裕量仅 **1.20× / 1.05×**。
> 故本文下方"节拍不变""端到端延迟 +6 µs"应读作 **+10~12 µs**。**权威口径见**
> [[操作文档/阶段三_prj10_内存进环路开工草案_2026-09-29]] §九（实施单 v1.0）与 [[操作文档/阶段三_prj10_W3前置清单_2026-09-29]] §2.1。
> 另见 09-29 二次核查：`prj10_W2_判据独立复核`（同目录 `docs/`）修复了 2 个真缺陷（多驱动 / 超长帧卡死）并新增绝对地址断言。

| 项 | 草案 §九 估算 | **W2 实测（混合帧长均值，非设计点）** |
|---|---|---|
| 单桥写服务 | ≈0.4–0.7 µs/帧 | **3.11 µs/帧**（933 ui 拍，混合帧长） |
| 单桥读服务 | 同上 | **3.07 µs/帧**（920 ui 拍） |

> **修正点**：草案只算了 AXI 突发本体（24 拍 ≈0.16 µs），**漏掉 8b↔512b 逐字节转换**——
> 那才是内存桥的真实服务时间（1466 B 帧 ≈1466 ui 拍 ≈4.9 µs；实测均值 3.1 µs）。
> **结论不变**：读写在同一 ui_clk 域是**并行两个 FSM**，单桥按 max = 3.1 µs/帧、两级桥 ≈6.2 µs
> **仍 < 帧周期 12.30 µs**，节拍器仍是泵B/栈TX（12.21/12.24 µs）→ **全链路上限 ≈957–959 Mbps 口径保留**，
> 端到端延迟 +6 µs 量级。**待 W1 用 MIG 生成报告复核 `ui_clk` 真实频率后定稿**。

## 五、bring-up 修掉的三条真 BUG（方法论沉淀）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| R1 | 首帧写完，之后所有读**卡在 `R_AR`**，MIG 替身停在 RS_DATA | **AXI R 通道握手违规**：`rready` 只在 `rvalid` 未到时拉高、`rvalid` 一到同一拍就撤销 → 从机永远采不到 `rvalid && rready`，突发送不出去 | 用 `if (m_axi_rvalid && m_axi_rready)` 判握手（与 AW/W/B 三通道一致） |
| R2 | **帧黏连**：尾巴帧永远写不完（末拍不满 64 B，FSM 等下一帧字节来填） | 尾拍完成条件只判"满 64 字节" | 增加"帧字节预算耗尽即完成"：`(w_bi==63) \|\| (w_bidx+1==w_len)` |
| R3 | 所有帧被当"非法长度"拒收 | `ud_din = wcnt` 组合取自**同一拍被清零**的 `wcnt` → 描述符长度恒 0 | 独立寄存器 `ud_len_r` 锁存长度 |
| (TB) | 批量用例"内容整体错一帧"，一度怀疑 RTL | **TB 记账 bug**：T6 送帧后未推进 TB 的 `fid`，槽号与 `flen_of[]` 失配 —— RTL 自始正确 | T6 后 `fid=1`；并把"先单帧全信号追迹、再看批量判据"写进方法 |

> **方法沉淀（可复用到 W3–W6）**：**单帧 + 全内部信号追迹（`dbg_tb.sv`）先跑**，
> 再上批量判据。本轮 R1 用追迹 10 分钟定位（读指针在 300 MHz 下卡住），
> 而"错一帧"表象最终证明是 TB 记账——**先证伪测试台，再改 RTL**。
