# prj10 W5 · 时序收敛第三轮：根因验证与最终收敛（2026-10-08 白天）

> **一句话**：先验证再动手——对照实验链证明「锥」是主因但不是全部；据此实施的三刀修复把 WNS 从 −1.121 一路推到 **+0.001**，四仿真全绿，位流已达门限、可上板。

---

## 一、任务与验证方案

用户指令：**先验证此轮根因是否判断正确，然后继续推进 W5**。

第二轮的根因主张 = 「读命令解码锥（FWFT 组合读出 → 范围比较 → 槽选择 → 三张 256:1 查表）超预算」。该主张有一个未闭环环节：W4（+0.008）与 W5（−1.121）之间**还插入了 cmd_channel 整个模块**，两者不是受控对照。验证方案按可证伪性设计：

| 主张组件 | 验证方式 |
|---|---|
| 最差路径 = 解码锥 | Vivado 逐级路径追踪（网表事实） |
| cut-1 切掉前缀 | run C 最差路径换源 |
| **缺口由锥被接活引起**（关键未闭环项） | **对照实验：让锥死掉 → 看 WNS 是否回到 ~+0.008** |

---

## 二、两次失败的对照实验（方法论坑 #28）

### 2.1 v1：cfg_mode 单常量化 → −0.473（无效对照）

把顶层 `u_mem.cfg_mode` 接回 `1'b0`（`cfg_rd_slot` 留活）。预期锥被折叠，实测 **WNS = −0.473 ≈ run C 的 −0.494**，且最差路径仍见 `pre_slot → r_beats`（预取槽号仍在喂查表 = 锥没死）。

**为什么没折叠**：`u_rd_cmd` 是 4 深 × 9 位的命令 FIFO，被综合成 **LUTRAM 宏（RAMD32）**；**宏对常量传播不透明**——写入恒 0 不代表读出可当常量。`cmd_rnd`（bit 8）仍是时序分析眼里的活信号。

### 2.2 v2：cfg 双常量化 → −0.297（仍无效，但分离出一个 0.2ns 因子）

把 `cfg_mode=1'b0, cfg_rd_slot=8'h00` **整体**常量（完全复刻 W4 接线）。实测 **WNS = −0.297**，且最差路径里 `p_in_rng0`（fo=79）**仍是活信号**——锥依然没死（同一个 LUTRAM 原因）。

意外收获：v2 比 v1 好 0.176ns，差异只来自 `cfg_rd_slot` 常量化 → **顶层到桥的 cfg 布线负载本身有 ~0.2ns 级影响**（此前未被注意的因子）。

### 2.3 教训定案（入坑账本 #28）

> **「把配置输入接常量」不能用来做「让 RAM 读出路径死掉」的对照实验**——LUTRAM/BRAM 宏对常量传播不透明。要验证某条读路径是否是根因，必须做**结构性移除**（把该路径从 RTL 里删掉），而不是接常量。

---

## 三、结构性移除实验：根因定案

v3：临时把读锥改成纯 SEQ 形式（`p_eff = rd_seq_slot`、`p_in_rng = 1'b1`、范围比较全删），cmd_channel 与其余一切不动。

### 3.1 对照实验链（完整数据）

| 配置 | WNS | 增量解读 |
|---|---|---|
| W4 基线（无 cmd_channel、无修复、含加法器） | **+0.008** | 参照系 |
| run B：cmd_channel + 完整锥 | −1.121 | 锥 + 集成负载 + 加法器 |
| run C：+ cut-1（预取寄存/判决拍/预算表） | −0.494 | cut-1 收回 0.63 |
| v1：cfg_mode 常量（**无效对照**） | −0.473 | ≈run C，反证可重复性 |
| v2：cfg 全常量（**无效对照**） | −0.297 | +0.20 来自 cfg 布线负载消失 |
| **v3：锥结构性移除（纯 SEQ）** | **−0.074** | **+0.42 = 锥的贡献定案** |

### 3.2 结论

1. **锥假设确认成立（主因）**：锥完整（−0.494）与锥移除（−0.074）差 **0.42ns**，占缺口 4/5；
2. **存在次因**：v3 距 W4 基线还差 0.082ns = **cmd_channel 集成负载**（新增逻辑的面积/布线挤占）；
3. **修复方向确定**：把 RND 锥的成本压到「SEQ 形式」以下不现实（结构下限 −0.074），必须**同时**把 SEQ 形式本身的残余瓶颈（full_bit 树挂两个 FSM 的 CE）也切掉。

## 四、最终修法（三刀 + 一镜像，全部在 axi4_master_bridge.v，两桥共享）

### 4.1 修复 1：范围数学提到预取拍（−0.494 → −0.121）

~~~verilog
// R_IDLE 预取拍: 命令弹出的同拍就把范围数学算完并寄存
wire [7:0] c_clamp  = (stat_wm == 0) ? 0 : stat_wm[7:0] - 1;
wire       c_in_rng = (stat_wm >= 256) || (cmd_slot < stat_wm[7:0]);
wire [7:0] c_eff    = cmd_rnd ? (c_in_rng ? cmd_slot : c_clamp) : rd_seq_slot;
if (rc_rd_en) begin pre_eff <= c_eff; pre_in_rng <= c_in_rng; rstate <= R_PRE; end
// R_PRE 判决拍: 三张表全部以寄存器 pre_eff 为索引（不再有比较+选择前缀）
~~~

**语义**：与 cut-1 等价（判决仍晚一拍），只是数学挪到更空的预取拍。实测 **−0.494 → −0.121**。

### 4.2 修复 2：残余瓶颈 = full_bit 树本身（−0.121 复现两次）

修复 1 后最差路径全部变成 `full_bit_reg[X] → 两个 FSM 的 CE`（`w_no_room = full_bit[w_slot_next]`、`seq_ok = … full_bit[rd_seq_slot]`、SEQ 指针扫描）——256:1 树挂在高扇出 CE 上，是 **SEQ 形式的固有成本**（W4 时代就有，靠低拥塞险过）。

### 4.3 修复 3：full_bit_q 控制镜像 + (* keep *)（−0.121 → +0.001 ✅）

~~~verilog
(* keep = "true" *) reg full_bit_q [0:255];   // 控制查找用 1 拍晚镜像
// 写提交/退休时同步置位/清零 full_bit 与 full_bit_q
wire w_no_room = full_bit_q[w_slot_next];     // 写侧控制查找
wire seq_ok    = cmd_rnd | full_bit_q[rd_seq_slot] | ...;  // 读侧门控
// SEQ 指针扫描同用 full_bit_q
// ⚠️ p_target_ok 保留组合读 full_bit[pre_eff] —— 桥内写提交与读判决同拍时
//    仍能立即看到 FULL（功能正确性所在），不能镜像
~~~

**关键实测教训（坑 #28 下半条）**：不加 `(* keep *)` 时**综合器把镜像合并回原树**（`w_slotfull_i_87` 直接读 full_bit），两轮构建同为 −0.121——**时序收益精确归零**。加 keep 后 **WNS = +0.001**。

**语义影响（四仿真证实零变化）**：镜像只用于「能不能写 / 能不能放行读 / 指针扫不扫」这类控制查找，晚 1 拍的后果是「退休→重写」间多 1 拍气泡（无害）；判据计数（wm/wr/rd/stall/ill_rd/noframe）**逐字不变**，服务周期 wr=933/rd=921 与基线相同（1 拍隐藏在 RAM 流水里）。
