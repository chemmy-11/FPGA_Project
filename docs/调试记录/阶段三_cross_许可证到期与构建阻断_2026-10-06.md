## 五、附带事故登记：内存校准位流被误删（我的操作失误）

- **经过**：为修复复位极性缺陷，我启动了一次位流重建（`reset_run synth_1` + `launch_runs impl_1`）。该运行在许可检查处失败，但 **Vivado 已按"重跑"流程清空了 `impl_1` 运行目录** ——
  里面原有的 `mig_verify_top.bit` / `.ltx` **以及我事先放在同一目录的备份**都被一并删除。
- **教训**：**备份不能放在 Vivado 的 run 目录里**（会被清空）——应放到工程外的独立目录。
- **影响**：内存校准位流当前**不存在**，且因 §三 的许可阻断**暂时无法重建**。
- **已完成的补偿**：源码侧的**复位极性缺陷已修好**（`mig_verify_top.v`：`.sys_rst(~sys_rst_btn)`，并写了注释说明根因）；
  许可一恢复即可直接重出位流（`build_mig.tcl` 幂等，命令见 §六），**新位流是修好极性的版本**。
- **对照意义（减轻损失的事实）**：被删的那版位流**带极性缺陷**，本来就无法完成校准——即"损失的是一版注定失败的位流"。
