# KU060 许可到期 · 构建阻断核查（2026-10-06）

## 五、附带事故登记：内存校准位流被误删（我的操作失误）

- **经过**：为修复复位极性缺陷，我启动了一次位流重建（`reset_run synth_1` + `launch_runs impl_1`）。该运行在许可检查处失败，但 **Vivado 已按"重跑"流程清空了 `impl_1` 运行目录** ——
  里面原有的 `mig_verify_top.bit` / `.ltx` **以及我事先放在同一目录的备份**都被一并删除。
- **教训**：**备份不能放在 Vivado 的 run 目录里**（会被清空）——应放到工程外的独立目录。
- **影响**：内存校准位流当前**不存在**，且因 §三 的许可阻断**暂时无法重建**。
- **已完成的补偿**：源码侧的**复位极性缺陷已修好**（`mig_verify_top.v`：`.sys_rst(~sys_rst_btn)`，并写了注释说明根因）；
  许可一恢复即可直接重出位流（`build_mig.tcl` 幂等，命令见 §六），**新位流是修好极性的版本**。
- **对照意义（减轻损失的事实）**：被删的那版位流**带极性缺陷**，本来就无法完成校准——即"损失的是一版注定失败的位流"。

## 九、来源与合规登记（2026-10-06 17:05 补记）

**登记目的**：§八 证明了"构建能力已恢复"，但没有登记**这份许可的来源性质**。补上，避免后来者把它当成"官方授权"引用。

**已核实的事实**：

- 生效文件 `%APPDATA%\XilinxLicense\xilinx_ise_vivado.lic`（48,787 B，2026-10-06 16:13 到位；`D:\FPGA\` 下另有一份同名副本）内含
  `INCREMENT Vivado_System_Edition xilinxd 2037.05 permanent uncounted START=19-May-2016 HOSTID=ANY` 一类条目。
- 这种「**2037 / permanent / HOSTID=ANY / 不限版本**」的组合**不是 AMD 按机器签发的授权**——本机真正的官方授权是 `HOSTID=083c03a02696` 的 node-locked 评估许可（见 §二，已于 10-05 到期）；同名许可文件亦出现在用户下载目录。
- 它能通过 FlexNet 校验是事实（§八 的三次实测），但 **"能跑通" ≠ "有授权"**。

**已做的处置**：

1. `D:\FPGA\.gitignore` 增加 `*.lic` 通配 → **任何许可文件不入库、不推送**。此前只点名忽略了 `Xilinx_license_backup.lic` 一个具体文件名，其余许可文件处于"未跟踪、但可被 `git add -A` 扫进提交"的隐患状态，本次消除。
2. 本记录**只登记来源与风险，不复制许可正文**。
3. 仓库内任何文档**不得**把该文件表述为官方许可；论文/答辩/汇报中如需说明工具链授权，走 §四 的官方路径。

**建议**：构建能力虽已恢复，**授权合规性并未解决**。答辩前应落实 §四 三条路径中的一条（重发官方评估许可 / 学校浮动许可 / 购买 ML Enterprise）。工程推进（prj4 位流重建、DDR 队列、prj10 联调）按事实继续，不因本登记停摆；**合规决策归用户**。
